# askhava-server: the composition root and both binaries

## Purpose

Builds the two processes from one crate: `server` (the `web` process, Axum) and `worker` (the task runner). It is the only crate that may depend on every module; it wires their routes and task handlers together and owns process concerns (TLS provider, port, signals) (`docs/architecture.md` section 2, D-481).

## What it owns

- `src/lib.rs`: `install_crypto_provider()`, `start_up()` (first checks and installs `core`'s embedded brand, refusing to start on a bad field, D-1932; then settings from `std::env::vars()`, then the JSON log and Sentry; D-689), `build_router(pool, test_control, webhooks)` (merges `core`'s `TestControl::router()`, empty in the release build, SEC-035, D-739; `portals`' quote page, pick flow and private feedback page (`feedback_routes`, T230); Twilio's webhook routes when `webhooks` is `Some`; the request-log middleware, under the request-ID and `TraceLayer` layers that log the route template only), `shutdown_signal()` (SIGINT or SIGTERM), `release_minter()` (`payments`' `Minter` over `privacy`'s release mint, taken once per process behind a `OnceLock`, D-1477), `session_minter()` (T253: `privacy`'s session mint taken once per process behind a `OnceLock`, shared by the composition and every server test file, D-1739), `register_handlers(stream, texts, confirm)` (takes the release minter first; `confirm` is `picks::api::ConfirmSettings`, which the worker reads once from `ASKHAVA_PICK_CONFIRM_WINDOW_MINUTES`, D-1503; the `core::api::Registry` of every task handler; `texts` registers `intake`'s `jobs.homeowner_text` sender), `pick_code_keys(settings, pairs)` (T246, D-1516: the page pick's `PickCodeKeys<TwilioVerify>` from the vault keys, `ASKHAVA_ID_SECRET`, `TwilioConfig` and the compiled-in `docs/legal/homeowner-terms.md`; `None` in dev and CI without vault keys, an error in test and live; `build_router` takes `(webhooks, pick_keys)`), `job_text_keys(settings, id_secret, pairs)` (the sender's keys from `ASKHAVA_ID_SECRET`, `VAULT_KEY` and `VAULT_INDEX_KEY`; `None` in dev and CI without vault keys, an error in test and live, and an error naming the missing key when only one is set, D-1302, D-1306).
- `src/main.rs`: the `server` binary; binds `0.0.0.0:$PORT` and serves with graceful shutdown. `server migrate` instead applies pending migrations over `ASKHAVA_MIGRATION_DATABASE_URL` (via `askhava_core::api::migrate`) and exits (D-700, SEC-052). Missing or bad `PORT` exits 1 without echoing the value (D-588).
- `src/release_sink.rs` (T254, D-2013 to D-2016): `PickReleaser` (`new`, `settle_and_release`), `payments`' `ReleaseSink`: `picks::api::settle` and commit, then for a pick now `paid` or `free` the homeowner contact from `intake::api::job_homeowner` (none: one High `NO_CONTACT_ALERT`, `picks.release_no_contact`, and `MovedOn`, so nothing retries it, D-2017), `release_minter().mint` and `picks::api::release` with the vault and masked pool, `email_chosen` false (D-1740); `stripe_webhook(settings, pool, pairs)` (`StripeHooks`; `WEBHOOK_SECRET`, `STRIPE_MODE`, `STRIPE_BASE_URL`): unset secret is `None` in dev and CI and an error in test and live; with it the Stripe key and account, both vault keys and the Twilio settings are required. `build_router` takes `(webhooks, pick_keys, stripe)` and merges `stripe_webhook_routes`; `main` serves with `into_make_service_with_connect_info::<SocketAddr>()` (SEC-040).
- `src/bin/worker.rs`: the `worker` binary; it runs `core`'s `Worker::run` on `TestControl::clock()` (the system clock in release, D-740; the off-database stream uses the same clock), the claim loop over `core.task` (4 at once, idle poll 200 ms to 5 s, the reaper when idle), with the shutdown signal and a 20-second drain, after which the loop calls `release_leases` (JOB-006, D-708, D-710). With the Twilio settings (required in test and live) it registers `picks.line_retry` (`picks::api::retry_line` over the masked pool, D-1688, T254).
- `src/offdb_stream.rs` (T017, D-734, D-735): `OffDbStream` (storage, `ID_SECRET`, clock, stand-in purge directory; `from_settings` reads `ASKHAVA_STORAGE_BASE_URL` and `ASKHAVA_ID_SECRET`), `register` (handlers for `ops.offdb_stream` and `ops.offdb_verify`), `verify_audit_chain`, `purge_request_log`, `schedule_verify`, `audit_name`, `RequestLog` (the bounded channel and background writer of request lines, D-737) and the `log_request` middleware that `build_router` puts on every route.
- `src/inbound_text.rs` (T241, D-1307 to D-1311): `Webhooks` (pool, clock, public base URL, Twilio auth token, `ID_SECRET`, vault, LIST names, intake settings), `routes` (`POST` `INBOUND_PATH` `/webhooks/twilio/sms` and `STATUS_PATH` `/webhooks/twilio/status`). `src/lib.rs` `webhooks(settings, pool, pairs)` builds `Webhooks` when `ASKHAVA_PUBLIC_BASE_URL` is set (then the Twilio auth token, a strong `ASKHAVA_ID_SECRET` and both vault keys are required, a half-set pair naming the missing key, D-1311); unset: `None` in dev and CI, an error in test and live. A module error that stops a text is logged at warn with the step and variant name only; the HELP settings are built only for a HELP text. T256 (D-2039): a first text whose new contact loses the unique phone index to a concurrent one continues with the winner's contact (found again in the delivery transaction), else 500 with the whole delivery rolled back (D-1751); a business phone's opt-out calls `businesses::api::phone_stopped`, and its other texts queue `business_auto_reply` when `auto_reply_due` holds. T257 (D-1752, D-2087, D-2088): the sender is resolved before the read, and a homeowner's text is scrubbed by `privacy::api::read_inbound_for` with her vault name and the names she stated in earlier texts; a vault database or audit error is 500 (the delivery rolls back); any other vault error falls back to the empty-context `read_inbound`, so the opt-out and HELP steps still run, and then stops the text with 200 before `intake`.
- `src/inbound_voice.rs` (T262, D-2091 to D-2095): `VoiceHooks` (the shared `Webhooks`, the masked pool, the PIN wait), `routes` (`POST` `VOICE_PATH` `/webhooks/twilio/voice`), the pool numbers' voice webhook: signature-checked as `inbound_text` is, the signed query names the turn (`try=N`, `confirm=N`), each turn runs `calls::api::voice_turn` or `voice_confirm` and answers `calls::api` TwiML (prompt, read-back on A attestation, dial, hang-up); a database error is 500, any other `calls` error a hang-up with one warn line. `src/lib.rs` `voice_hooks(settings, webhooks, pairs)` builds it when `webhooks` is built; `build_router` takes `Hooks` = `(webhooks, voice, pick_keys, stripe)`.
- `src/bin/rules_bridge.rs` (T074, D-1592): the twin's door to the app's pure rules, one JSON line each way (`{id, call, args}` in, `{"ok": {id, result}}` or `{"error": {id, code}}` out): `fee` (`payments` `period_fee_for`), `quiet_hours` (`messaging` `decide`), `transition` (`jobs` `check_move`), `card` (`quotes` `card_for` over the shipped license map and catalog) and `job_types`. `rules_bridge.schema.json` is its hand-written schema; `twin/rules_bridge.py` drives it and `twin.yml` builds it (`SQLX_OFFLINE=true`).
- No tables.

## Rules it enforces

- SEC-029: workspace lints on (`[lints] workspace = true`), `unsafe_code` forbidden, built by `cargo build -p askhava-server --locked` in `scripts/smoke.sh` and `Ci` (D-488).

## Never break

- PICK-022, PRIV-005, D-1739: only `release_sink` mints a release proof, only for a `Releasable` `payments` cleared, and only after `picks::api::settle` left the pick `paid` or `free`; a pick that left awaiting confirm releases nothing; every failure is the route's 500 so Stripe resends, and the release row keeps it once (`tests/release_recovery.rs`). The web process must be served with connect info, or the Stripe route cannot read its peer (SEC-040).

- `rules_bridge` answers only through each crate's public `api`, reads nothing but stdin and the compiled-in files, takes and gives no personal data, checks every argument exactly, and keeps to `rules_bridge.schema.json`; a new call adds its `$defs.calls` entry and a case on both contract sides (D-1592): `tests/rules_bridge_contract.rs`, `tests/contract/test_rules_bridge.py`.
- SEC-016: the voice route answers nothing before `verify_webhook` passed, puts no line ID, phone or PIN in a URL or log, and answers only the calling leg (`tests/inbound_voice.rs`).
- SEC-016, SEC-039: no module sees a Twilio delivery before `verify_webhook` passed over `ASKHAVA_PUBLIC_BASE_URL` plus path and query; a refusal is 403 with one log line; a checked delivery is one transaction, 200 unless the database failed (500); the inbound order is `receive_inbound`, the sender lookup (blind index only), `read_inbound_for` for a homeowner (her vault and stated names, in the delivery's transaction, D-1752; on a vault error other than database or audit, `read_inbound` with an empty context for the opt-out and HELP steps only, never `receive_reply`, D-2088) or `read_inbound` with an empty context for a business phone, `on_inbound_text`, `reply_to_help`, `receive_reply` (non-business only); nothing logs a phone, body or URL: `tests/integration/tests/inbound_text_route.rs`. A text never commits its inbox row without reaching its handler because of a contact race: `PhoneTaken` is looked up again, else `Halt::Database` (D-1751, `tests/integration/tests/inbound_first_contact.rs`). `inbound_text.rs` names no `crate::` item, since that test compiles it with `#[path]`.
- OPS-011, PRIV-029: every request hands one request-log line holding request ID, route template, status and time, never the path, to `RequestLog` without waiting (overflow dropped and counted); audit row `n` is stored as `audit/<n>.json` with its line and the ID and line hash of the row before it, and waits (retries) up to 2 minutes for a missing lower ID; the nightly `ops.offdb_verify` first queues tomorrow's run, then purges stand-in request days older than 30 and last raises a High `ops.audit_chain_broken` alert on any mismatch; the worker also queues today's and tomorrow's at start (`tests/integration/tests/offdb_stream.rs`).

- `install_crypto_provider()` runs first in both binaries, so sqlx and reqwest share the aws-lc-rs provider (D-481, D-488).
- Both binaries exit 0 on SIGTERM; the web server drains in-flight requests first (D-491).
- Errors at start never echo a setting's value; both binaries call `start_up()` right after the TLS provider, so a bad setting exits 1 before anything is served or claimed (SEC-002).
- Routes are merged before the layers in `build_router()`, so every route gets the request ID and the route-template span (PRIV-016, PRIV-028).
- Any future `src/status.rs` must start with `#![deny(clippy::wildcard_enum_match_arm, clippy::match_wildcard_for_single_variants)]` (SEC-031, D-488).
- The worker gives back its leases after the drain on every signal, so a deploy never strands a task for a lease length (rust brain R14).
- `/healthz` belongs to T106 (`src/healthz.rs`); do not add it here.

## How to change

- Add a module's routes: merge its `routes()` in `build_router()` in `src/lib.rs`; add the path dependency to `Cargo.toml` with `workspace = true`.
- Register a task handler: one `registry.register(kind, handler)` line in `register_handlers()` (`src/lib.rs`); the worker runs whatever it returns.
- Run `cargo build -p askhava-server --locked`, `cargo clippy --workspace --all-targets -- -D warnings` and `bash scripts/smoke.sh`.
