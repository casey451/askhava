# askhava-server: the composition root and both binaries

## Purpose

Builds the two processes from one crate: `server` (the `web` process, Axum) and `worker` (the task runner). It is the only crate that may depend on every module; it wires their routes and task handlers together and owns process concerns (TLS provider, port, signals) (`docs/architecture.md` section 2, D-481).

## What it owns

## Never break

- PICK-022, PRIV-005, D-1739: only `release_sink` mints a release proof, only for a `Releasable` `payments` cleared, and only after `picks::api::settle` left the pick `paid` or `free`; a pick that left awaiting confirm releases nothing; every failure is the route's 500 so Stripe resends, and the release row keeps it once (`tests/release_recovery.rs`). The web process must be served with connect info, or the Stripe route cannot read its peer (SEC-040).

- `rules_bridge` answers only through each crate's public `api`, reads nothing but stdin and the compiled-in files, takes and gives no personal data, checks every argument exactly, and keeps to `rules_bridge.schema.json`; a new call adds its `$defs.calls` entry and a case on both contract sides (D-1592): `tests/rules_bridge_contract.rs`, `tests/contract/test_rules_bridge.py`.
- SEC-016: the voice route answers nothing before `verify_webhook` passed, puts no line ID, phone or PIN in a URL or log, and answers only the calling leg (`tests/inbound_voice.rs`).
- SEC-016, SEC-039: no module sees a Twilio delivery before `verify_webhook` passed over `ASKHAVA_PUBLIC_BASE_URL` plus path and query; a refusal is 403 with one log line; a checked delivery is one transaction, 200 unless the database failed (500); the inbound order is `receive_inbound`, the sender lookup (blind index only), `read_inbound_for` for a homeowner (her vault and stated names, in the delivery's transaction, D-1752; on a vault error other than database or audit, `read_inbound` with an empty context for the opt-out and HELP steps only, never `receive_reply`, D-2088) or `read_inbound` with an empty context for a business phone, `on_inbound_text`, `reply_to_help`, `receive_reply` (non-business only); nothing logs a phone, body or URL: `tests/integration/tests/inbound_text_route.rs`. SEC-014, D-2206: the new-request count runs only for a homeowner with no open request, never for a reply, HELP, STOP, a START that lifted her listing or a 911-list text (D-3087), inside the delivery's transaction and after every other read, with no network call between it and the commit (the shared `intake.requests_all` row stays locked until then): `tests/integration/tests/inbound_text_guards.rs`. A text never commits its inbox row without reaching its handler because of a contact race: `PhoneTaken` is looked up again, else `Halt::Database` (D-1751, `tests/integration/tests/inbound_first_contact.rs`). `inbound_text.rs` names no `crate::` item, since that test compiles it with `#[path]`.
- OPS-011, PRIV-029: every request hands one request-log line holding request ID, route template, status and time, never the path, to `RequestLog` without waiting (overflow dropped and counted); audit row `n` is stored as `audit/<n>.json` with its line and the ID and line hash of the row before it, and waits (retries) up to 2 minutes for a missing lower ID; the nightly `ops.offdb_verify` first queues tomorrow's run, then purges stand-in request days older than 30 and last raises a High `ops.audit_chain_broken` alert on any mismatch; the worker also queues today's and tomorrow's at start (`tests/integration/tests/offdb_stream.rs`).

- `install_crypto_provider()` runs first in both binaries, so sqlx and reqwest share the aws-lc-rs provider (D-481, D-488).
- Both binaries exit 0 on SIGTERM; the web server drains in-flight requests first (D-491).
- Errors at start never echo a setting's value; both binaries call `start_up()` right after the TLS provider, so a bad setting exits 1 before anything is served or claimed (SEC-002).
- Routes are merged before the layers in `build_router()`, so every route gets the request ID and the route-template span (PRIV-016, PRIV-028).
- D-1870, D-2208, SEC-012: the layers, innermost first, are `catch_panic`, `limit_request`, the request log, `TraceLayer`, the two request-ID layers and `security_headers` last; a timed-out request is 503 with `Retry-After: 5` and a panic 500, each with `no-store`, the request ID, the security headers and no body text. A dropped handler commits nothing half-done (every write is in a transaction or keyed), and a Confirm press cut mid-Stripe-call stays `sent` until Stripe says it failed (FEE-037): `tests/request_timeout.rs`, `tests/server_hardening.rs`.
- Any future `src/status.rs` must start with `#![deny(clippy::wildcard_enum_match_arm, clippy::match_wildcard_for_single_variants)]` (SEC-031, D-488).
- OPS-004, JOB-006, D-2285: a task kind the app queues is registered in `worker_registry` or listed with its owner in `tests/task_kinds_deferred.json`, and a `NO_HANDLER` dead letter raises one open High alert per kind in test and live (`tests/integration/tests/task_registry.rs`).
- The worker gives back its leases after the drain on every signal, so a deploy never strands a task for a lease length (rust brain R14).
- `/healthz` belongs to T106 (`src/healthz.rs`); do not add it here.
- TD-SEC-41, D-1868, D-2269: `tests/route_wiring.rs` checks only the rows listed in `docs/architecture.md` section 13: a `yes` row must be served by `build_router` and a row naming a task must not be, so a listed route never merged fails naming its row. An axum router cannot list its routes, so a route served with no row is not caught: the task that merges a new route adds its row (`yes`) in the same change.

## How to change

- Add a module's routes: merge its `routes()` in `build_router()` in `src/lib.rs`; add the path dependency to `Cargo.toml` with `workspace = true`; in the same change mark the route's rows `yes` in `docs/architecture.md` section 13 (`| Method | Path | Module | Wired |`, one row per method and path, `{name}` for a parameter), or add them as `yes` if no row names them (D-2269, D-2270). The route's layers (cross-site refusal, `no_store`, `noindex`, the request log, any session check) run before axum's 405, so a route layer must let a same-origin method the route does not take through to the 405: `tests/route_wiring.rs` reads any other answer than the fallback 404 or a 405 without the row's method as served, and a `yes` row only as a 405 naming its method. A new optional part of `build_router` is configured with fake values in `tests/route_wiring.rs`'s `router()` too.
- Register a task handler: one `registry.register(kind, handler)` line in `register_handlers()` (`src/lib.rs`), or in `worker_registry` when it needs a worker-only client; the worker runs whatever `worker_registry` returns. A new queued kind needs a handler, or `tests/integration/tests/task_registry.rs` fails (TD-OPS-36); name a kind's constant `*_KIND` so the scan sees it. When an owner registers a kind listed in `tests/task_kinds_deferred.json`, the test prints it as stale; the plan change after the merge removes the entry (only a harness task adds one).
- Run `cargo build -p askhava-server --locked`, `cargo clippy --workspace --all-targets -- -D warnings` and `bash scripts/smoke.sh`.
