## Goal

Four changes, nothing else. (1) `runner/verify.py` `check_paths`: a changed path `app/<crate>/NOTES.md` counts as shared exactly when `app/<crate>/CLAUDE.md` is in `shared`, so every task may add its lines there without a new `kit/tasks.json` shared path or a change to `scripts/validate_tasks.py`'s allowlist; name `NOTES.md` in a module-level constant or pattern with a comment citing D-3474 (the task template tells workers that NOTES.md is shared once `runner/verify.py` names it). Any other path keeps today's rules, and a NOTES.md under a protected path or `NEVER_TOUCH` is still refused. (2) `runner/__main__.py` `crate_doc_full`: a crate is also full when its `CLAUDE.md` on origin's `main` (`crate_doc_text`, unchanged), in UTF-8 bytes, plus `(held + 1) * check_code_docs.CRATE_DOC_TASK_BYTES` (400, one `## Never break` bullet for each task in flight and for the next one) is over `check_code_docs.MAX_CRATE_DOC_BYTES`. The guides are about 15 to 45 lines, so the 120-line count (D-3303) alone can no longer reach its limit, while two tasks that each add a bullet near the byte budget would merge into a file the check refuses, which costs a resync. Keep the line rule, keep a missing or unreadable file full, read both constants with `getattr` and fall back to the line rule alone when the runner's copy of the check lacks them; update the docstring. (3) `scripts/check_code_docs.py` still accepts the six pre-D-3474 headings (`LEGACY_HEADINGS`) only because the protected fixture `HEADS` in `tests/test_runner_crate_merge.py` uses them: change that fixture to the three headings `check_code_docs.HEADINGS` names (reading the constant, so it cannot drift again), then delete `LEGACY_HEADINGS` and its branch in `check_crate_doc`; every other assertion in that file stays. (4) `tests/docs/test_brand_literals.py` `SKIP_NAMES` also skips `NOTES.md` (a crate's notes, like its `CLAUDE.md`, are never shown to a customer; D-3474), with a planted case showing a brand word in `app/<crate>/NOTES.md` passes while the same word in an `app/` source file still fails; until then the split left the ten brand-naming entries after the `## Detail` paragraph of their crate's `CLAUDE.md`, which this task moves at its end (step 5). (5) Last, once (1) to (4) pass: run `python3 scripts/split_crate_doc.py --sweep`, which moves every entry line under a crate `CLAUDE.md`'s `## Detail` paragraph (the ten brand-naming entries and any interim lines tasks added before this task) to the end of that crate's `NOTES.md`, and commit the moved lines with no other change to those files; `python3 scripts/check_code_docs.py` and the brand guard must pass after it. The crate docs and NOTES files this touches are shared paths, as are `docs/architecture.md`, `docs/decisions.md` and `kit/plan.lock`, so they sit outside the owned-file budget (scripts/validate_tasks.py requires `files` to equal the owned count); the line budget covers them. Tests (keep every other existing test unchanged): in `tests/test_runner_logic.py`, a task touching `app/<crate>/NOTES.md` passes when that crate's `CLAUDE.md` is shared and fails as not owned when it is not, and a NOTES.md under a protected path is still refused for a build task; in `tests/test_runner_crate_cap.py`, a guide well under the byte budget is not full at held 0, one whose bytes plus one task's room pass the budget is full at held 0, held tasks count 400 bytes each, and a check module without the two constants falls back to the line rule.
