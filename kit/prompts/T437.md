Four changes, nothing else. (1) `runner/verify.py` `check_paths`: a changed path `app/<crate>/NOTES.md` counts as shared exactly when `app/<crate>/CLAUDE.md` is in `shared`, so every task may add its lines there without a new `kit/tasks.json` shared path or a change to `scripts/validate_tasks.py`'s allowlist; name `NOTES.md` in a module-level constant or pattern with a comment citing D-3474 (the task template tells workers that NOTES.md is shared once `runner/verify.py` names it). The guides are about 15 to 45 lines, so the 120-line count (D-3303) alone can no longer reach its limit, while two tasks that each add a bullet near the byte budget would merge into a file the check refuses, which costs a resync. Keep the line rule, keep a missing or unreadable file full, read both constants with `getattr` and fall back to the line rule alone when the runner's copy of the check lacks them; update the docstring. (3) `scripts/check_code_docs.py` still accepts the six pre-D-3474 headings (`LEGACY_HEADINGS`) only because the protected fixture `HEADS` in `tests/test_runner_crate_merge.py` uses them: change that fixture to the three headings `check_code_docs.HEADINGS` names (reading the constant, so it cannot drift again), then delete `LEGACY_HEADINGS` and its branch in `check_crate_doc`; every other assertion in that file stays. (4) `tests/docs/test_brand_literals.py` `SKIP_NAMES` also skips `NOTES.md` (a crate's notes, like its `CLAUDE.md`, are never shown to a customer; D-3474), with a planted case showing a brand word in `app/<crate>/NOTES.md` passes while the same word in an `app/` source file still fails; until then the split left the ten brand-naming entries after the `## Detail` paragraph of their crate's `CLAUDE.md`, which this task moves at its end (step 5). Tests (keep every other existing test unchanged): in `tests/test_runner_logic.py`, a task touching `app/<crate>/NOTES.md` passes when that crate's `CLAUDE.md` is shared and fails as not owned when it is not, and a NOTES.md under a protected path is still refused for a build task; in `tests/test_runner_crate_cap.py`, a guide well under the byte budget is not full at held 0, one whose bytes plus one task's room pass the budget is full at held 0, held tasks count 400 bytes each, and a check module without the two constants falls back to the line rule. ## Output discipline

Every turn re-reads all earlier tool output, so a large result is paid for again on each later turn (D-3305). Never cut a failure line to save tokens.

1. Never `cat` or `Read` all of a file over 200 lines (`wc -l`): `grep -n` (context `-C` 3 at most), then `sed -n 'A,Bp'` or Read with offset/limit, at most 120 lines per read, or up to 250 when one read then covers what would take two. Do not re-read a file, or a region of one, you already read unless it changed since: use your earlier output.
2. Build, test and lint output goes to a log, and you print only what decides: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`. Grep each tool's own failure markers: cargo and clippy `^error|FAILED|panicked`, pytest `FAILED|ERROR`, tsc `error TS`, npm `ERR!`, playwright `✘|failed`. When a failure needs more, read the log by line range; if `head` cut failure lines, read the rest.
3. Prehand-in: `bash scripts/prehandin.sh >/tmp/p.log 2>&1; echo exit=$?; tail -n 40 /tmp/p.log` (the smoke test as in Start step 2).
4. Batch every read, grep and `wc -l` you can foresee into one turn (parallel tool calls, or one Bash call joined with `;`): each turn re-reads the whole context (D-3530).
5. `git diff --stat` before any full diff, then diff only the files you need.
6. Keep each output under 4,000 characters (D-3444); when a failure needs more, read the log in further line ranges. No running commentary: one concise report at the end (End routine).
