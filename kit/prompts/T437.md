## Goal

Merge hotspots (D-3474; D-3303, D-3444, D-473): 22 of the last 25 resyncs involved a crate `CLAUDE.md` (23 file conflicts) where two tasks lengthened the same giant line (the 120-line limit pushed workers to pack entries into lines of over 10,000 characters), and the rest were per-task paragraphs and definitions appended to `src/api.rs` files and registrations appended to the server `lib.rs`. `docs/code-docs.md` sections 2 and 9 now state the rules; this task makes a machine enforce them, points the runner's crate-full signal at the new budget and gives splitters a tool. (1) `scripts/check_code_docs.py` `check_crate_doc` (keep every existing check: the six headings in order, the architecture name, module comments, requirement references, the trace, the root `CLAUDE.md` limit): drop `MAX_CRATE_DOC_LINES` and the 120-line limit; add `MAX_CRATE_DOC_LINE_CHARS = 400`, `MAX_CRATE_DOC_BYTES = 84_000` (UTF-8 bytes of the file) and `CRATE_DOC_TASK_BYTES = 2_000`, each with a comment naming D-3474. An old-format line is a non-blank line over 400 characters, or a non-blank line under one of the five list headings that does not start with `- `. A new constant `OLD_FORMAT_MARKER` is one exact line of plain words, at most 400 characters (built from the 400 constant), saying: this file is in the old format; the next task that starts in this crate, not a fix round and not a resync, splits it (only this one crate file per task: its module's file if marked, otherwise the largest marked file it writes) by running `python3 scripts/split_crate_doc.py` on it and hand-fixing the lines it reports, keeping every fact, ID and path, then deletes this line; until then the runner lets one task at a time into this crate (D-3474). One helper (for example `old_format_lines(text)`) never counts the marker line itself, and is the single definition this check, the runner and the splitter use. A file with no marker line fails on any old-format line (naming the line number and its length or the missing bullet). A file with the marker line passes its old-format lines, but fails when its crate is not in a new frozenset `OLD_FORMAT_CRATES` or when it has no old-format line left ("delete the marker line"). Every file fails over `MAX_CRATE_DOC_BYTES`. (2) The same script checks each `app/<crate>/src/api.rs` (D-3474, section 9): count its `//!` lines and its definitions (a top-level line, no indentation, that opens a `fn`, `struct`, `enum`, `union`, `trait`, `impl`, `type`, `const`, `static`, `macro_rules!` or a `mod` with a body, with or without `pub`, `pub(crate)`, `async`, `unsafe`); a new dict `API_ALLOWANCE` maps each crate to its two ceilings, and a crate missing from it gets 12 and 0. Over either ceiling fails, naming the count, the ceiling and the rule ("put the note in the crate CLAUDE.md bullet or the owning module's //! comment", "define it in its own module and re-export it"). (3) New `scripts/split_crate_doc.py PATH` (standard library only; module docstring per section 6 of the code docs standard): splits each old-format line of one crate `CLAUDE.md` (the shared helper; the marker line is left alone) at sentence ends or "; " into `- ` bullets of at most 400 characters, prefixes a non-bullet line under a list heading with `- `, verifies that the file's word sequence, ignoring the bullet marks it added, is unchanged (otherwise it writes nothing and exits 1), writes the file, and prints only a summary: lines split, bullets written, and the line numbers still over 400 for the hand fix. It never deletes the marker; the splitter does that once the check passes. (4) Runner. `runner/lanes.py` `task_crates` also counts each crate in the task's optional `crate_notes` (kit/tasks.json, checked by scripts/validate_tasks.py since D-3474), so a task whose goal updates another crate's `CLAUDE.md` holds that crate too; update the module docstring and `crate_limit` docstring that say "line limit". `runner/__main__.py` `crate_doc_full`: a crate is full when its `CLAUDE.md` on origin's `main` (`crate_doc_text`, unchanged) has any old-format line or the marker, or when its bytes plus `(held + 1) * CRATE_DOC_TASK_BYTES` exceed `MAX_CRATE_DOC_BYTES`; missing or unreadable is still full. In `runner/update_merge.py` change only the docstrings that say "120" or "line limit" (module docstring point 5 and `_docs_broken`): the merge resolver already runs `check_crate_doc`, so a resolved file is held to the new rules. The `_crate_limit` docstring in `runner/cycle.py` is T395's (D-3474). (5) Freeze the allowances last, from `origin/main` fetched just before hand-in (read with `git show origin/main:<path>`; never merge, rebase or touch `claude/kit-state` for it): `OLD_FORMAT_CRATES` is every crate whose `CLAUDE.md` there has an old-format line, and `API_ALLOWANCE` each crate's `//!` count plus 8 (at least 12) and its definition count plus 2, a margin for tasks that merge while this one is reviewed, so the merged tree still passes.
