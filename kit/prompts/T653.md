## Goal

Plan change D-4310 (Fable's decision on the licensing spot review of `main` 4fee847d, finding 1; no requirement amended). Sign-up stores the typed `btr_number` for Home inspection and Alarm systems through `record_agency_license` (`app/server/src/business_signup.rs:1317`; D-5387: it was at `:1289` to `:1293`), which inserts it as `verification = 'agency_record'` (`app/licensing/src/holder.rs:120`); `read_rows` (`:226`) adds every row to `holder.agencies`, so `rules::agency_only` gives `Eligibility::Card`, and `card_facts::agency_facts` (`app/licensing/src/card_facts.rs:136`) prints LIC-034's "showed Active on the ... website when we checked on <date>" with the sign-up day as the check day. No BTR lookup exists, so the line is false and LIC-015, LIC-013 and CARD-015 are not met. Until a BTR source exists, an unchecked number gets no card and no line; extending LIC-047's attestation to BTR is Casey's call (`docs/for-casey-review.md`), not this task's. (1) `migrations/0212_licensing_btr_typed_unchecked.sql`: `licensing.business_license.verification` also allows `typed_unchecked`, only on `home_inspector` and `alarm_business` rows: drop the column's auto-named `business_license_verification_check` (from `migrations/0048_licensing_agency_rules.sql:23`) and add a named CHECK in its place, plus one tying `typed_unchecked` to those two agencies; every existing `home_inspector` and `alarm_business` row with `agency_record` becomes `typed_unchecked` (the comment says why: only sign-up ever wrote them); the other checks stay. (2) `holder.rs`: a new `record_typed_agency_number(conn, business, (agency, number), actor)` stores a typed number as `typed_unchecked` (trimmed, at most 64 characters, `BadRecord` for pest and septage hauler, the unique index's `AlreadyRecorded`, one audit row naming the agency as the field, never the number, PRIV-028), exported through `licensing::api`; `record_agency_license` stays the writer for a number read from the agency's own source, and its doc says sign-up never calls it; `read_rows` adds an agency only for an `agency_record` row (pest stays `self_attested`). (3) `card_facts.rs`: `agency_facts` reads no `typed_unchecked` row; a `pest_management` row stays `self_attested` and keeps LIC-047's line (TD-PICK-62, T393's `quote_page_cards.rs:325`–`:341`, unchanged); `agency_facts`'s doc states the wording rule: a card says a license "showed Active ... when we checked on <date>" only from a stored check of that number against the agency's own source, <date> being that check's day, never the sign-up day; no "verified", "certified by Laftly" or "vetted" (WORD-003). (4) `business_signup.rs:1317` calls `record_typed_agency_number`. (5) `app/server/tests/business_signup_route.rs:673` (TD-BIZ-49) asserts a typed `HI-5678` puts `HomeInspector` in `holder.agencies`; D-4310 makes that wrong, so it now asserts the row is stored `typed_unchecked` and is not in `holder.agencies` (this task is `harness` for that one change; nothing else in the file changes). Tests, fake data only, on PostgreSQL: TD-LIC-32 in `tests/integration/tests/btr_typed_unchecked.rs`. Follow-up, not this task: a BTR source (stand-in, adapter and the CARD-015 daily check) that writes `agency_record` rows with the check date, in a later plan change that gives T134 the real source; because of the unique `(business_id, agency)` index it must UPDATE the `typed_unchecked` row in place to `agency_record`, and `licensing.business_license` then needs a check-date column (until then `recorded_at` is the only date, which is why sign-up must never write `agency_record`). Migration number: 0212 runs after T645's 0210 and 0211 in the serial order (V9); 0213 is T745's; T236's is 0218 (D-5336, D-5341). Update `app/licensing/NOTES.md`, `app/server/NOTES.md` and `docs/decisions.md`.

Acceptance: TD-LIC-32 passes against PostgreSQL; `app/server/tests/business_signup_route.rs` changes only in the TD-BIZ-49 assertion D-4310 names; `tests/integration/tests/holder_read.rs`, `quote_page_cards.rs`, `capability_offer.rs` and every other licensing and sign-up test pass unchanged; the `app/licensing/` 95% branch floor holds.
