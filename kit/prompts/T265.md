Add to `scripts/stage_exit.py` a fifth condition: read the register's table; a row whose area is `security`, `money` or `privacy` and whose status is not `closed` is judged at stage N only when every owner it names has a `stage` at or below N in `kit/tasks.json` (a row with a later-stage owner is printed and not failed at N, because the runner re-runs `stage_exit.evaluate()` for every earlier stage on every claim, `runner/state.py:403`, and an earlier stage must not close again behind it); a judged row fails when it names only tasks DONE or SKIPPED in the state; a row with no owner at all, or naming a task id missing from `kit/tasks.json`, fails at every stage; a `closed` row must carry evidence (a merged commit SHA or PR number and a test name) or it fails too; rows of other areas are printed, never failing. The reasons print one per line as the other conditions do. Tests in `tests/test_stage_exit.py` (new cases only; every existing case passes unchanged): an open gating row with a queued owner passes; an open row whose owners are DONE but one owner sits in a later stage passes at the earlier stage and fails at that later stage; with only DONE owners fails, with no owner fails, with an unknown task fails, a closed row without evidence fails, a non-gating unowned row passes with a printed line, and a missing register file fails.

Acceptance: TD-OPS-31 passes (`python3 -m pytest tests/test_stage_exit.py`), and `python3 scripts/stage_exit.py --stage N` for every stage already passed on the current state (1, 2, 3) still passes with the register on `main`.
