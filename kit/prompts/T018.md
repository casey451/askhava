# T018: adapters: signature checks, replay and idempotency-key tests

Task T018 (build, phase 1, stage 2). Slug: webhook-security.
Branch: `claude/task/T018-webhook-security`
Model: `claude-opus-5-5`, effort medium. Reviewer: `claude-opus-5-5` (areas: security).

## Goal

Twilio, Stripe, Resend and Lob webhooks are signature-checked in the adapter before any module sees them (403 and a log line on failure, Stripe with a 5-minute tolerance), each event is processed once, and security tests prove forgery, replay and missing idempotency keys all fail (SEC-016 to SEC-018, SEC-039). Stripe webhook source addresses are checked against `app/adapters/data/stripe_webhook_ips.json`, a committed copy of Stripe's published `ips_webhooks.json`, never fetched at startup (SEC-049, D-492).
