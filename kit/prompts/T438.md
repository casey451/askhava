## Goal

Token double count (D-3475; D-3305, D-1110, D-3444; BUILD_BRIEF.md:510): `runner/verify.py` `usage_in_transcript` (lines 119-133) adds the `message.usage` of every transcript line, but Claude Code writes one line per content block of a reply, each repeating the reply's `message.id` and `usage` (the fact `turns_in_transcript`, line 136, already counts on), so every recorded token total reads about 1.65 times the real one (T319: 27.6M recorded against about 16.5M; T249: 45.2M against about 26.6M; a 36-line sample transcript holds 17 replies). (1) `usage_in_transcript` counts each reply once: among lines whose `message.usage` is a dict, the LAST line of each string `message.id` gives that reply's usage; a line without a string id counts once on its own; bad JSON, non-object and usage-less lines count nothing, as now. `read_transcripts` and `role_reading` (`runner/github_env.py`, not owned) then record deduped figures without change. (2) Marking, so old and new figures never mix unseen: `runner/cycle.py` `_record_usage` always writes `usage_counting: "message_id"` (also when `cfg.on_usage` is unset) on a `usage.by_task` entry holding no `USAGE_FIELDS` key yet; the claim pre-seeds the entry with `estimated_bytes` and `estimated_tokens` (`scripts/pacing.py:389`), so "new" means no token field, never "task id absent from by_task". An entry spanning the change (token fields recorded before it, more added after) stays unmarked and is corrected by the factor as a whole, a small under-estimate for the few tasks in flight at the change, accepted and logged in `docs/decisions.md` rather than stored separately. No one-time rewrite of `kit/state.json`: unmarked entries keep their raw numbers, and `history[n].usage` rows before this change stay as recorded (documented as per-line in `docs/architecture.md` section 12). (3) Pacing on deduped numbers: new `kit/pacing.json` key `pre_dedupe_factor` 0.6 (T319 16.5/27.6 = 0.60, T249 26.6/45.2 = 0.59), with its note; `scripts/pacing.py` `calibrated()` multiplies an unmarked DONE entry's weighted tokens by it before the median (a marked entry is used as recorded), so `estimate()`, the claim's `estimated_tokens`, `reserved()` and `projected_finish()` (line 375) run on deduped figures; a config without the key reads 1.0, so today's behaviour. The ledger windows (`usage.windows`, a fallback used only when no quota or session reading is under six hours old) are left exactly as today: never scaled, never marked, their shape `{start, tokens}` unchanged (D-3536: scaling them raced in `_windows_onto` across lanes, and an inflated fallback only errs toward waiting and rolls off within 7 days). The weekly `standing.week.used` comes from a session reading or the quota command (the plan's own utilisation; `usage.source` was `session_reading` on November 13), which never sums transcripts, so it is not affected; only its ledger fallback was, and that fallback stays as today (D-3536). (4) `kit/state_schema.json` declares `usage_counting` (enum `message_id`) on `usage.by_task` entries; `python3 scripts/check_state.py` passes on a state with and without them. Tests (new `tests/test_runner_usage_dedupe.py`; no existing test changes, and every existing runner and pacing test passes unchanged; the marker is never made conditional: if a whole-entry comparison in an existing test breaks only because of it, stop and report it as a decided-value change for `docs/decisions.md` under `BUILD_BRIEF.md:69`, never weaken or skip the assertion): a fixture of repeated-id lines (three lines of one id with the same usage, two of another whose last line has a larger `output_tokens`, one id-less line, a usage-less line, bad JSON) gives the per-reply totals with the last line per id winning; `read_transcripts` and `role_reading` over two files of it; `_record_usage` marks an entry the claim pre-seeded with only `estimated_*` (and one with no entry), marks it with the pacer unset too, and leaves an entry with earlier tokens unmarked, never scaling turns; `calibrated()` over three unmarked DONE entries is 0.6 of the old median with the factor and the old median without it, and over marked entries the raw median; `projected_finish` falls by the factor for a calibrated model; `record_usage` leaves the ledger windows exactly as today; `check_state` validates both shapes. Update `docs/architecture.md` section 12 and `docs/decisions.md` (the measured before and after totals of the fixture).

Acceptance: Repeated `message.id` lines count once (last usage per id wins, id-less lines once each) in `usage_in_transcript`; every by_task entry with no token field yet (including one the claim pre-seeded) gets, pacer set or not, `usage_counting: "message_id"`; calibration, estimates and the projected finish apply `pre_dedupe_factor` only to unmarked, pre-change figures and behave as today without the key; `kit/state_schema.json` declares the new keys and `check_state.py` passes; `tests/test_runner_usage_dedupe.py` covers each case and every existing test passes unchanged.
