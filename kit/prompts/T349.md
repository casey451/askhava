# T349: calls: a PIN draw fails only when the OS source fails, and one failed draw costs one draw

Task T349 (build, phase 1, stage 4). Slug: pin-draws-only-fail-on-os.

## Goal

Moved out of T311, which the runner claimed before this fix reached main (D-2451). PIN draws that fail for no reason (D-2451; CALL-003, CALL-017, D-1755): `os_number` (`app/calls/src/pins.rs:53`) rejects two-byte values of 60,000 or more and gives up after 4 tries, so about 1 call in 19,600 it returns `None` although the OS source works (8.4% rejection, 0.0845⁴ ≈ 5.1e-5), and `draw_pin` (`:46`) uses `map_while`, so that one `None` ends all 8 draws; `allocate_pin` then gives none, `assign_number` (`app/calls/src/service.rs:137`) calls `refuse_line` (`:162`), which raises a false High `calls.pool_exhausted` alert and refuses the line with `NoFreePin` (the masked-line assignments at `app/picks/src/release.rs:236` and `app/picks/src/settle.rs:148`; T254's one `picks.line_retry` hides most of them). Fix: `os_number` returns `None` only when the OS source fails, by drawing again until a value below the largest multiple of 10,000 the width holds, with a cap so large it is never the reason (for example 64 two-byte draws, about 2e-69), the bytes coming from an injectable fill function so the rejection step can be tested; `draw_pin` uses `filter_map`, so a failed draw costs one of the 8 draws, not all of them. Unit tests beside the existing ones in `pins.rs`: a source that fails once and then gives a free PIN succeeds; an injected byte source that gives values of 60,000 or more several times and then one below gives that value modulo 10,000; an injected source that fails gives `None`. The two existing unit tests and TD-CALL-13's 500-line integration test (`tests/integration/tests/call_pins.rs`) pass unchanged. After T311 (the other owner of `pins.rs`, whose read-back changes this task must keep). Update the `calls` `CLAUDE.md` and `docs/decisions.md`.
