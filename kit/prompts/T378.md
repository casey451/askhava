## Goal

Nov 11 vendor-double review batch 4, F3 (D-2762; CALL-006, CALL-022, OPS-028, INT-004, SEC-016). `TwilioVoice::open_call` posts only `To` and `From` (`app/adapters/src/voice.rs:55`); Twilio's Calls API needs one of `Url`, `Twiml` or `ApplicationSid` and refuses the create without one, and fetches the call's TwiML only from that parameter. So once T330 registers `place_safety_call` (`app/calls/src/voice.rs:319`) and T108 calls `ring_owner` (`:492`, whose comment expects `owner_bridge_twiml` to run on Casey's answered leg), every safety call and owner bridge fails at Twilio; and no call asks for status callbacks, so `safety_call_answered` (`:464`) is never called. The fake's `create_call` (`stand_ins/twilio.py:264`) takes `To` and `From` only and succeeds. Fix: (1) `VoiceAdapter::open_call` (`app/adapters/src/voice.rs:26`) gains one parameter, a `&CallPlan` (new, in `voice.rs`: the script and the callback settings below), so no create can leave without a script (D-3112: chosen over a second trait method with a default body, which would keep a script-less create that Twilio refuses); it takes the call's script as inline `Twiml` (at most 4,000 characters) for both call kinds, never a `Url` (the owner bridge's TwiML holds the homeowner's number, which must never sit in a URL, so no TwiML-serving route is added), a `StatusCallback` URL on the public base and its `StatusCallbackEvent` list; the safety call asks for Twilio's answering-machine detection with `MachineDetection`, `AsyncAmd=true` and `AsyncAmdStatusCallback` pointing at the same status route with the same alert query (the worker cites the Calls API page). (2) `place_safety_call` sends `safety_twiml` (with its `Gather` `action` an absolute URL on the public base, since inline TwiML has no document URL to resolve a relative one against) and `ring_owner` sends `owner_bridge_twiml` (its signature gains the homeowner's number and the safety words; T108, after this task, calls the new form); a script builder's `None` places no call and logs as today. (3) Two new signed routes in `app/server/src/voice_status.rs`, merged in the shared `app/server/src/lib.rs` like `inbound_voice` and verified like every Twilio webhook over the public base, path and query (SEC-016); each query carries only the alert ID. (a) `POST /webhooks/twilio/voice/status?alert=<id>`: with async detection Twilio posts `answered` before the detection result and without `AnsweredBy`, so the call is decided only by the detection result (`AnsweredBy` `human` to `Person`, `machine_start`, `machine_end_*` and `fax` to `Machine`, `unknown` to `Unknown`) or by a final `CallStatus` of `no-answer`, `busy`, `failed` or `canceled` (`Nobody`); `safety_call_answered` runs once per CallSid (the first deciding post wins); any other callback (`initiated`, `ringing`, `answered`, a `completed` after a decision) is acknowledged and changes nothing; an owner-bridge callback is acknowledged and changes nothing. (b) `POST /webhooks/twilio/voice/safety-key?alert=<id>`, the absolute `Gather` `action` that `safety_twiml` (`app/calls/src/voice.rs:226`) posts the key press to: it calls `safety_call_key` (`:411`; "9" puts her number on the suppression list, CON-035) and answers `hangup_twiml`; a repeat post for the same CallSid changes nothing. (4) `stand_ins/twilio.py`: `create_call` refuses a create with none of `Url`, `Twiml`, `ApplicationSid` with Twilio's 400 error shape, stores the callback URL and events, and a control emits callbacks only to the stored URLs, as Twilio does: `answered` without `AnsweredBy`, then, when detection was asked, the detection result as a separate post to the `AsyncAmdStatusCallback`, then `completed`. Tests: `tests/contract/test_twilio_voice_contract.py` (the refusal, the stored callback, no callback without one) and `tests/integration/tests/voice_call_plan.rs` (a safety call through the served stand-in carries its TwiML and callback, fails before the fix; a `human` detection result acknowledges the alert once; `answered` followed by `machine_end_beep` never acknowledges it (OPS-028); `no-answer` logs `nobody`; a repeat callback changes nothing; a key press of 9 on the safety-key route puts her number on the suppression list and answers hang-up TwiML, another key does not; the owner bridge carries `owner_bridge_twiml`).
