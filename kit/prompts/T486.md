## Goal

Plan change D-3779 (the T261 plan gap; FEE-010, LIC-002; D-019, D-152, D-195): `payments::api::waive_at_confirm` judges the free first win by `JoinDates { joined, launch, trades_opened }` (`app/payments/src/models.rs:286`, `app/payments/src/free_wins.rs:45`), which its caller must read from `businesses` and `catalog` (D-491), but nothing reads `businesses.signup.submitted_at` (written at `app/businesses/src/models.rs:296`) and `catalog.category` stores no switch-on time (`migrations/0027_catalog_module.sql:15` to `:26`). (1) New `app/businesses/src/join_date.rs`, exported by one `pub use` line in the shared `api.rs` and one `mod` line in the shared `lib.rs`: `businesses::api::join_facts(conn, business) -> Result<Option<JoinFacts>, BusinessesError>`, read-only; `JoinFacts` has two accessors: `joined() -> Timestamp`, the sign-up's `submitted_at` (FEE-010: a business joins on the date its sign-up form was submitted, never its activation, D-152), and `trades() -> &[String]`, the category codes chosen at sign-up, `businesses.signup.trades` (FEE-010's "a category they signed up for"; FEE-010's own words; a category added later through the job-type checklist does not count, D-3779); `None` when the business has no sign-up row. (2) `migrations/0190_catalog_switched_on.sql` (after T467's 0189 in the runner's serial order; the queued migrations 0190 to 0207 each move up one, V9): `catalog.category` gains `switched_on_at timestamptz`, the latest time the category was switched on, with `CHECK (NOT enabled OR switched_on_at IS NOT NULL)` (adding it `NOT VALID` and then `VALIDATE` is the worker's choice, postgres brain P2); backfill: every category already on gets `'1970-01-01 00:00:00+00'`, read as "on before launch" (a category on before Gate C is covered by the launch window, D-019); off categories stay null. Before Gate C no real business exists, so this gives the same windows as backfilling from each category's latest `catalog.category_switched` audit row to `on` (`app/catalog/src/service.rs:283` to `:292`, the system switch-offs at `:87` to `:98`); that read is not used because a `catalog` migration may not name `ops.audit_log` (`tests/integration/tests/architecture_migrations.rs`, TD-SEC-35, D-1632) and the column must be filled before the check holds (D-3779). (3) `app/catalog/src/service.rs`: `store_category`'s insert of a new category sets `switched_on_at` to `now()` when the file has it on, and its `ON CONFLICT` update never touches it (as it never touches `enabled`); `set_enabled` sets `switched_on_at = now()` in its one `UPDATE` on every off-to-on change, never on an on-to-on call (which already writes nothing) or a reload, so a trade that reopens after launch gets its own 90 days (D-195, "a trade that opens late"; the switch is owner-only and the win is once per entity key, FEE-011, so toggling gives nothing more, D-3779); switching off, by the owner or by `switch_off_unsafe`, leaves it, and the check holds because a category is enabled only by those two writers, each of which sets the time; the audit rows and every function signature are unchanged, so no caller changes (LIC-002). `catalog::api::trades_opened(conn, codes: &[String]) -> Result<Vec<Timestamp>, CatalogError>`, defined in `service.rs` and re-exported by one `pub use` line in the shared `api.rs`, read-only: the stored `switched_on_at` of every listed category that has one, whether it is on or off now (FEE-010 and D-195 judge only the join date against the switch-on: a later switch-off does not undo a business's eligibility, D-3779); unknown codes and categories never switched on give nothing. T261 builds `JoinDates` from these and the launch-date setting. No fee amount, no `payments` file and no other task's file changes. Tests in `tests/integration/tests/join_dates.rs`, real PostgreSQL, fake data only: `join_facts` returns the submit time and the sign-up trades, not a category added later to the checklist, and `None` for a business with no sign-up row; a new category the file has on reads a switch-on time and one it has off reads none; switching on through `catalog::api::set_category_enabled` records the time, switching off keeps it and the category still answers it, switching on again records the later time, and a reload or a repeated switch-on changes nothing; a category never switched on and an unknown code give nothing; an enabled row with a null time is refused by the check; and TD-FEE-08's switch-on cases hold on the read dates through `payments::api::in_free_win_window` (a business that joined on day 200 for a trade switched on at day 250 is inside, one joining exactly 90 days after the switch-on is outside). Money work (D-3779): an Opus worker, an Opus money review, and two review rounds (the second on the head the first round's fixes produce). Update the `businesses` and `catalog` `CLAUDE.md` and `NOTES.md` files, `docs/architecture.md` section 3 (the new column) and `docs/decisions.md`.

Acceptance: `tests/integration/tests/join_dates.rs` passes against PostgreSQL: `businesses::api::join_facts` returns the sign-up's submit time and sign-up trades (`None` with no sign-up row); `catalog::api::trades_opened` returns the latest switch-on time of each listed category that has one, on or off now, and nothing for unknown or never-switched-on codes; the migration's backfill and check hold; TD-FEE-08's switch-on cases hold on the read dates; `tests/integration/tests/catalog_settings.rs`, `tests/integration/tests/capability_offer.rs`, `app/server/tests/catalog_start.rs`, `tests/integration/tests/free_wins.rs` and `app/catalog/src/tests/loader.rs` pass unchanged.
