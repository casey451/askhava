# T149: businesses: sign-up deliverability check with a sample card, and the backup notice address

Task T149 (build, phase 1, stage 4). Slug: business-email-reliability.
Branch: `claude/task/T149-business-email-reliability`
Model: `claude-opus-5-5`, effort high. Reviewer: `claude-opus-5-5` (areas: privacy, security, compliance).

## Goal

After email verification sign-up sends a fake sample card from the real sender and walks the person through the inbox, spam and alert steps for their mail app without blocking activation; and a verified backup notice address can be added only from that person's or the owner's session (BIZ-042, BIZ-043). Each mail-app step is written in `docs/copy/mail-app-steps.md` with the maker's help-page address and the date it was checked, and the screens read it; the backup address reaches every notice by extending `businesses::api::notice_addresses` (T220's), the one lookup the enqueuing modules (`quotes`' card notices, T147; `picks`' pick and release notices, T063 and T069) call before handing `messaging` opaque address IDs (so the release purpose returns a backup only for an owner or a "Confirm and billing" person); the test emergency email is T150's (D-491). Adding or changing a backup address needs a Verify code from the last 5 minutes (SEC-038, TD-SEC-17, D-492). The "Send a sample pick" step is shown the first time an owner or "Confirm and billing" person opens a real job card, in the job-card page route `app/portals/src/business_actions.rs` (T148's, extended here) (TD-BIZ-28, D-493).
