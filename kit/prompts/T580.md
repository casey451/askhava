## Goal

Plan change D-4052 (Casey's outside code audit, batch B, Nov 17, 2026; each item re-checked on `main` 67f601a before planning): (B4) `messaging::api::delivery_status` (`app/messaging/src/service.rs:332` to `:351`) returns `Sending` for every outbox status other than `queued` and `sent` with a SID, so a row that ended `blocked`, `failed` or `expired` (`migrations/0182_messaging_outbox_not_before.sql:23`) reads as still sending, and the card timer (`app/intake/src/summary_step.rs:309`, `card_text_watch` in `app/intake/src/status.rs:13` to `:19`) looks again every few minutes for ever (INT-041, TXT-013). The function maps `blocked`, `failed` and `expired` to `DeliveryStatus::Failed` and `unknown` (the carrier may hold it; never resent) to `Sent`, so the card timer starts its wait; `queued` stays `Queued` and `sending` stays `Sending`; the doc comment says so. (B20) `refused` (`service.rs:316` to `:322`) counts every 4xx as a definite refusal, so a 429 rate limit goes to `retries::record_failure` (`app/messaging/src/outbox_sender.rs:294`, `:303` to `:324`) and three of them give the text up (TXT-014, TXT-015). A 429 (and Twilio code 20429 on any status; `OutboxError` and `Carrier` live in `app/messaging/src/models.rs:20`, which this task owns for that variant only) is still proof nothing was sent (TXT-011), so the row is released as now, but a new `OutboxError` variant (or a field on `Carrier`) tells the sender to hold the row for one minute (a `const`, doubling on each 429 in a row up to 15 minutes, derived from the row's current hold; no migration) without calling `record_failure`; the adapter does not surface `Retry-After`, so none is read. (Doc) `app/messaging/CLAUDE.md:7` (shared) still says every text begins "Ask Hava:"; it becomes "Every text begins `<short_name>:` from the brand file (today `Laftly:`)", keeping the test name as it is (D-3347 (4)). Tests in the new `tests/integration/tests/outbox_end_states.rs`, against PostgreSQL with the stand-in Twilio and fake data only: each of `blocked`, `failed`, `expired` reads `Failed` and `unknown` reads `Sent`; a card timer on a failed summary text stops (no new timer queued); a 429 from the stand-in holds the row, leaves its failure count unchanged, and the text goes on the next try; three 429s then a send still send once; a 400 is still a counted failure. `tests/integration/tests/outbox_sender.rs` and `outbox.rs` pass unchanged. Ordered after T526, which owns `outbox_sender.rs` now (and, once D-4051 merges, after T573, which owns `service.rs`). Plan change D-4327 (night spot review of outgoing email, Nov 18, 2026, re-verified on `main` d662af7e5): `MANAGE_URL` (`app/messaging/src/outbox_sender.rs:61`, used in `email_to` at `:339`) is the relative `/h`, so the failed-text email copy's "Manage email notices" link (the footer `href`, `app/messaging/src/email.rs:365`, and the plain-text line, `:372` to `:373`) leads nowhere from an inbox (SEC-028; SEC-025: links only to laftly.com); every other sender uses `OnDomain("/h")` (`app/messaging/src/optout_email.rs:44`).
