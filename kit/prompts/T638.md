What changes: in each of the four `changes` steps of `.github/workflows/ci.yml` (Checks: `rust` and `npm`; Lint and slow tests: `rust`; Coverage: `rust`; E2e: `run`), after today's rule has set a flag true on a branch run, a new standard-library script `scripts/ci_proven.py` may set that flag back to false, only when ALL of these hold for a candidate commit C: (1) C is HEAD^1, HEAD has exactly two parents, and HEAD^2 is on origin/main's first-parent line (`git rev-list --first-parent origin/main` over the depth the step already fetches); that is the runner's update merge (`runner/update_merge.py` `commit`: parents the reviewed head, then main; after an update the reviewed head is the previous update merge, whose own `ci` ran); (2) every run of this repository's `.github/workflows/ci.yml` workflow on C (Actions REST, matched by the workflow's id or its exact `path`, `event == push`, and the run's `repository.full_name` and `head_repository.full_name` both equal to `GITHUB_REPOSITORY`; every attempt) has the same job, by its exact name, completed with conclusion `success`, and at least one such job exists; (3) `git -c core.quotepath=off diff -z --no-renames --name-only C HEAD` (NUL-separated, so no path is quoted or split) matches neither that flag's own rule regex (the very string the step already uses, passed to the script, never a second copy) nor `tests/coverage_floor.json`, `scripts/coverage_floor.py`, `.cargo/`, `.github/workflows/` or `scripts/ci_proven.py`. Anything else means unproven and the flag stays true: a HEAD with one or three parents; HEAD^2 off main's first-parent line or beyond the fetch; a run queued or in progress; any conclusion but `success` (skipped, cancelled, neutral, timed_out, failure); a missing job; an HTTP error; a timeout (10 s per call); a page that may be incomplete; malformed JSON; a git error. The script prints exactly one line, `proven=<40-hex sha>` or `unproven: <why>`, and always exits 0; a step trusts only an exact `proven=` line. Schedule, workflow_dispatch and `main` runs keep their early exit (always compile). No step outside the four flags changes: the sources fingerprint, gitleaks, the PII scan, conflict markers, plan lock and change rules, the delete guard (`ci.yml:146`, still before the Checks changes step), the Rust source rules, approved crates, the compiled-in-file check (D-1867), every other Python step and the whole Python job still run on HEAD. ## Output discipline

Every turn re-reads earlier tool output; large results cost tokens on every later turn (D-3305). Never omit failure lines to save tokens.

1. For a file over 200 lines (`wc -l`), never `cat` or `Read` it whole. Use `grep -n` with at most `-C` 3, then `sed -n 'A,Bp'` or Read with offset/limit: at most 120 lines, or 250 if one read replaces two. Don't re-read unchanged files or regions; use earlier output.
2. Log build, test and lint output; print only decisive lines. Example: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`. Grep each tool's failure markers: cargo/clippy `^error|FAILED|panicked`, pytest `FAILED|ERROR`, tsc `error TS`, npm `ERR!`, playwright `✘|failed`.
