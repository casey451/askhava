# T282: calls and picks: each call's start time reaches the unreachable refund rule

## Goal

`call_record` (`app/picks/src/unreachable_refund.rs:69`, T191's, merged in #323) puts `LoggedCall::ended_at` into `payments`' `CallRecord::at`, which means when the call started (`app/payments/src/refund_rules.rs:49`), so FEE-022's 8 a.m. to 8 p.m. hours, its 72 hours and its 3-hour spacing are judged on end times; the call log stores only the end and the talk length (`app/calls/src/handlers.rs:133`), and talk length does not include ringing, so subtracting it is not a start time (second external audit B06, D-1836). The start is recorded where the app must already be reached: T262's inbound voice webhook stores it in `calls.call_start` (T262's migration 0151) keyed by the parent CallSid when it answers, and T271's route records the dialed leg's `initiated` callback against that row by `ParentCallSid`. In `app/calls/src/handlers.rs`: `dial_twiml` asks for the dialed leg's `initiated` and final status callbacks at T271's route; `call_start_confirmed(db, parent, dialed, at)` records the dialed leg's SID on the parent's row, or creates the row at `at` when the webhook's write was lost (a repeat or late callback never moves a start); `call_log` joins each logged call to its start by the dialed SID and returns `LoggedCall::started_at: Option<Timestamp>`. `call_record` uses `started_at`; a call whose start was still not recorded uses its end time for every FEE-022 check and counts as a qualifying attempt, because a lost callback is Ask Hava's fault and the business must not lose its refund for it (D-1836; `payments`' rules are not changed). This is a harness task because it takes over T191's `tests/integration/tests/unreachable_refund.rs`: its `call` helper sets `started_at` to the time it already passes, and no expected value changes. New cases in `tests/integration/tests/call_start.rs`. Update the `calls` and `picks` `CLAUDE.md` files and `docs/decisions.md`.

Acceptance: TD-CALL-15 passes against PostgreSQL; every TD-JOB-07, TD-FEE-22, TD-TXT-10, TD-TXT-13, TD-TXT-30 and TD-FEE-39 case in `tests/integration/tests/unreachable_refund.rs` passes with only its `call` helper given `started_at`, and no expected value changes; every TD-CALL-04 case still passes.
