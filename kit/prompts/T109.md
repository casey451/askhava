# T109: recovery: backup checks and the nightly encrypted export

Task T109 (build, phase 1, stage 5). Slug: recovery-backup-export.
Branch: `claude/task/T109-recovery-backup-export`
Model: `claude-opus-5-5`, effort high. Reviewer: `claude-opus-5-5` (areas: privacy, recovery, security).

## Goal

`recovery` makes the nightly encrypted export to separate storage under its own key, kept 30 days with versioning and object lock, runs the monthly test restore with a High alert on failure, and leaves the key inventory to T117; `recovery` records each backup and restore result through `ops::api` (a function added here), and `portals` reads them from `ops`: the restore result line in `digest_flags.rs` (T204's) and the last-backup figure in `health_page.rs` (T106's), both extended here (D-491, D-493) (OPS-013, PRIV-018, PRIV-024, PRIV-029). The export is `pg_dump -Fc`; every restore runs `scripts/bootstrap_roles.sql` first, then `pg_restore --single-transaction`, with the ownership and append-only grant check (OPS-051), and the storage provider is Backblaze B2 (PRIV-029) (D-492).
