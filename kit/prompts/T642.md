## Goal

Plan change D-4281 (Fable's merge-speed decision, Nov 18, 2026, about 00:30Z, `main` 7f322437, under Casey's standing rule: speed is the goal, quality must not decline). Task B, the keeper acts on free-lane work (Fable item 1; robustness, at most about 65 lane-minutes a day). With seven lanes the keeper never starts a run: `keeper.wake_after` returns the soonest live lease's end plus 2 (`runner/keeper.py:115`) before it looks at work (`:127`), and with 3-hour leases renewed every 30 minutes that is always 120 to 180 minutes; `on_wake` re-arms whenever any other backup-runner run is live. On Nov 17 lane 2 sat free from 00:33 to 01:13Z with claimable work after refill run 43993852568 failed. Change, with the blocker (flag off; red main waiting for a person), the unreadable rule, the pacer's wait and the week stop all still winning first: (1) `free_slots(state, now, lanes)` = the smaller of the numbered lanes 1 to `lanes` (kit/runner.json; 1 while `lanes_fallback`) with no task in flight (`st.in_flight`: a live lease, or MERGE_PENDING on its own lane) and the lanes `cycle.refill_lanes(cfg, state, now)` returns (`runner/cycle.py:1753`, the chain step's own rule: free lanes, no red main, no pacer wait, eligibility, `lanes.compatible_ids`, the crate rule and the read-only `_plan_keep`, so a task a claim already marked `plan_gap` gets no lane, D-3812), with the Config built read-only as `runner/__main__.py` builds it (`cfg = cycle.Config(kit["tasks"], kit["models"], kit["protected_paths"], kit["shared_paths"], outbox_dir, session, now_utc, gate, pacer, usage_recorder, owner_paths, lanes(ROOT / "kit" / "runner.json"), env.decision_numbers, proof_stages=..., locked=locked_path, plan_health=claim_health(kit, refusal), claim_first=..., order=..., prefer_disjoint_crates=..., exclusive_crates=..., crate_cap=..., crate_full=crate_doc_full(ROOT), smoke_ancestry=...)`, about lines 240 to 256, passed to `cycle.refill_lanes` by `refill` at `:950` to `:961`); read only `runner/cycle.py:1745` to `:1790` (`refill_lanes` and its helpers) and that Config build, not the whole files; this task does not own `__main__.py`, so it builds the Config the same way from the keeper's main checkout without changing that file, and if that proves too heavy it counts every `plan_gap`-marked task as 0 (fail safe) instead; NOT `has_work`, which is true whenever any task is MERGE_PENDING (nearly always with seven lanes) and would start boots that can only end `merge_pending`; a state it cannot read gives 0. (2) `wake_after`: when free_slots is above 0 and `last` (the arming cycle's own result) is neither in NOTHING_CLAIMED nor in `runner/__main__.py` REFILL_STOP (copy the names, with a test that the two sets are equal), it returns IDLE_MINUTES with why `free lanes: <n> with claimable work`, before the live-lease branch. `on_wake` gets the same guard: the keeper step reads `kit/runner_log.jsonl` (as the arm step does) and passes the last cycle result to `on_wake` (`--log`), so a lease-length sleep that follows a REFILL_STOP result does not wake into the short path; an unreadable log means no short path. (3) `on_wake`: in that case `go` with the lanes to start, even while other runs are live: the free lanes minus every lane whose backup job is queued or in progress (the backup job's `name` gains its lane, `backup lane <n>` from `needs.gate.outputs.lane`, read from the Actions REST list of each live run's jobs; check first that nothing in `runner/`, `scripts/` or `.github/` reads the job's name), minus one more free lane for each live run whose lane cannot be read (a gate still waiting for auto-merge), at most free_slots; none left gives `rearm` as today. The keeper step passes the jobs it read (`--jobs`, written like `--runs`; a failed read leaves no file and today's behaviour) and, for `go` with lanes, runs `gh workflow run backup-runner.yml -f lane=<n>` once per lane, as the hourly tick does; `go` with no lanes (one lane) dispatches as today. It cannot spin: one sleeper (the keeper's concurrency group); at most free_slots dispatches per wake; each dispatched run takes its lane's concurrency group (one runs, one waits); a run that claims nothing ends in REFILL_STOP, and its keeper arm then never takes the short path. Unchanged: the gate's lane pick (`st.run_lane`), leases, claims, the hourly tick, auto-merge, the merge line and red main. Measure, in the decision entry a day after the merge: keeper `go` count and boots that end without a claim. Tests, in `tests/test_runner_keeper.py` (every existing case passes unchanged), planted: 7 lanes, 5 in flight, 3 eligible gives 20 minutes and `go` with 2 lanes; 7 in flight gives the lease time as today; 5 in flight, 0 eligible but MERGE_PENDING tasks gives no short sleep; `last` of idle, fix_main, paced, no_free_lane, lease_live, lost_race or smoke_pending gives no short sleep, at arm and at wake; eligible tasks that overlap a task in flight or clash on a crate count 0; a `plan_gap`-marked task plus a merged last result gives no short sleep (planted, the D-3812 failure); the pacer waiting or the week stopped gives their times; the flag off or an escalated red main stops; an unreadable state looks again in IDLE_MINUTES as today; live runs on lanes 6 and 7 give `go` only for the other free lanes; a live run with no readable lane gives one fewer; unreadable jobs give today's rearm; `lanes_fallback` gives lane 1 only; in the workflow the keeper step dispatches `-f lane=` per listed lane and the backup job's name carries its lane. `docs/architecture.md` section 12's "Keeper (D-1451)" bullet says so.
