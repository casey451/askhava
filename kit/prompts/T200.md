## Goal

The owner help page lists open help requests with a 300-character reply box screened like a quote, and businesses send help through the portal's Get help form, which opens one request (BIZ-047, CON-034, OPS-036). The "Get help" link is business-only (plan change D-3155, owner call put to a Fable agent under Casey's Nov 11 standing rule): the shared layout `app/site/templates/base.html` (after T101's banner block) gets an empty `get_help` block, and the new `app/portals/templates/business_layout.html` extends it and fills that block with the link; `get_help.html`, `business_home.html` and `business_billing.html` extend `business_layout.html` here, the other signed-in business pages in T410 (T364's and T375's new pages extend it themselves); no homeowner, owner or public page fills it, and the site help page's owner-message form (`help.html`) is wired to the same help-request endpoint here (D-491). A delete or copy request that arrives by email or the help form is acted on only after a Verify code to the number on file and answered within 30 days (PRIV-031, D-493). T305 serves the owner help page and T309 the Get help form and the site help form's endpoint (D-2128): page functions and route constants only, no `.route` in `server`; the browser halves of TD-BIZ-23 and TD-PRIV-16 run in T309's spec, and `tests/e2e/get_help.spec.ts` checks what an unserved page allows. Plan change D-3155: the help page's form runs the opt-out detector (CON-035) on its message; an opt-out ("no more texts") calls `messaging::api::suppress` with `RevokeChannel::HelpForm` and is confirmed on screen, never by text (TD-CON-17's help-form half). The link goes only on pages a signed-in business sees, because the Get help form is behind the business session (T309).
