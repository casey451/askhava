## Goal

Plan change D-4294 (spot review of privacy, verified on `main` fde4fad3; INT-027, PRIV-008, PRIV-005, AI-003, AI-020). (1) After the code, `chat_message` (`app/intake/src/web_chat.rs:247` to `:286`) calls `receive_text` and then `keep_words` for every message in a request with a job; it never reaches `replies::receive_raw_reply`, whose name-and-address branch hands the raw text only to `take_name_address` (`app/intake/src/replies.rs:17` to `:23`). So her answer to the step-11 question typed in the chat ("Maria Sample, 42 Sample St") reaches no vault field and is kept in `quotes.job_description` with the first name left in (the chat scrub has no vault name, below), where `order::build_and_keep` would build the card from it. Fix: while `intake::api::name_address_open` holds for the session's contact, the chat turn goes to `receive_raw_reply` with the raw text and the vault (`RawReply`, `replies.rs:75`), under the same rules as a text (LIST and CLOSE keep their path; `reads_as_address` decides the screen), and `keep_words` is not called for that turn; T645's opt-out check stays first, and its under-18 stop is not run twice. The raw text comes from `site::chat` (which holds it before its scrub, `app/site/src/chat.rs:316` to `:318`) as a `SecretString` together with the vault the chat's code keys hold (`app/server/src/chat_codes.rs`), never logged, stored in the session or shown back. (2) The chat scrubs every message with no vault name and a fresh `NameMemory` (`chat_codes::scrubbed`, `app/server/src/chat_codes.rs:104` to `:115`), where the SMS path scrubs with her vault name and the names she stated before (`privacy::api::read_inbound_for`, `app/privacy/src/scrub_context.rs:40`, called at `app/server/src/inbound_text.rs:990`). After the code, the composition scrubs the chat's words through `read_inbound_for` with the session's contact, so the vault name and every name she stated (in a text or the chat) are removed before `intake`, the kept description and, once T299 wires it, the AI; before the code the no-contact scrub stays (there is no contact). Vault errors are handled exactly as the SMS path's `read` does (`app/server/src/inbound_text.rs:990` to `:994`, D-2088): a vault `Database` or `Audit` error fails the turn and keeps nothing; any other vault error falls back to the empty-context scrub and the turn stops before `intake` and the AI. The chat's `Scrub` type in `site` changes as needed; `site` still calls no `privacy` function itself (`kit/layers.json`), and the shared `app/server/src/lib.rs` passes the new parts. (3) Tests, fake data only, in `app/server/tests/web_chat_after_code.rs` through the assembled router's `/request` (TD-INT-43, TD-AI-30). Update `docs/architecture.md`, `app/site/CLAUDE.md` or `NOTES.md`, `app/server/NOTES.md`, `app/intake/NOTES.md` and `docs/decisions.md`. Budget 4 files, 420 lines. Review round 1 (D-4294): an age under 13 in a turn that went to `receive_raw_reply` (its `Reply::UnderAge`, or INT-038's reply inside `Handled`) also deletes the `intake.web_chat_session` row in the same outer transaction, as T645 does for its path, and TD-INT-43 checks it; the chat's `Inbound` keeps `opt_out` and `help` false (T645's check ran first), so `check_in_reply` and the close step behave as on a text.
