## Goal

(1) A `payment_intent.succeeded` whose `metadata.pick_id` is missing or not a UUID is acknowledged 200 before any database read and recorded nowhere (`dispatch_of`, `app/payments/src/routes.rs:254`; `pick_of` :290; `checked` `None` answered 200 at :170). It becomes `Dispatch::Unreadable`: one `payments.webhook_event` row and one High `payments.stripe_event_unreadable` alert (no subject) in that row's transaction, answered 200, so it alerts once per event ID; nothing is released from untrusted metadata, and the nightly reconcile (FEE-029) still matches the charge by its PaymentIntent. (2) A `radar.early_fraud_warning.created` whose PaymentIntent has a `payments.pick_intent` row but no `payments.charge_evidence` row today returns `Acted::Unknown` and rolls back (`routes.rs:417`, :534, answered 200 at :333). A harness task because `tests/integration/tests/stripe_webhook_dispatch.rs` is T259's (DONE); its existing cases change only where they pinned the old silent answers, which D-2289 lists. Tests there (TD-FEE-53, TD-FEE-54): missing, empty and non-UUID `pick_id`; a duplicate event; a warning before the evidence row (500 with one alert, a second resend before the row raising nothing new, then 200 and acted on once the row exists); an unmatched warning.
