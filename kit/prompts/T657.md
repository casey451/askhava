## Goal

Plan change D-4326 (night accessibility spot review of `main` e64d06e02, re-verified on `main` d662af7e5; A11Y-030, TD-A11Y-02). (1) `PriceProblem::field` (`app/quotes/src/formats.rs:146` to `:154`) sends every package fault to `tier1_name` and every range fault to `low`, so a business whose package 3 has a name and no price, or whose high price is bad, is pointed at package 1's name or the low price (WCAG 3.3.1). `PriceProblem::Tiers` and `PriceProblem::Range` now carry where the first fault is: for packages, the first package (1 to 3) with only one of its name and price or a price that is not an amount, and whether its name or its price is at fault (`tier<n>_name` or `tier<n>_price`; with no package at all, `tier1_name` as today); for a range, `low` when the low is not an amount, else `high`. `field()` answers that element's ID, `message()` keeps today's words, and every input that fails today still fails (`tests/integration/tests/quote_whole_field_gate.rs` and `quote_formats.rs` pass unchanged). (2) `app/portals/templates/business_actions.html` (`:97` to `:103`): each package name or price input whose ID is the problem's field gets `aria-invalid="true"` and `aria-describedby` naming the error line, so the summary's link lands on it; the `visit_date` (`:149`) and `minutes` (`:168`) inputs get `aria-invalid="true"` when their error shows, as `days` does (`:80`). (3) `app/portals/templates/capability_setup.html:52`: `largest_amount` gets `aria-invalid="true"` when the `largest` error shows. (4) `app/portals/templates/owner_signin.html`: the failed page keeps its one generic line, "That didn't work", which on purpose never says which factor failed; so the password (`:19`) and the code (`:22`) both get `aria-invalid="true"` and an `aria-describedby` naming the summary's line, both or neither, never one alone. (5) Tests, fake data only: unit tests in the new `app/quotes/src/tests/price_fields.rs` (`tests/mod.rs` is shared) for each package and range fault's field; `tests/e2e/portal_form_errors.spec.ts` (TD-A11Y-05) posts each failed form through the served routes as the existing served specs do (`tests/e2e/owner_signin_served.spec.ts`, `business_portal_served.spec.ts`, `action_links_served.spec.ts`): owner sign-in with a wrong password, the owner step-up with a wrong code, business sign-in with an empty address, and the quote form with package 3 named but unpriced and with a bad high price; for each it checks the "Error: " title, the focused summary first in `main`, `aria-invalid="true"` on exactly the faulty fields (both sign-in factors together) and no `axeScan` violation at 320 and 1280 px. `tests/a11y/page_states.ts` opens states by GET only, so these POST answers are scanned here. If a scan finds a fault on a page this task does not own (`owner_step_up.html`, `business_signin.html`), it reports it rather than editing it.
