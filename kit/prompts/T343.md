# T343: harness: the DONE pick tests' fixtures record each job's facts, before the fee reads them

Task T343 (harness, phase 1, stage 4). Slug: job-facts-in-pick-fixtures.

## Goal

Seventh audit fix round (D-2331, D-2330): once T340 prices the pick from the job's stored facts, a non-emergency job with no facts row is refused at the pick, so the DONE tests whose fixtures create a job and pick it would fail. This task changes only those fixtures: after a fixture creates a job, it records a facts row through T339's `jobs::api::record_job_facts` with a category and job type whose catalog resolution gives the facts the test already assumes (not fee-free, the category's default visit tier, recurring only where the test's quote has a period), so every expected value stays as it is. Files: `tests/integration/tests/fee_fixed_at_pick.rs` (T287), `page_pick.rs` (T246), `text_pick.rs` (T054), `app/server/tests/release_recovery.rs` (T254, T287), `consent_records.rs` (T181) and `first_quote_move.rs` (T247); and (D-3112) `tests/integration/tests/accepted_quote_email.rs` (T388, `:184`), `auto_confirm.rs` (T209, `:215`), `backup_choice.rs` (T157, `:75`), `business_leaving.rs` (T228, `:219`, `:227`), `quote_shown_changes.rs` (T384, `:320`, `:332`), `share_and_cant_take.rs` (T214, `:376`, `:449`), `tests/security/tests/page_pick_privacy.rs` (T246, T214, the served pick at `:237`) and `tests/e2e/j1_homeowner.spec.ts` (T098, T214: `seedQuotes` inserts the job by SQL and the test finishes the pick, so the seed inserts one `jobs.job_facts` row in the same statement). T340 resolves the codes through `catalog::api` from the stored catalog, which no Rust fixture stores (T400 stores it only when the web server starts), so each Rust fixture that records facts also stores the catalog once (`catalog::api::load_embedded`) before it (`tests/security/Cargo.toml` has no `askhava-catalog` dev-dependency, so the worker adds that one line to the shared manifest for `page_pick_privacy.rs`); the served e2e server stores it itself after T400. The server crate's door probe (T348's) also picks a job; its facts row is T404's, which owns that file. No assertion, case or expected value changes, none is removed, and no new case is added; recording facts changes no behaviour until T340, so every test passes before and after (D-2331 is the logged spec change). Harness: an Opus review.

Acceptance: Every test in the fourteen files passes with its assertions unchanged and each fixture job holding a facts row; the diff of the fourteen files shows only fixture lines that record facts and, once per fixture, the line that stores the catalog (in the e2e seed, the facts row's insert), plus the one `askhava-catalog` dev-dependency line in the shared `tests/security/Cargo.toml`; T340 must keep them passing.
