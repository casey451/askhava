## Goal

PICK-024's release email carries "a signed link that opens sign-in"; T147 fills each recipient's `{link}` (D-1565 (2), D-1761), but nothing on the sign-in side checks it, and T194, which owns sign-in now, is already running (D-1761). In `app/portals/src/business_auth.rs` (after T194 and T253, its other queued owners), the business sign-in page accepts the link `core`'s `link_token(secret, LinkKind::Action, person, LinkSalt::from_bytes(job number as 8 big-endian bytes ‖ expiry as 8 big-endian Unix seconds))` with the person ID, job number and expiry in the URL: it recomputes the token and compares in constant time; a valid, unexpired link opens sign-in for that person (the one-time link or code flow of T084 and T194, unchanged) with the job page as the next page after sign-in; a tampered, expired or other person's link opens plain sign-in; the link alone never signs anyone in or shows any job detail. Tests in `tests/integration/tests/notice_signin_link.rs`. Update the `portals` `CLAUDE.md` and `docs/decisions.md`.

Acceptance: TD-PICK-51 passes against PostgreSQL; every T084, T194 and T253 sign-in case still passes unchanged.
