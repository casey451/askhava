## Goal

Nov 11 code review batch 3, F6 (b), found while checking it (D-2704; LIC-006, LIC-007, LIC-008, LIC-010, LIC-039, CARD-015, D-230, D-942): nothing in production runs the daily lists: `licensing::api::import_roc_list` and `import_city_list` (`app/licensing/src/service.rs:74`, `:106`) have test callers only, `LicenseSource::fetch_daily_list` (`app/adapters/src/license_sources.rs:19`) is never called, and `list_failure_alerts`, `alert_list_failure` and `lookup_while_list_fails` (`app/licensing/src/handlers.rs`) wait for a caller that holds the failure start (its module docs); so verified statuses never update from the lists, a license that lapsed keeps its cards, and no re-apply (T372) can ever see a class change. T134 only puts the real sources behind the adapter. Fix: `app/licensing/src/daily_lists.rs`: a `licensing.daily_lists` task, registered in the shared worker and queued once a day at a fixed Arizona time (a setting) with tomorrow queued first (D-737), fetches each list through `LicenseSource` (the `file://` fixtures in the build), records it with the import function, and on a fetch or import failure takes the failure start from licensing's own import records when the list was imported before (`licensing.list_import` stores successful imports only, `app/licensing/src/service.rs:149`); a list never imported has no such start and nothing stores when the alerts last ran, so the failure start and the last run time travel in the re-queued task's payload (no new table; plan change D-3106), and it raises `alert_list_failure`'s alerts once each, and runs `lookup_while_list_fails` for that list's active businesses at the throttle, bounded per run (a capped batch, a setting, the rest on the next run); the (business, license number) pairs come from `businesses::api` through the server's handler wiring in the shared `app/server/src/lib.rs`, since licensing may not call businesses (`kit/layers.json`); while a list is failing the task re-queues itself on a short cadence (hourly, a setting) instead of daily, so the 12-hour alert fires on time; a run that succeeds after failures ends the failure; a second run for the same list date records nothing new. Tests in `tests/integration/tests/daily_license_lists.rs` (TD-LIC-28), clock advanced: a fixture list is recorded once and a re-run adds nothing; a missing list for 12 hours raises the listed alert once and runs the lookups at least the spacing apart and never more than the batch cap per run, the remainder on later runs; the hourly re-runs raise the 12-hour alert within the hour it falls due; at 24 hours the push alert once; the next good list ends the failure. Update the `licensing` and `server` `CLAUDE.md` files and `docs/decisions.md`. Plan change D-2954: the license source's base URL is the setting `ASKHAVA_LICENSE_BASE_URL` (T385 adds the key; required in `test` and `live`), and the list names are `roc` and `city`, the names of T385's e2e fixture lists.
