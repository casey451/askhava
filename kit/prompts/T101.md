## Goal

The site's base layout (`app/site/templates/base.html`, the shared template T051 created, restyled here, plus the stylesheet and routes; this task extends the minimal `app/site/Cargo.toml` and `src/lib.rs` T051 created, D-492) renders every page server-side without JavaScript in the design spec's daylight-and-evergreen look (V6, D-3331), with one `h1`, landmarks, a skip link, `lang` on page and passages and help in the same place on every page (A11Y-003, A11Y-004, A11Y-017, WEB-001, A11Y-026, A11Y-029, A11Y-030). The WEB-007 status banner is hidden by default (TD-WEB-01's banner case) (D-493); its on or off state is read from T279's `ops::api` status banner (D-1843). Plan change D-3144: the banner is on the site's own pages (WEB-007: "The site has a status banner"), not on portal pages: `base.html` gains an empty `{% block banner %}{% endblock %}` above the header, which only the new site layout `app/site/templates/site_layout.html` (extending `base.html`) fills, with the WEB-007 sentence when its `banner_shown` field is true; the 23 portal templates that extend `base.html` through `app/portals/askama.toml` keep the empty block, so no portal struct gains a field; every site page (T102, T103, T115, T201, T202, T221) extends `site_layout.html` and fills `banner_shown` per request from `ops::api::banner_shown` (`app/ops/src/status_banner.rs:32`, an async read the handler makes before rendering) through one site helper this task adds. The stylesheet, and the fonts and photos T166 and T216 add, are compiled into the binary (`include_bytes!`, a fixed list of name, MIME type and bytes in the new `app/site/src/assets.rs`), because the runtime image keeps only the built `.js` files (`Dockerfile:17` to `:21`), and are served at `/static/site/<name>` by one `Router::nest_service("/static/site", get(asset))` mount with no `.route(` line and no `/`-prefixed `*_PATH` or `*_ROUTE` constant (T362's rule, D-3106: `tests/security/tests/auth_matrix.rs:276` to `:300` reads those as routes, and its test router, `:400` to `:408`, merges no site route, so a `.route(` there would answer 404 in `td_sec_01`); an unknown name is a 404 and another method a 405 with `Allow`. No site script is written (`site.ts` is dropped; the pages work without JavaScript), so T362's `/static/<crate>/` folder has no `site` entry; this task runs after T362 and proves both mounts answer through `build_router`. The site's router is merged in `build_router` (the shared `app/server/src/lib.rs`), and each later site task merges its own page router there. The `nest_service` call gets a reasoned `NOT_PAGES` line in the shared `tests/a11y/fixtures.ts` (its A11Y-002 scan lists every such call, `:64`), and section 13 gets the row `GET /static/site/site.css` (module `site`) marked `yes`.
