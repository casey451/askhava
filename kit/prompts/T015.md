### 2. Principles (lines naming this task's requirements)
**P5. Append-only is a missing privilege, tested as the app role.** Append-only tables (`ops.audit_log`, `payments.ledger_entry`, `payments.charge_evidence`, the consent and opt-out event tables) get `SELECT, INSERT` only. `TRUNCATE` is its own privilege, separate from `DELETE` (docs), so never grant it to the app role. Default privileges grant `UPDATE, DELETE` broadly, so the creating migration must `REVOKE UPDATE, DELETE ON <table> FROM askhava_app` right after `CREATE TABLE` [inferred from P4]. Tests `SET ROLE askhava_app` and expect the `UPDATE` to fail (D-481). The off-database audit stream is the second copy (OPS-010, OPS-011). Serves D-092, OPS-010, FEE-029.
### 4. Checklist
1. The migration is new, numbered, forward-only, and its first comment names module, purpose and requirement IDs (P1).
2. It touches only its own module's schema; no cross-schema foreign key (Arch 4 rule 3).

5. Append-only tables revoke `UPDATE`, `DELETE`, `TRUNCATE` from the app role, and a `SET ROLE` test proves it (P5).

### 2. Principles that bind this codebase (lines naming this task's requirements)
**R11. Work that leaves the database is queued in the same transaction as the state change.** A state change and its `core.task` row commit together; never call a vendor inside the transaction that changes status. Brandur: enqueue mid-transaction and the job runs too early; enqueue after commit and a crash loses it ("Data is persisted, but the background work doesn't get done"). Here the queue is in the same database, so the insert is simply part of the transaction. Serves JOB-004, JOB-005, JOB-006, Arch 4 rule 2.
**R15. Every request carries an ID into every log line; arguments are not logged by default.** Set `x-request-id` with tower-http `SetRequestIdLayer` *before* `TraceLayer` ("make sure to set request ids before the request reaches `TraceLayer`"), propagate it to the response. `#[instrument]` records all arguments by default with `Debug`, so use `skip_all` and name fields explicitly (tracing-attributes docs). Serves PRIV-016, SEC-048, OPS-011 (web request log).
