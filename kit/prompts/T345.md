Nothing else in the workflows changes (permissions and tokens stay as they are; trimming them is not this task). `.github/dependabot.yml` already watches the `github-actions` ecosystem, so the pins get update pull requests. Proof for the runner pin: the next runner cycle after the merge completes on fake data; the hand-in report says how to revert (the one-line pin back to `@v1` in `backup-runner.yml`, by a harness pull request) if it does not. The repository-wide test that keeps every workflow pinned is T121's (TD-SEC-24). Harness: an Opus review.

Acceptance: No external `uses:` line in `.github/workflows/` lacks a 40-character SHA (a grep or the T121 check pattern finds none); each SHA is the commit its former tag resolved to, recorded in the decision; the next runner cycle after the merge completes on fake data, or the report names the revert.
