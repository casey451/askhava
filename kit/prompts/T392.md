## Goal

Proposal N-02 (D-2740, D-3080; `docs/compliance/reconciliation.md` TECH-12, TECH-07, TECH-13 and F-04): the code's privacy rules are proved in `Ci` (T217's `sentinel_db_logs.rs`, T120's local sentinel), but no test looks at what the vendors keep. On the Railway test project, after T136's journeys and T137's real AI run, with every vendor in its sandbox and fake data only (PRIV-019), `tests/sandbox_sentinel/sentinel_trace.py` (standard library only) makes one set of unique fake markers (a fixture name, a 555-01xx phone, an example.com email, a street number and a marker written into a test photo's metadata), runs J1 once with them, then reads each sink through its sandbox API or export and records every marker as present-and-protected, absent or deleted: the app's logs (web, worker, migrate), Sentry events (PRIV-017), Twilio message records after the T276 body-redaction job, Resend's logs, the photo bucket (only sealed objects, PRIV-023), the off-database audit stream, and the AI request inputs as the adapter sent them (only scrubbed text, AI-004); a sink the sandbox gives no way to read is recorded as "not observable" with the reason, never as absent. The allowed places are a table in the script (the vault's ciphertext, a Twilio body before its redaction ran, and so on), each with its requirement. Any marker found outside its allowed place is a High finding: it goes at the top of `docs/for-casey-review.md`, is filed for a plan change and is not fixed here (as T136, D-491), and it blocks Gate C (T145, D-3080) until a later run of this script is clean: the plan change filed for a finding also adds the task that re-runs this script after the fix, and only that run's "Verdict: clean" in `docs/phase2/sentinel-trace.md` unblocks Gate C. `docs/phase2/sentinel-trace.md` records the run (commit, date, each sink's query and result, by marker kind and never the value) and ends with one line, "Verdict: clean" or "Verdict: blocked" with the finding count. The live run needs the test project's sandbox credentials, which Claude never holds, so a step that needs one is a hands-on stop (BUILD_BRIEF.md:548); it never runs in `Ci` and never touches the live project or a live key (BUILD_BRIEF.md:68). `tests/sandbox_sentinel/test_sentinel_trace.py` (TD-PRIV-26) runs in `Ci` offline over fake sink exports.

Acceptance: TD-PRIV-26 passes in `Ci`; `docs/phase2/sentinel-trace.md` records one live run on the Railway test project with every listed sink read or marked not observable, and ends with its verdict line; any High finding is at the top of `docs/for-casey-review.md`.
