# T322: businesses: a backup notice address is checked again at confirmation and against new members, and listed once

Task T322 (build, phase 1, stage 4). Slug: backup-address-recheck.

## Goal

Fourth external audit F45 (D-2209; BIZ-043): a backup notice address must never be a person's main address, but only `request_backup` checks it (`app/businesses/src/backup_address.rs:163`): `confirm_backup` (`:199`) does not check again, so an address that became a member's main address between the request and the confirmation (`add_member`, `app/businesses/src/team.rs:319`) is confirmed as a backup; `add_member` does not look at verified backups; and `notice_addresses` (`backup_address.rs:290`) can list one mailbox twice. (1) `confirm_backup` checks again, in its transaction, that the mailbox is no member's main address and refuses as `request_backup` does; (2) `add_member` with a mailbox that is a verified backup of another person of the business removes that backup (audited) or refuses the new member, whichever BIZ-043 reads as right: decide and log; (3) `notice_addresses` lists each mailbox once. Tests in `tests/security/tests/backup_address_confirm.rs` (TD-BIZ-44); every existing `tests/security/tests/backup_address.rs` case passes unchanged. Update the `businesses` `CLAUDE.md` and `docs/decisions.md`.
