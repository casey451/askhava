## Goal

Plan change D-4425 (Fable's decision under Casey's delegation, Nov 18, 2026: "The rest let fable answer"; SEC-004, PICK-033; D-366, D-477). T683 sends the Confirm link by text in reply to a linked phone's YES or CONFIRM; SEC-004 now accepts the phone-only Confirm that gives at every fee tier, but a session started from such a link lasts 30 minutes, not 30 days. T457 builds `confirm_link_session` (`app/portals/src/action_links.rs`) with `BUSINESS_SESSION_LIFE` (30 days). (1) `app/portals/src/action_links.rs` adds `mint_text_confirm_link(db, target, (now, ends))`, exported through the shared `portals::api`: Confirm only (any other kind is `NotAllowed`), the same member, role and time checks as `mint_action_link`, stored under the binding `action-text:confirm:<object>:<token>` (a prefix no path can produce: the URL supplies only the kind slug, the object and the token, and `ActionKind::from_slug` never returns a kind that yields `action-text`), so the mark sits outside the attacker-controlled part of the binding and `portals.login_link` (`migrations/0123_portals_business_signin.sql:12` to `:21`) needs no new column or migration; the URL is the same `ACTION_ROUTE`, so section 13, the door matrices and every link page are unchanged. `open_action_link`, `action_link_business` and `use_action_link` first refuse, as `ActionLinkError::Ended` and with nothing read or hashed, any token that is not exactly 64 lower-case hex characters (as `business_auth::well_formed` does for sign-in links, `app/portals/src/business_auth.rs:788`; today `target()` in `app/server/src/action_links.rs:147` to `:153` passes the path token raw), so a token with `%3Atext` or anything else appended never reaches a binding; then, for a Confirm token, they try the email binding, then the text one (each a single guarded read or update, so a token is used at most once); `ActionGrant` gains a private `text_started` flag with a `text_started()` reader, true only from a text-binding match. (2) `confirm_link_session` starts the session with the new `TEXT_CONFIRM_SESSION_LIFE` (30 minutes) for a text-started grant and `BUSINESS_SESSION_LIFE` otherwise; a live session of the link's own person is used as it is, never shortened or lengthened; the Verify code step, the shared-inbox rule (`fresh_code_needed`) and the code caps are unchanged. Tests (TD-SEC-80) added to `app/server/tests/action_links_route.rs`, every existing case unchanged. Update the `portals` `CLAUDE.md`, `docs/architecture.md` and `docs/decisions.md`.

Acceptance: TD-SEC-80 passes through the assembled router; an emailed Confirm link behaves exactly as before; every action-link test passes unchanged; no migration.
