# T014: core: derived IDs (HMAC) and the webhook dedupe helper

Task T014 (build, phase 1, stage 2). Slug: core-ids-webhooks.
Branch: `claude/task/T014-core-ids-webhooks`
Model: `claude-opus-5-5`, effort medium. Reviewer: `claude-opus-5-5` (areas: recovery, security).

## Goal

`core` derives card, quote, pick and link IDs by HMAC from what they identify plus a server secret (link tokens with a stored per-record salt, so a link can be re-issued and revoked), and gives every webhook handler one dedupe helper so an event processed once changes nothing the next 99 times (CARD-017, PICK-028, SEC-017, SEC-037, SEC-039). This task also owns the quote-page token hashes and salt in `jobs` with an issue/revoke `api` (SEC-037, D-491); `jobs` is created by T031, so T014 depends on it. `core` cannot hold the dedupe insert for another module's table: it gives the outcome type and the `INSERT … ON CONFLICT DO NOTHING RETURNING` pattern, and each module writes its own literal insert into its own `webhook_event` (D-491).

Requirements (each sentence as it stands in `docs/spec/`):

- **CARD-017** Job card IDs are derived from what they identify plus a server secret, so they can't be guessed and a replay recreates them exactly. (`docs/spec/job-cards.md:21`)

- **SEC-017** Every webhook is processed exactly once by event ID, so the same event arriving 100 times changes nothing after the first. (`docs/spec/security.md:21`)
- **SEC-037** Every link token that reaches a person (quote page, action links, photo links) is HMAC-SHA-256 under the versioned `ID_SECRET` over the record ID plus a per-record 128-bit random salt that is stored with the record and written to the off-database stream, so replay reproduces it, a single link can be re-issued or revoked from database state, and the secret plus the job number alone cannot reproduce a token (D-480). (`docs/spec/security.md:41`)
- **SEC-039** Every inbound webhook is signature-checked before any module sees it, including Resend (Svix, 5-minute tolerance) and Lob; Twilio status callbacks dedupe on (MessageSid, MessageStatus) and voice requests on (CallSid, step); `webhook_event` rows are kept at least as long as the consent log; and a `ReleaseProof` is built only when the Stripe event's livemode matches `APP_ENV`, its account is the configured one, its amount equals the server-computed fee and its metadata names the pick being released (D-480).
