# T377: adapters and stand-in (harness): every text asks Twilio for status callbacks, and the fake sends them only when asked

## Goal

Nov 11 vendor-double review batch 4, F2 and the stand-in half of F5 (D-2761, D-2764; TXT-013, TXT-014, CARD-019, SEC-016, OPS-017). `TwilioSms::send_text` posts only `To`, `From` and `Body` (`app/adapters/src/sms.rs:72`); Twilio posts a message's status only to the `StatusCallback` URL of its create request (or a Messaging Service's callback, which Ask Hava does not use), so in sandbox and live `POST /webhooks/twilio/status` (`STATUS_PATH`, `app/server/src/inbound_text.rs:74`) is never called and `messaging::api::receive_status` never runs: no delivery or failure is recorded, TXT-014's email fallback for a failed text and CARD-019's counts never see a failure, and `ErrorCode` paths are dead. The fake hides it: `status_callback` (`stand_ins/twilio.py:167`, control route `/_stand_in/twilio/status`, `stand_ins/server.py:295`) emits a callback for any message. And the fake's sent log filters by the app's own `MessageKey` (`stand_ins/server.py:121`), which Twilio cannot store. Fix: (1) `TwilioSms` (built in `app/adapters/src/base.rs:106`) carries the status URL, `<ASKHAVA_PUBLIC_BASE_URL>/webhooks/twilio/status` (Twilio signs the full callback URL, and `verify_webhook` checks the public base, path and query, `app/server/src/inbound_text.rs:143`, so the URL sent must be exactly the URL the route rebuilds), and `send_text` adds `StatusCallback` to every create; with no public base URL (dev and CI without webhooks) it sends none, as today. (2) `stand_ins/twilio.py`: `create_message` stores the `StatusCallback` it was given; `status_callback` for a message created without one refuses (the control route answers 409 and records no callback), and with one returns the URL with the params, so a test posts to the URL the app asked for. (3) The fake's Messages list honours Twilio's own filters `To`, `From`, `DateSent`, `DateSent<` and `DateSent>` (dates `YYYY-MM-DD`, UTC); `MessageKey` stays a stand-in-only filter, documented in `stand_ins/server.py` as test-only and used only by `core::test_control`, never by app code (T110 matches without it, D-2764). (4) Tests: `tests/integration/tests/sms_status_callback.rs` sends a text through the adapter against the served stand-in with a public base URL set and asserts the fake recorded `StatusCallback` equal to that URL plus `/webhooks/twilio/status` (fails before the fix), and that the route accepts the callback the fake then gives (signature over that URL); `tests/contract/test_twilio_contract.py` and `tests/contract/test_stand_in_server.py`: no callback for a message created without `StatusCallback`, one aimed at the given URL with it, and the `From` and `DateSent` filters. T129 checks the create parameter against Twilio's test credentials. Update `app/adapters/CLAUDE.md` (shared), `docs/architecture.md` section 7 and `docs/decisions.md`.
