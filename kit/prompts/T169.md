## Goal

Ci pins the Postgres service image by digest, caches the Cargo registry and target with Swatinem/rust-cache pinned by commit SHA (keyed on Cargo.lock and the toolchain, CARGO_INCREMENTAL=0, dev profile debug = line-tables-only), installs cargo-audit, cargo-deny, sqlx-cli and cargo-llvm-cov from pinned prebuilt binaries, runs `sqlx migrate run` then `cargo sqlx prepare --workspace --check -- --all-targets --all-features` so stale offline query data fails, measures branch coverage in its own parallel job on a nightly pinned by date against tests/coverage_floor.json (this task writes the file with the measured total and the 95% floors for app/payments, app/catalog fee rules, app/privacy and app/licensing), fails any PR that lowers a floor, and keeps `cargo build -p askhava-server --locked` as the one boundary build (no per-crate clippy runs) (D-453, D-479, D-481). Acceptance: a PR that lowers coverage by one line in app/core (which has code by now; `app/privacy` is empty until T022) turns Ci red, a deliberately stale .sqlx entry turns Ci red, and a warm-cache run finishes in 15 minutes or less (all shown in the task report). Per the skeleton trial (D-488): `cargo build -p askhava-server --locked`; `sqlx migrate run` then `cargo sqlx prepare --workspace --check -- --all-targets --all-features`; cargo-audit and cargo-deny from their musl release tarballs with pinned SHA-256s; clippy before the build in the same job; and a check that the cache keeps `target/tests/trybuild`, without which a cold pass runs 12 to 15 minutes on 2 vCPU. `Ci` keeps the role step (creating `askhava_app` and `askhava_migrator` before `sqlx migrate run`), and after T012 lands runs `scripts/bootstrap_roles.sql` instead (D-491). `.github/dependabot.yml` watches the `github-actions` and `docker` ecosystems, so a new base-image digest opens a PR that runs the full checks (SEC-021, SEC-045, D-492).

Acceptance: On this branch `Ci` runs fmt, clippy, the build, the tests, cargo-audit and cargo-deny against the pinned Postgres image by digest with a warm cache; `cargo llvm-cov` reports branch coverage for every crate that exists and the floor-compare script fails when a run drops a crate below `tests/coverage_floor.json` (shown locally by lowering a floor above the measured value); the e2e and a11y jobs are wired but pass with no specs yet (`--pass-with-no-tests`); a Playwright job completes under 15 minutes.

## Output discipline

Every turn re-reads all earlier tool output, so a large result is paid for again on each later turn (D-3305). Never cut a failure line to save tokens.

1. Never `cat` or `Read` all of a file over 200 lines (`wc -l`): `grep -n` (context `-C` 3 at most), then `sed -n 'A,Bp'` or Read with offset/limit, at most 120 lines per read, or up to 250 when one read then covers what would take two. Do not re-read a file, or a region of one, you already read unless it changed since: use your earlier output.
2. Build, test and lint output goes to a log, and you print only what decides: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`. Grep each tool's own failure markers: cargo and clippy `^error|FAILED|panicked`, pytest `FAILED|ERROR`, tsc `error TS`, npm `ERR!`, playwright `✘|failed`. When a failure needs more, read the log by line range; if `head` cut failure lines, read the rest.
3. Prehand-in: `bash scripts/prehandin.sh >/tmp/p.log 2>&1; echo exit=$?; tail -n 40 /tmp/p.log` (the smoke test as in Start step 2).
4. Batch every read, grep and `wc -l` you can foresee into one turn (parallel tool calls, or one Bash call joined with `;`): each turn re-reads the whole context (D-3530).
5. `git diff --stat` before any full diff, then diff only the files you need.
6. Keep each output under 4,000 characters (D-3444); when a failure needs more, read the log in further line ranges. No running commentary: one concise report at the end (End routine).
