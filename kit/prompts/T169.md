# T169: CI for the Rust workspace: pinned Postgres service, cache, coverage floors, sqlx prepare check, one boundary build

Task T169 (harness, phase 1, stage 2). Slug: ci-rust-playwright.
Branch: `claude/task/T169-ci-rust-playwright`
Model: `claude-sonnet-5-5`, effort medium. Reviewer: `claude-opus-5-5` (areas: harness, security).

## Goal

Ci pins the Postgres service image by digest, caches the Cargo registry and target with Swatinem/rust-cache pinned by commit SHA (keyed on Cargo.lock and the toolchain, CARGO_INCREMENTAL=0, dev profile debug = line-tables-only), installs cargo-audit, cargo-deny, sqlx-cli and cargo-llvm-cov from pinned prebuilt binaries, runs `sqlx migrate run` then `cargo sqlx prepare --workspace --check -- --all-targets --all-features` so stale offline query data fails, measures branch coverage in its own parallel job on a nightly pinned by date against tests/coverage_floor.json (this task writes the file with the measured total and the 95% floors for app/payments, app/catalog fee rules, app/privacy and app/licensing, FEE-034, PRIV-022, LIC-033), fails any PR that lowers a floor, and keeps `cargo build -p server --locked` as the one boundary build (no per-crate clippy runs) (D-453, D-479, D-481). Acceptance: a PR that lowers coverage by one line in app/privacy turns Ci red, a deliberately stale .sqlx entry turns Ci red, and a warm-cache run finishes in 15 minutes or less (all shown in the task report).
