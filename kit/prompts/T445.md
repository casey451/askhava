## Goal

Runner robustness (D-3563 (e); D-486, D-1126, D-3499, D-3531). (1) On November 13 a one-in-a-hundred property-test miss failed `named-mutants` on nightly-main; a failed `kit/nightly.json` makes `scripts/stage_exit.py` `_nightly_problems` fail every stage, so `passed_stages` (called by `runner/__main__.py` `build`'s `gate`) is empty and no task is claimed until a green nightly, about 2 hours, even after main had moved on and was green; `main_red` already ignores a failed nightly on an older head (`runner/cycle.py` `_nightly_red_on_head`, about line 1264). Make the gate do the same: `.github/workflows/nightly-main.yml`'s `record` step also writes `last_green` (`{"sha", "ran_at"}`): this run's when it is green, else the `last_green` of the `kit/nightly.json` it replaces (absent when there is none), and `failures_since_green`: 0 on a green run, else the replaced file's value plus 1 (1 when the replaced file has none or there is none); every other key and the commit line stay as they are. A new pure `stage_exit.gate_nightly(nightly, main_head, is_ancestor)` returns the record unchanged unless its `conclusion` is `failure`, its `sha` is not `main_head` and is an ancestor of it (`is_ancestor` answers `True`), it carries a `last_green` with a `sha`, and its `failures_since_green` is exactly 1 (the first failure since the last green run; the nightly runs about once a day while `main` moves all day, so almost every failure is on an older head, and a second failure in a row is no longer chance: the gate closes); then it returns `{"conclusion": "success", "sha": <last_green sha>}`, so a stage whose merges that green run contained stays passed and a stage that needs a newer merge waits for a newer green nightly. `gate` passes `gate_nightly(env.read_nightly(), env.main_head(), git_is_ancestor(ROOT))` to `passed_stages`; `evaluate`, `passed_stages`, the command line, `runner/proof.py`'s stage proofs and `main_red` read the raw record as today. A failed nightly on main's current head always closes every stage (and sets `main_red` as today), whatever the counter says, and so does any second or later failure in a row. (2) `runner/state.py` `sync_graph` (about line 99) copies a changed `stage` onto every entry not DONE or SKIPPED, as it does `deps` (D-1126), so a plan change that re-stages a queued task takes effect (the parked D-3498 re-stage of T111 and T121 needs it). (A worker stop opening `MAIN RED:` that the runner confirms is left out: it would add `runner/cycle.py`.) Tests first, in the new `tests/test_runner_stage_robustness.py`: `gate_nightly` returns the last green record for a failure on an older head, the raw failure on main's head, on a SHA that is not an ancestor or when `is_ancestor` answers `None`, and with no `last_green`, and when `failures_since_green` is missing or 2 or more; two consecutive failed nightlies on older heads close every stage (`passed_stages` over `gate_nightly`'s answer is empty for a stage the last green run had passed); a success passes unchanged; `passed_stages` over the substituted record keeps a stage whose merges the last green SHA contains and closes one whose merge it does not; the `record` step's Python (read from the workflow file and run on fake records) keeps `last_green` across a failure and moves it on a success, and counts `failures_since_green` up across failures and back to 0 on a success; `sync_graph` moves a QUEUED entry's stage and leaves a DONE entry's. Every existing test passes unchanged.

Acceptance: `tests/test_runner_stage_robustness.py` holds every listed case and passes; `python3 scripts/stage_exit.py --stage N` and every existing test (including `tests/test_stage_exit.py`, `tests/test_failure_drills.py`, `tests/test_runner_proof.py`) pass unchanged; the nightly `record` step writes `last_green` and `failures_since_green` and nothing else new; only the first failure since the last green run, on an older head, is replaced; a failed nightly on main's current head, or two failed nightlies in a row on older heads, leaves `passed_stages` empty.
