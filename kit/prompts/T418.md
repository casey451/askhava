## Goal

Performance track (D-3292), part 3: lab Core Web Vitals and `Ci`'s performance report, which warns and never fails a build on time. (1) `tests/perf/web_vitals.spec.ts` with its own `tests/perf/playwright.config.ts` (globalSetup reused from `tests/e2e/webserver.ts`, objects made as `tests/e2e/fixtures.ts` makes them, fake data only, BUILD_BRIEF.md:66): in Chromium at a 390x844 viewport with CPU throttled 4x and a slow mobile network through the DevTools protocol, it loads the home page, a ZIP result, the first intake step, the quote page, the Confirm page and the business dashboard, and reads LCP and CLS through `PerformanceObserver` (buffered) and a lab stand-in for INP (the longest Event Timing duration for one click and one key press on the page's main control). Each figure is written to one JSON file labelled "lab, not field" with the goal (LCP 2.5 s, INP 200 ms, CLS 0.1) and the aspirational figure (LCP 1.5 s, INP 150 ms) beside it; the spec asserts only that each figure was measured, never a threshold. (2) `perf/compare.py` reads T417's JSON (from `perf/bench.py --quick`), this JSON and the stored `Ci` baseline `docs/audit/perf-baseline-ci.json`, writes a Markdown table to `$GITHUB_STEP_SUMMARY` (per route p95 and queries per request, each vital, and the change from the baseline), prints a `::warning::` line for each p95 more than 25% above its baseline and each goal missed, and always exits 0; a missing or empty baseline compares nothing and says so. (3) In `.github/workflows/ci.yml`'s E2e job, after the journeys, one step runs the quick benchmark, the vitals spec (`npx playwright test --config tests/perf/playwright.config.ts`; `tests/e2e/playwright.config.ts` would find none of them) and the comparison with `continue-on-error: true` and a 6-minute timeout, reusing the binaries and the Playwright browser already there; no new `uses:`. A second short E2e step (not `continue-on-error`) runs the feature-on test-control tests, which no `Ci` step ran before: `cargo test -p askhava-security --test perf_db_route --test control_router_absent --features askhava-core/test-control`. The two change filters (the Checks job's `npm` rule and the E2e job's `run` rule) also match `perf/` and `tests/perf/`; no other step changes. `tsconfig.json`'s `include` gains `tests/perf/**/*.ts`, since `npx eslint .` type-checks every `.ts` file through its project service and would otherwise fail on the new spec. (4) `tests/perf/test_compare.py` (offline): a p95 25% above baseline gives no warning and 26% gives one; a missed goal gives one; a missing baseline compares nothing and exits 0; a malformed input exits 0 with one warning; the summary holds no value outside the figures (TD-OPS-43). (5) `docs/audit/perf-baseline-ci.json` holds this task's own E2e run's figures when the session can read that run's step summary, otherwise `{"routes": {}, "vitals": {}}` with a note that the first green `main` run sets it. No hard failure on any measure: a deterministic gate (queries per request, payload bytes) waits for a later decision with a baseline-refresh path (D-3292). Update `docs/decisions.md`.

Acceptance: `python3 -m pytest tests/perf/test_compare.py` passes; `npx playwright test --config tests/perf/playwright.config.ts` runs green locally against the test-control build and writes every figure; `npx eslint .` and `npx tsc -p tsconfig.json` pass with `tests/perf/` included; the E2e job's feature-on test step passes and its performance step runs on this task's branch and its failure cannot fail `Ci` (`continue-on-error: true`); `tests/test_ci_workflow.py` and every other workflow test pass unchanged.

## Output discipline

Every turn re-reads all earlier tool output, so a large result is paid for again on each later turn (D-3305). Never cut a failure line to save tokens.

1. Never `cat` or `Read` all of a file over 200 lines (`wc -l`): `grep -n` (context `-C` 3 at most), then `sed -n 'A,Bp'` or Read with offset/limit, at most 120 lines per read, or up to 250 when one read then covers what would take two. Do not re-read a file, or a region of one, you already read unless it changed since: use your earlier output.
2. Build, test and lint output goes to a log, and you print only what decides: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`. Grep each tool's own failure markers: cargo and clippy `^error|FAILED|panicked`, pytest `FAILED|ERROR`, tsc `error TS`, npm `ERR!`, playwright `✘|failed`. When a failure needs more, read the log by line range; if `head` cut failure lines, read the rest.
3. Prehand-in: `bash scripts/prehandin.sh >/tmp/p.log 2>&1; echo exit=$?; tail -n 40 /tmp/p.log` (the smoke test as in Start step 2).
4. Batch every read, grep and `wc -l` you can foresee into one turn (parallel tool calls, or one Bash call joined with `;`): each turn re-reads the whole context (D-3530).
5. `git diff --stat` before any full diff, then diff only the files you need.
6. Keep each output under 4,000 characters (D-3444); when a failure needs more, read the log in further line ranges. No running commentary: one concise report at the end (End routine).
