## Goal

Plan change D-3189 (PRIV-008, PRIV-011, CARD-007, CARD-023, INT-041; D-801, D-1521, D-1274, D-2330, D-3118), the plan fix for BLOCKED T251's reported gap (D-2859). The homeowner's scrubbed job description and the card she approved are stored nowhere: `messaging.inbox` keeps only the provider ID and time (D-801), a sent text's body is cleared (`migrations/0042_messaging_outbox.sql:34`), `intake.intake_answer` holds codes only (`migrations/0053_intake_tables.sql:68`) and `quotes.job_card` holds IDs only (`migrations/0067_quotes_job_card.sql:13`), while the approval event carries only the card digest (`app/intake/src/summary_step.rs:415`), the emergency release only the request (`app/intake/src/service.rs:672`) and the business job page needs the card she approved from its caller (`app/quotes/src/job_page.rs:33`); so T251's card sender, T162's card build (step 12 needs the words of step 1) and T301's quote form have nothing to read. PRIV-008 keeps job text, with contact details removed, for 3 years; this task is that store (owner call under Casey's Nov 11 standing rule, D-3189). Raw inbound bodies are still never stored (D-801) and the outbox still clears a sent body. (1) `migrations/0154_quotes_job_text.sql`: `quotes.job_description`, one row per inbound text whose scrubbed words describe a job (request ID, job ID, a message ID typed `uuid`, the words, the recorded time; unique on message ID and job ID together, since a SPLIT opens a second job from the same text, `app/intake/src/routing.rs:423` to `:443`; the message ID is the `messaging.inbox` row ID for a text and the chat message's own ID for web chat, which has no inbox row, `migrations/0053_intake_tables.sql:54` to `:59`; no foreign key to `messaging.inbox`, so a later inbox purge is never blocked), and `quotes.shown_card`, one row per card shown or released for a job (request ID, job ID and the 32-hex card digest, unique together and checked by pattern; the card text, town, place code and photo IDs exactly as `build_card` made them; the category code and the remaining candidate job type codes; an `emergency` mark, true only for a card stored on the INT-029 emergency path; the recorded time; `sent_at`, null until the card sender marks it); no name, phone, email, street address or contact column; app role SELECT, INSERT and DELETE on both, and UPDATE of `shown_card.sent_at` only. The number is the free 0154: this task depends on the done T157 (0153) and sits just before T287 (0155) in `kit/tasks.json`, so its number rises in the runner's serial order (V9). (2) `app/quotes/src/job_text.rs`, through the shared `quotes::api`: `keep_description(conn, (request, job), message, &ScrubbedText, at)` takes only the scrubber's `ScrubbedText` (`app/privacy/src/scrub.rs:320`, made only by `privacy::api`), so raw words cannot be stored (T277's rule, D-3118), and a repeat for the same message and job stores nothing; `description(conn, job)` gives the job's stored words in time order, or `None`; `keep_card(conn, (request, job), digest, &JobCard, (category, candidates, emergency), at)` stores a card only when `digest` is its text's card digest, which `quotes` computes itself with the workspace `sha2` (added to the shared `app/quotes/Cargo.toml`; `quotes` may not call `intake`, `kit/layers.json`): the first 32 hex digits of the SHA-256 of `JobCard::text`, the value `intake::api::card_digest` gives and approval stores, the test asserting the two agree, refuses any other digest without writing, and stores nothing on a repeat; `stored_card(conn, job, digest)` gives that card (rebuilt through a new crate-private constructor in `app/quotes/src/cards.rs`; `build_card` stays the only public way to make one; `JobCard`'s derived `Debug` (`cards.rs:108`) becomes a hand-written one that hides the text, as `CardParts`' does, `:89` to `:102`), its category and candidates, only while the stored text's digest still equals `digest` (checked on every read, so the card sent is the card approved, CARD-007); `unsent_cards(conn, request)` gives, for each job of the request with no card sent, its newest stored card with its `emergency` mark, oldest job first (the emergency path, which has no approval step and sends only marked cards, T251); `mark_card_sent(conn, job, digest, at)` sets `sent_at` once; `sent_card(conn, job)` gives the card that went out, for the business job page and the quote form (CARD-023).
