From `docs/brains/postgres-operations.md` (cite its tags in the PR; read other sections only when a design choice needs them):

### 2. Principles (lines naming this task's requirements)
**P3. Two roles; the app role never owns anything.** Roles are created outside migrations by the host or a bootstrap script (D-481). The migration role owns every schema and table; the app role (`askhava_app`) used by `web` and `worker` gets only `USAGE` and table privileges. Why: "The right to modify or destroy an object is inherent in being the object's owner, and cannot be granted or revoked in itself" (PostgreSQL privileges docs), so an app role that owned a table could always rewrite it. Serves D-092, threat T6, SEC-029.
**P6. Lock down `public`.** PostgreSQL 15 removed `PUBLIC` create permission on the `public` schema for new databases, but "Upgrading a cluster or restoring a database dump will preserve `public`'s existing permissions" (PG 15 release notes). A bootstrap or first migration should `REVOKE CREATE ON SCHEMA public FROM PUBLIC` anyway; it is idempotent. Serves SEC-029 (one schema per module, D-091).
### 4. Checklist
1. The migration is new, numbered, forward-only, and its first comment names module, purpose and requirement IDs (P1).
2. It touches only its own module's schema; no cross-schema foreign key (Arch 4 rule 3).
3. No blocking DDL on a populated table: `CONCURRENTLY`, `NOT VALID` then `VALIDATE`, expand/contract (P2).
4. Grants and default privileges are present and idempotent; nothing is owned by `askhava_app` (P3, P4).
5. Append-only tables revoke `UPDATE`, `DELETE`, `TRUNCATE` from the app role, and a `SET ROLE` test proves it (P5).
6. Every instant is `timestamptz`; no `BETWEEN` on times; no `serial` (P7, P11).
7. Queue and lookup queries are served by a narrow index (partial, unique dedupe, blind-index hash) (P9, P12).
8. No transaction stays open across a network call; claim transactions are short (P9, P10).
9. Pool size is a setting and fits the P8 budget for the chosen host.
10. Nothing assumes gapless sequences (P11).
11. No plaintext contact value in a column, index, `WHERE`, log or idempotency key (P12, P15, PRIV-002).
12. Host claims used by the change (PITR window, plan, connection cap, encryption, log settings) are marked **verify with host** or cite the checked dashboard (P13, P14).
13. `.sqlx/` regenerated and `cargo sqlx prepare --check` passes after `sqlx migrate run` (Arch 2).
14. `docs/architecture.md` and `docs/decisions.md` updated when a table, owner, timeout or setting changed.

From `docs/brains/rust-production.md` (cite its tags in the PR; read other sections only when a design choice needs them):

### 2. Principles that bind this codebase (lines naming this task's requirements)
**R1. Parse at the edge into types that cannot hold bad values.** Phone numbers, codes, money, IDs and statuses become newtypes or enums the moment they cross a boundary (form, webhook, row, setting); inner code takes the type, never a `String`. Why: "Newtypes provide static distinctions" (C-NEWTYPE); "Arguments convey meaning through types, not `bool` or `Option`" (C-CUSTOM-TYPE); King: a parser returns a more precise type so the check is never repeated or forgotten. Serves SEC-010 (serde typed structs, `deny_unknown_fields`), SEC-033 (never trust browser values), Arch 4 rule 5.
**R3. One `thiserror` enum per crate; HTTP mapping happens once, in `server`.** Lower crates return their own error enum with variants a caller can act on; no crate below `server` knows a status code. Palmieri: pick an enum when "the caller [behaves] differently based on the failure mode"; keep HTTP concerns in the request handler's error type so the logic is reusable from other entry points (here, the worker). thiserror "deliberately does not appear in your public API". No `anyhow` (Arch 2, D-481). Serves SEC-029, Arch 2 (`service.rs`).
**R8. SQL is literal and compile-checked.** Only `query!`/`query_as!`/`query_scalar!` with literal SQL; builds run `SQLX_OFFLINE=true` on the committed `.sqlx/`; `cargo sqlx prepare --check` "exits with a nonzero exit status if the data in `.sqlx` is out of date"; test queries need `-- --all-targets --all-features` after the `--` (sqlx-cli docs). Every query names only its own schema. Serves SEC-029, Arch 4 rule 3, D-481.
**R16. Configuration comes in as data, not from the process environment in tests.** Edition 2024 makes `std::env::set_var` unsafe because it "can be unsound … in a multithreaded program" (edition guide), and `unsafe` is forbidden. `Settings::from_iter` takes pairs; binaries pass `std::env::vars()`, tests pass a map (Arch 5). Serves SEC-002, SEC-036, SEC-029.
### 3. Patterns (lines naming this task's requirements)
Forms: `#[derive(Deserialize)] #[serde(deny_unknown_fields)]` with fields of these types (SEC-010).
### 4. Anti-patterns to refuse (lines naming this task's requirements)
- SQL built with `format!`, string concatenation or `query()` with a non-literal (SEC-029).
