# T616: site: strong per-coding ETags with 304 revalidation, a one-year cache for the hash-pinned fonts, and gzip or Brotli for the stylesheet and the mark

Task T616 (build, phase 1, stage 5). Slug: site-asset-caching.
Branch: `claude/task/T616-site-asset-caching`
Model: `claude-opus-5-5`, effort high. Reviewer: `claude-opus-5-5` (areas: security, accessibility).

## Goal

Plan change D-4252 (Fable's UI and accessibility review of the D-4246 tasks; Casey, Nov 17, 2026: "make it exceptional and meet all of the ADA requirements"). DESIGN_SPEC section 7's speed rule (`docs/design/DESIGN_SPEC.md:129`, WEB-030): site files are served with `public, max-age=3600` and no validator (`app/site/src/routes.rs`, the `asset` handler), and nothing is compressed, so a returning visitor fetches the fonts, the photo and the stylesheet again every hour, at full size; the long cache exists only for `/static/portals/` (`app/server/src/static_files.rs`, `LONG_CACHE`). This task: (1) `app/site/src/assets.rs` computes each listed file's SHA-256 once (the allowed `sha2` crate, `std::sync::LazyLock`). (2) Every answer of the `asset` handler carries a strong `ETag` that differs per content coding (`"<first 16 hex>"` for the plain bytes, `"<first 16 hex>-gzip"` and `"<first 16 hex>-br"` for the compressed ones), and a matching `If-None-Match` gets 304 with no body. (3) The addresses never change: `base.html`'s `<link rel="stylesheet" href="/static/site/site.css">` stays byte for byte as `app/site/src/routes.rs`'s own test asserts, and no template changes. The font files are cached `public, max-age=31536000, immutable`, which is safe only because a font's name is fixed to its bytes: a unit test pins each font file's SHA-256 next to its name, so changing a font's bytes without a new name fails the build (`:129`); `site.css` keeps `public, max-age=3600` with its ETag, unchanged from today (D-3901: the one-hour cache together with the body stylesheet link made A11Y-030's autofocus run pass 96 of 96, and each alone still failed, so the stylesheet is never sent `no-cache`); the photos, the mark and the icons, which may change under the same name (the licensed photo included), are sent `Cache-Control: no-cache`, so a repeat visit costs a 304. (4) Compression for static files only, never a page (a compressed page holding a CSRF token invites a BREACH-style attack): enable tower-http's `compression-gzip` and `compression-br` features in the workspace `Cargo.toml` (tower-http is allowed; the features add transitive crates, so the task's decision entry records each new crate's purpose, license, `cargo deny check` and `cargo audit` result, and if either fails the task stops with a plan gap) and wrap the `asset` service inside `site_routes()` in `app/site/src/routes.rs` in a `CompressionLayer` whose predicate admits `text/css` and `image/svg+xml`, adding `Vary: Accept-Encoding`; the text `nest_service("/static/site"` stays exactly as it is (`tests/a11y/fixtures.ts:41` lists it in `NOT_PAGES`), and the server's mount in `app/server/src/lib.rs` is not touched. (5) `app/site/src/tests/asset_cache.rs` covers: the cache header of a font, of `site.css` (`max-age=3600`) and of the photo, mark and icons (`no-cache`), the font hash pins, a different ETag for each coding, the 304, gzip and Brotli answers decoding to the same bytes for `site.css`, a WebP or woff2 never compressed, and a page never compressed. The first-view weight check (T613) and every existing test pass unchanged. Plan change D-5318 (job 9 pre-flight): the `asset` handler cannot know the coding `CompressionLayer` picks after it, so goal (2) is done in a layer outside the `CompressionLayer`: it computes the ETag suffix from the response's actual `Content-Encoding` (none, `gzip`, `br`) and evaluates `If-None-Match` there; a 304 carries the `ETag`, `Cache-Control` and `Vary: Accept-Encoding` and no body. `asset_cache.rs` also covers a weighted `Accept-Encoding` (`br;q=0.5, gzip;q=1`), `identity`, a `HEAD` request, and a 304 round trip for each coding. The hash pins cover each of the seven `fonts/*.woff2` files (`app/site/src/assets.rs:50` to `:84`).

Acceptance: The site crate's tests pass, `asset_cache.rs` and `routes.rs`'s own stylesheet-link test included; `cargo deny check` and `cargo audit` pass with the new transitive crates recorded in the decision entry; every existing e2e and Ally test passes unchanged, the J1 and J2 keyboard journeys and `tests/e2e/site_polish.spec.ts`'s first-view check included.
