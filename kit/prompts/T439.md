Evidence available at `--after`: the worker and reviewer subagent transcripts (`find_transcripts`, `~/.claude/projects/*/*/subagents/agent-<id>.jsonl`), whose lines hold the model, the assistant text and each tool result's text; git on the runner's checkout; the hand-off file. The reviewer today states no verdict and no head, so: (1) `.github/workflows/backup-runner.yml` step 4 (and 4c, 5b and 3c, which re-run it): the reviewer runs `git rev-parse HEAD` itself on the task branch before reading the diff and ends its report with exactly one line `REVIEW-VERDICT: APPROVED <40-hex head>` or `REVIEW-VERDICT: FINDINGS`; every worker and fix-round worker commits with plain `git commit` (no `-q`, output not filtered or redirected), so Git's `[<branch> <abbrev>]` line reaches its transcript; after any fix commit, including a worker redoing a commit after a (b) hold, the session runs a NEW reviewer that must approve the new head over the new head and passes every reviewer agent id to step 5. (2) New `runner/review_proof.py` (standard library; called from `collect_result` for outcome `submitted`, on the worker's head BEFORE `_hand_in_in_order`'s runner commit and the pre-hand-in gate). Rule (a), approval of the head: when the task has a reviewer (`cycle.reviewer_model`), some reviewer transcript must, counting only `subagents/agent-*.jsonl` paths from `--reviewer-agent`, never one also given by `--worker-agent` and never one holding a `[<branch> <abbrev>]` commit line (a reviewer that committed is no reviewer), in an assistant text block (never a tool result or a quoted prompt), have as its LAST verdict line `REVIEW-VERDICT: APPROVED H` with H the full hand-in head, must hold a tool result containing H (its own `git rev-parse`), and its own models must pass the same rule as `cycle._review_problems` (`runner/cycle.py:500-505`: `reviewer_model(task)` with `known_models`), so a D-2225 model-window or fallback reviewer passes; an approval of any earlier commit, a `FINDINGS` last verdict, or a verdict only in another role's transcript does not count. Since the approval names the exact head, any commit after the last reviewed one fails (a). Rule (b), who committed: for each commit in `git rev-list H ^<main base> ^<branch start>` (branch start: new hand-off field `branch_start`, the prepared branch's existing `base_sha` from `_prepare`, the local task branch tip at the claim; when it is missing, because `prepare_branch` returned `{}` (`runner/github_env.py:1966`, dry run or a git failure), (b) is skipped with a log line naming why (no `remote_at_start` fallback: it would judge the runner's own prepared merge); so the runner's own prepared merge and earlier attempts' commits are not judged), a non-merge commit needs a worker transcript (passed via `--worker-agent`, a `subagents/` path) whose tool result holds Git's commit summary line naming it (`[<branch> <abbrev>]`, abbrev at least 7 hex and a unique prefix of the full SHA); a merge commit passes when its second parent is on `origin/main` and its tree equals `git merge-tree --write-tree` of its parents (a clean, unedited merge adds no authored content), else it needs the same line. Commits made by the main session itself leave no line in any worker transcript, so they fail; this is the closest checkable rule: the evidence proves a worker subagent's tool ran the commit, not who asked for it, and transcripts are files on the runner's disk with the same trust as D-1328's model evidence. (3) Refusal: each rule may hold the hand-in once (`prehandin_holds` style, separate hand-off counters `review_holds_a` and `review_holds_b`, each at most 1), printing `runner: review_missing` with the unapproved or unproven commits, so the session runs a new reviewer (or has a worker redo the commit, after which a fresh reviewer must approve the new head, as the workflow text says) and `--after` again; a rule failing again after its hold fails the attempt as `tests_failed` with a log naming each commit (short SHA, subject) and the rule, nothing pushed, as any failed hand-in. A task without a reviewer skips (a) only. `collect_result`'s new parameter defaults to no check, so existing callers and tests keep their behaviour; `after()` always passes it. Failure drills and tests (new `tests/test_runner_review_proof.py`; no existing test changes, every existing runner test passes): T249's shape (fix commit after the approval) refused; T423's shape (a commit whose summary line is only in the main session's transcript) refused; approval of an earlier SHA refused; `FINDINGS` after an `APPROVED` refused; a verdict quoted in a tool result or in the worker's transcript ignored; a reviewer transcript on a non-reviewer model refused and a model-window or fallback reviewer accepted; a reviewer path also given as `--worker-agent` ignored; a reviewer transcript holding a commit line ignored; an approval without its `rev-parse` tool result refused; a clean main merge accepted and an edited merge without a summary line refused; an ambiguous or 6-hex abbrev refused; the decisions reorder commit and the runner's prepared merge not judged; no `base_sha` skipping (b) with its log line; (a) and (b) each holding once on their own counter, then `tests_failed`; the happy path (worker commit, fix commit, new reviewer approving the head) accepted and `reviewed_sha` set; the workflow step text. Update `docs/architecture.md` section 12 and `docs/decisions.md`.

Acceptance: `--after` refuses a hand-in whose head has no reviewer-model transcript ending in `REVIEW-VERDICT: APPROVED <head>` backed by its own `git rev-parse` result counting only `--reviewer-agent` subagent transcripts that are not worker paths and hold no commit line, on `_review_problems`' model rule; and one with a commit since `base_sha` that no worker transcript shows being made (clean main merges exempt; (b) skipped with a log line when `base_sha` is missing); each rule holds the hand-in once on its own counter, then `tests_failed`; the workflow's reviewer steps state the verdict line; `tests/test_runner_review_proof.py` holds every listed drill and every existing test passes unchanged.
