(1) Webhook outcomes: a layer on the `/webhooks` routes in the new `app/server/src/vendor_alerts.rs`, added in the shared `app/server/src/lib.rs`, writes one `ops` audit row (action `server.webhook_error`, the route's code name as subject kind, a fresh UUID per request as `subject_id`, `app/ops/src/models.rs:105`; no body, no sender) for each request the app answers with a 5xx, and one `server.webhook_ok` row for the first 2xx on each route in each 5-minute window, keyed on the route and the window start (at most 12 rows an hour per route); the layer keeps no in-memory state, so this holds across restarts and across processes.
