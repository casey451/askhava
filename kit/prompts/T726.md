## Goal

Plan change D-4720 (Nov 19, 2026; Fable's decision on Casey's token-efficiency ask). Part A of two (T727 is part B and builds on this): the mechanics of keeping a failed attempt's unpushed work on a `claude/wip/**` ref, with no behaviour change until T727 calls them. Today workers never push (`.github/workflows/backup-runner.yml:518`), the runner pushes the task branch only on the approved path after the review record (`runner/cycle.py:2541` to `:2546`, D-515, D-486), and with no task branch on origin `prepare_branch` starts the next attempt from `main` (`runner/github_env.py:2157` to `:2158`). Follow the merge train's refs as the model (D-4281: `TRAIN_REF`, `train_refs`, `delete_train_ref`, Env methods the cycle reaches through `getattr` and that fail closed). (1) `kit/runner.json` gains `"wip_continue": true` and a `wip_continue_note` citing D-4720; `GitHubEnv.wip_continue()` returns True only when the file says exactly `true` (missing, malformed or anything else is off), as `train_depth()` reads its key; check every test that pins `kit/runner.json` values (`grep -l runner.json tests/`) still passes. (2) In a new module `runner/wip.py` (`//!`-style module docstring per `docs/code-docs.md`): `WIP_REF` = `claude/wip/(T[0-9]+[A-Za-z]?)-a([0-9]+)` and `wip_ref(task_id, attempt)`; `blocked_paths(paths, protected, locked)`, the changed paths under any `kit/tasks.json` `protected_paths` entry (CLAUDE.md rule 7's list and more: `.github/`, `.claude/`, `runner/`, `stand_ins/`, `sources/`, the protected tests and scripts), or among `main`'s `check_plan_lock.locked_paths()` (which covers `scripts/*.py`, `scripts/*.sh`, `.gitattributes`, `kit/runner.json`, `kit/tasks.json` and the rest of the locked blueprint), or named `.gitattributes` anywhere, or `.gitleaks*`; so a retry never starts on an unreviewed `smoke.sh`, `prehandin.sh` or scanner change. `binary_paths(numstat)`: any path `git diff --numstat` reports as binary (`-`), an image included, is refused (a public repository: a photo or binary is never kept on a WIP ref). `scan(...)` returns '' only when all of these pass: no added line in `<main>..<head>` contains `gitleaks:allow`; `gitleaks git` over exactly that log range (`--log-opts`, `--no-banner --redact --exit-code 1`) AND `gitleaks dir` over the head tree; `scan_text` from `pii_scan.py` over each commit's changed files (as of that commit), over the head tree once (`pii_scan.py --root`), and over the commit messages (`git log --format=%B <main>..<head>`). Every scanner is main's copy, never the checkout's (at `--after` the checkout is the worker's branch, and `_pii_patterns` at `github_env.py:195` to `:198` loads `pii_scan.py` from its own path): `pii_scan.py`, `brand.py` and any gitleaks config are written from `git show <main>:<path>` into a temporary directory and run from there, as `prehandin()` writes main's gate (`github_env.py:2491` to `:2494`); trees are read with `git show`/`git ls-tree` or a `git worktree add --detach` checkout, never with `git archive`, which follows the head's `.gitattributes`. The whole scan has one time bound (`WIP_SCAN_SECONDS` = 120, then refuse). Exit 1 or any other non-zero code, a missing `gitleaks` binary, the time bound or any exception is a refusal with a one-line reason, never a pass (fail closed). (3) `GitHubEnv.wip_check(head) -> str` ('' when the head may be pushed, else why): commits ahead of origin's `main` > 0, the head's `.github` tree identical to `main`'s (`git rev-parse <head>:.github` equals `<main>:.github`), `blocked_paths` and `binary_paths` of the diff `<main>...<head>` empty, then `scan`. `GitHubEnv.push_wip(ref, sha) -> bool` pushes `sha` to `refs/heads/<ref>` as a create (never forced, never `claude/task/**`, a name not matching `WIP_REF` refused) ONLY with the job token `RUNNER_CHECKS_TOKEN` (the backup job's `GITHUB_TOKEN`, `contents: write` at `backup-runner.yml:224`): a push made with `GITHUB_TOKEN` starts no workflow run, and that token has no `workflows` permission, so it cannot push a commit that changes `.github/workflows/`. Never `RUNNER_PUSH_TOKEN` (a PAT with Workflows write, D-509, whose pushes do start workflows) and never the Claude App token: route these calls explicitly, ahead of `_long_token_args`, the way the job-token reads are routed, with the token only in the environment's credential helper, never in argv; `push_wip` and `delete_wip_ref` return False before any git call unless `GITHUB_ACTIONS` is `true`, `RUNNER_STARTER` is `actions` and `RUNNER_CHECKS_TOKEN` is non-empty, so a call can never fall through `_env_for` to `_push_env` (`github_env.py:631` to `:634`) and go out with `RUNNER_PUSH_TOKEN`; a push refused (a ruleset, a race: whether the live rulesets let the job token create `claude/wip/**` is unverified) returns False and logs one line, and the next attempt starts fresh. `wip_refs()` lists origin's `claude/wip/*` refs matching `WIP_REF` (name -> sha; None when the listing fails) and `delete_wip_ref(name) -> bool` deletes one matching name with the same job token. (4) `prepare_branch`: when the task dict passed in carries `wip_continue: {"ref", "sha"}` (T727 sets it), origin has no task branch AND origin's tip of that ref equals the recorded sha, the local task branch starts at that head with `main` merged in by `_merge_main` (none when `main` is already in it) and the result adds `continued_from: <ref>` and `base: "wip"`, `base_sha` the branch's start (so review proof rule (b) counts only this attempt's commits, D-3728); otherwise (a task branch on origin, the ref missing, a sha mismatch, a fetch failure, a merge conflict) the usual path runs and the result adds `wip_dropped: <why>`. (5) `runner/__main__.py` `branch_note`: for `continued_from`, tell the worker the branch holds an earlier attempt's unmerged work with the latest `main` merged in, that its failure record is the hand-off's `last_failure`, that it may keep what is sound and discard the rest with new commits or `git revert` (never reset, rebase or force), and the usual `git switch` line; the hand-off also carries `continued_from`. ## Output discipline

Every turn re-reads earlier tool output; large results cost tokens on every later turn (D-3305). Never omit failure lines to save tokens.

1. For a file over 200 lines (`wc -l`), never `cat` or `Read` it whole. Use `grep -n` with at most `-C` 3, then `sed -n 'A,Bp'` or Read with offset/limit: at most 120 lines, or 250 if one read replaces two. Don't re-read unchanged files or regions; use earlier output.
2. Log build, test and lint output; print only decisive lines. Example: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`. Grep each tool's failure markers: cargo/clippy `^error|FAILED|panicked`, pytest `FAILED|ERROR`, tsc `error TS`, npm `ERR!`, playwright `✘|failed`. If needed, read further log line ranges, including failures cut by `head`.
3. Prehand-in: `bash scripts/prehandin.sh >/tmp/p.log 2>&1; echo exit=$?; tail -n 40 /tmp/p.log` (smoke per Start step 2). Then, in its own Bash call with timeout 600000 ms, Ally: `bash scripts/prehandin.sh --ally >/tmp/a.log 2>&1; echo exit=$?; tail -n 30 /tmp/a.log`; no changed page path prints `not needed` immediately, otherwise only failed tests (D-3837).
4. Batch foreseeable reads, greps and `wc -l` into one turn, via parallel calls or one Bash call with `;` (D-3530).
5. Run `git diff --stat` before a full diff; diff only needed files.
6. Limit each output to 4,000 characters (D-3444). Read additional log ranges for failures. No running commentary; report once at end.
7. Exception: `git commit` must be plain, alone in its Bash call: never `-q`, redirect or pipe. Its Git `[<branch> <abbrev>]` transcript line is required by `--after` for every commit (D-3728, D-4796).
