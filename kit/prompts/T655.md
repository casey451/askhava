## Goal

After T654 every recorded ROC list writes each active business's daily `license_check`, and cards stop at the latest Active check's `checked_at + pause_after`. (1) `app/licensing/src/daily_lists.rs` (after T654): a public `roc_standing(conn, business, run_hour)` exported through `licensing::api`, giving the latest check (status, `checked_at`) and the ROC list's failure start (`recorded_failure_start`) when the list is failing and that check is before it; nothing for a business with no check row (no ROC number). (2) New `app/businesses/src/license_standing.rs`, a daily task chain `businesses.license_standing`, queued like the other chains and registered on the worker clock in the shared `app/server/src/lib.rs` (`now` from the worker's clock, as `register_purge_handlers` does), run after the ROC list's run hour and again each LIC-039 retry slot. One clock for both tasks (B3): for an active business whose latest check is `active` and whose list is failing, the pause moment is that check's `checked_at + pause_after` (LIC-008's 72-hour setting, `FailureLimits`), the instant T654 stops its cards, and the warning moment is the earlier of `failure start + warn_after` (24 hours) and the pause moment; `unknown_standing` is applied with `unknown_since` the failure start and its answer capped by those two moments. LIC-008's "stays as it was for up to 72 hours" holds: the latest Active check is never after the failure start, so the pause comes at most 72 hours after the status became unknown, never later. Warned: one `license_unknown` notice email to the owner, once per unknown spell (keyed by the business and the failure start), with its audit row; its words name the pause moment. Paused: the business is paused with reason `license` through the status machine (system actor, audit row in the same transaction), and if no `license_unknown` notice exists for this spell it is queued in that same transaction (B2: never a pause without a warning). Before the resume step, the chain records `check_license` against the latest ROC list for each business paused with reason `license` (a database-only read of the recorded list, never a lookup; review R2), because the daily list run checks only `active` businesses (`businesses::api::active_license_numbers`, `app/businesses/src/api.rs:239`, behind `server`'s `ActiveRoc`, which stays unchanged) and a paused business would otherwise never get a newer check; a business already checked against that list's date is skipped. Then, for each business paused with reason `license` whose latest check is `active` and later than the pause, with no pest report holding it (`pest_reported`), it resumes with `Event::Resume` and no review, unless a complaint hold or an earlier self-pause applies, in `lift_no_cover`'s order (complaints, then self). This is also the exit for `lift_no_cover`'s `license` re-hold (finding 3); `license_reapply.rs` changes only in that function's doc. A known Inactive or Not-listed check is not paused here: T654 stops its ROC cards and Confirm refuses it (PICK-020). Each pause and resume is a system-actor status audit row, which T524's weekly digest counts as automatic pauses and license-unknown counts (OPS-030, D-3882) and which is Casey's count (D-199); this task adds no digest code. (3) `app/businesses/src/notice_emails.rs` (after T490, which also changes it): `license_unknown` joins `NOTICE_KINDS`, to the owner's account address like `license_change`, with its English and Spanish words here (BIZ-018): Laftly could not check the ROC license on the state list since <date>; if it still can't by <the pause moment, Arizona time>, job cards pause until it can; nothing is needed if the license is Active. Tests, fake data only, on PostgreSQL, in `tests/integration/tests/license_standing.rs` (TD-LIC-05): with the list failing from the day after a check, the warning at failure start + 24:00:00 and not at 23:59:59; kept at pause moment minus 1 second; paused at the pause moment, the same instant at which T654's `latest_check_allows_card` turns false (both asserted in one case); a first run only at the pause moment sends one notice and pauses in one transaction; a check old enough that the pause moment precedes failure start + 24 hours warns at once; one email per spell; a `license`-paused business with a fresh list showing its license Active gets a check row written by the run itself (not planted) and resumes with no review; the pause cleared with no review by a later Active lookup too, kept on an Inactive check, a pest report or a complaint hold; `lift_no_cover`'s re-hold cleared the same way; a system-actor status audit row for each pause and resume. Plan change D-4361 (unwired sweep orphan 9 and its second pass, `main` 77a49d7cc; BIZ-026, BIZ-002; D-178, D-254, D-1712, D-2954): a sign-up parked by "That number is old" never resumes, because `resume_on_new_record` (`app/businesses/src/signup.rs:636`) has no caller (D-2954 logged it with no owner). (4) The same `businesses.license_standing` chain (`licensing` may not call `businesses`), after each recorded ROC list, takes each sign-up with `waiting_on_record_since` set, builds its `RecordSeen` from that list's record for the sign-up's license number (contacts and mailing address, read from the recorded list, never a lookup), and calls `resume_on_new_record` with the ID secret, which the chain's registration in the shared `app/server/src/lib.rs` passes in; when it answers true, `RECORD_UPDATED_TEMPLATE` goes once (dedupe per sign-up and list date) to the new record contact the resumed step will use, never to the old number nor to a typed one (D-1712); a contact that only disappeared does not resume.
