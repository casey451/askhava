# T365: calls: the read-back confirm connects only the line that was read back

Task T365 (build, phase 1, stage 4). Slug: readback-confirm-same-line.
Branch: `claude/task/T365-readback-confirm-same-line`
Model: `claude-opus-5-5`, effort high. Reviewer: `claude-opus-5-5` (areas: privacy, security).

## Goal

Nov 10 code review batch 2, calls F3 (D-2639; CALL-005, PRIV-005): the read-back confirm can connect a different line than the one read back: at the second wrong try the read-back names the first name and street of `mine.last()` (`app/calls/src/routing.rs:202`), but the line ID is never stored or signed, and `voice_confirm` (`app/calls/src/pins.rs:347`) re-reads `lines_on` and connects the newest line, so a line opened between the two requests is connected to a caller who confirmed someone else's details. Fix: the read-back line's ID is stored with the call's (CallSid, try) row (or signed into the `confirm=N` URL under the ID secret), and `voice_confirm` connects only that line, and only while it is still open; otherwise it answers as for a wrong PIN. After T349 and T326 (the queued owners of `pins.rs` and `routing.rs`); T311's read-back and T349's draws are kept. Tests in `tests/integration/tests/readback_confirm_line.rs` (TD-CALL-21): a second line opened on the number after the read-back is not connected by the confirm (fails today); a line closed after the read-back is not connected; the plain read-back and confirm still connect the line read back; TD-CALL-13 and TD-CALL-20 pass unchanged. Update the `calls` `CLAUDE.md` and `docs/decisions.md`.
