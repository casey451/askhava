## Goal

Plan change D-6028 (Casey approved; Fable's ruling; after T881, T882, T883, T884 and T886). Since Nov 25 only 48% of 337M tokens went to merged attempts, and three runaway attempts (T734 a2 39.3M / 203 turns, T849 a1 20.3M / 141, a4 13.5M / 119) were 22%. The cap is flat and worker-only, not a pacer multiple: soft at 8M weighted tokens or 80 turns, hard at 12M or 110. A task may carry a higher `budget.attempt_tokens` (and `budget.attempt_turns`) by plan change; `scripts/validate_tasks.py` is protected and not edited, so the runner reads both keys with defaults and ignores a non-integer. (1) New `runner/budget.py` (standard library): the runner measures, never the worker. `--renew` (`runner/__main__.py` `renew`, `:646`; its result stays exactly `renewed`, `renew_refused: ...` or `lost_race`, as `tests/test_runner_live.py:1352`, `:1365`, `:1377` assert) also prints one line `budget: ok|wrap_up|stop <tokens>/<turns>`. It globs this session's subagent transcripts as `find_transcripts` does (`runner/github_env.py:3062`) and sums the weighted usage with `role_reading`'s count (`:3030`) and the assistant turns of the worker and fix-round worker transcripts of this attempt (those started after the claim that are not a reviewer's: the hand-off file keeps the ids each `--renew` saw, and a reviewer's own `--renew` passes `--role reviewer`). Today's `turns: <n>` in the note is self-reported (`.github/workflows/backup-runner.yml:552`). The tests must show that `--renew` sees a transcript that is still being written (lines appended after the first read are counted on the next `--renew`); if the layout makes that impossible, report a `PLAN GAP:`. (2) Session prompt (step 6, `:552`, and the worker and fix-round instructions of steps 3 and 4c) tells every worker, word for word: on `budget: wrap_up`, finish the current step, commit, and start no new scope; on `budget: stop`, commit, write the progress note and return at once. On a stop, the session runs `--after --outcome over_budget --log <the note>`, unless the work was complete and handed in at the cap, which is reviewed and handed in as usual. (3) `runner/cycle.py` `_after_worker` (`:600`): `over_budget` makes the task BLOCKED at once with a reason opening `over budget` (as `record_plan_gap`, `:504`, does for a plan gap; not in `REQUEUABLE`, `:84`) and an outbox item `T###-over-budget` naming the tokens, turns and kept WIP; its head is kept as T881's `blocked` WIP. A new outcome `check_failed` (T886's sibling, for the hand-in suites task after this one) counts exactly as `tests_failed` (`record_failure`), and its head is kept with the existing WIP kind `review` (`WIP_KINDS`, `:113`), so `kit/state_schema.json` is not edited. (4) Continuing: the overseer requeues after Fable's ruling with a fresh budget, and the next attempt resumes the WIP (T882). A second over-budget stop of one task means a split or a plan fix, never a third requeue. Casey's 150-turn / 30M flag stays as the backstop for reviewer and whole-session spend, and no job is cancelled without him: the stop is the worker's own wrap-up. Tests in a new `tests/test_runner_attempt_budget.py`: ok, wrap_up and stop at each threshold for tokens and turns; a task's `budget.attempt_tokens` raises the cap; a reviewer transcript is not counted; a transcript appended to between two `--renew` calls; `over_budget` BLOCKED with its reason, outbox item and WIP; `check_failed` counted as `tests_failed` with a `review` WIP; the workflow sentences. Update `docs/architecture.md` (the runner's budget) and `docs/decisions.md`.

## Output discipline

Every turn re-reads earlier tool output; large results cost tokens on every later turn (D-3305). Never omit failure lines to save tokens.

1. For a file over 200 lines (`wc -l`), never `cat` or `Read` it whole. Use `grep -n` with at most `-C` 3, then `sed -n 'A,Bp'` or Read with offset/limit: at most 120 lines, or 250 if one read replaces two. Don't re-read unchanged files or regions; use earlier output.
2. Log build, test and lint output; print only decisive lines. Example: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`. Grep each tool's failure markers: cargo/clippy `^error|FAILED|panicked`, pytest `FAILED|ERROR`, tsc `error TS`, npm `ERR!`, playwright `✘|failed`. If needed, read further log line ranges, including failures cut by `head`.
3. Prehand-in: `bash scripts/prehandin.sh >/tmp/p.log 2>&1; echo exit=$?; tail -n 40 /tmp/p.log` (smoke per Start step 2). Then, in its own Bash call with timeout 600000 ms, Ally: `bash scripts/prehandin.sh --ally >/tmp/a.log 2>&1; echo exit=$?; tail -n 30 /tmp/a.log`; no changed page path prints `not needed` immediately, otherwise only failed tests (D-3837).
4. Batch foreseeable reads, greps and `wc -l` into one turn, via parallel calls or one Bash call with `;` (D-3530).
5. Run `git diff --stat` before a full diff; diff only needed files.
6. Limit each output to 4,000 characters (D-3444). Read additional log ranges for failures. No running commentary; report once at end.
7. Exception: `git commit` must be plain, alone in its Bash call: never `-q`, redirect or pipe. Its Git `[<branch> <abbrev>]` transcript line is required by `--after` for every commit (D-3728, D-4796).
