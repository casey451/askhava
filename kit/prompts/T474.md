# T474: harness: clearing a red main counts a failed attempt against the blamed task only when FIX-MAIN actually reverted its files

## Goal

Red `main` clearing blames only a real revert (plan change D-3752; docs/governance.md section 5.3 and 5.4; D-1099, D-551, D-584, D-3747). Today `runner/cycle.py` `clear_main_red`, once a green smoke on main's head (and a successful nightly for that head when kit/nightly.json is for it) clears `main_red`, always calls `record_failure` on `main_red.task`, the task `offending_merge` blamed only because it was the latest DONE merge, with the reason "reverted by FIX-MAIN (...)". On November 14 that moved T437 from DONE to BLOCKED (attempts 4), although FIX-MAIN #795 merged only its D-3747 entry (FIX-MAIN's `files` in kit/state.json: `docs/decisions.md` alone) and T437's merge c97c4d0fe stayed on `main`; the red came from T357 (D-3747), and the BLOCKED T437 held its dependents. Change, in `runner/cycle.py` only: (1) A pure helper `fix_main_reverted(red, fix, shared)` (under 50 lines, a docstring citing D-3752) says whether the merged FIX-MAIN changed the offending task's work back. `red` is `main_red`, whose `files` are the offending merge's files (`set_main_red`); `fix` is the FIX-MAIN entry, whose `files` are the merged FIX-MAIN pull request's changed files, recorded when it went DONE. FIX-MAIN merges are squashed, so its revert commit is never in `main`'s history and the squash message proves nothing (#795's message says "Revert T437 merge" though its tree reverted nothing): the merged files are the signal. The offending task's own paths are its `files` not under a shared path (`Config.shared`, a prefix entry such as `.sqlx/` covering what it contains, matched as `runner/verify.py` matches shared paths). Reverted: FIX-MAIN's `files` include one of those own paths, or the offending merge had no own path and FIX-MAIN's `files` include one of its files other than `docs/decisions.md` (append-only; every FIX-MAIN adds an entry). Not reverted: FIX-MAIN went DONE as an empty hand-in (`empty_handin`), or its `files` are known and none of them is such a path. Unknown, kept as today (reverted, the safe side): FIX-MAIN's `files` missing or empty without `empty_handin`. (2) `clear_main_red` stores `outcome` (`reverted` or `fixed_otherwise`) and `fix_files` (FIX-MAIN's merged files) on the record it appends to `main_red_history`, and calls `record_failure` with today's reason text only when the outcome is `reverted`; on `fixed_otherwise` the offending task keeps its status, attempts, `merged_sha` and `files`. Nothing else about a red `main` changes: the smoke and nightly checks, `revert_landed_red`, `blocked_fix_main`, `clear_false_red` and `offending_merge` stay as they are, and the state schema needs no change (`main_red_history` records are not constrained). Tests in the new `tests/test_runner_fix_main_clear.py`, driving `cycle.run_cycle` with a fake env as `tests/test_failure_drills.py` does: a FIX-MAIN that merged only `docs/decisions.md` clears `main` and leaves the DONE offending task DONE with its attempts and `merged_sha`, history outcome `fixed_otherwise` with `fix_files`; one whose files include an own path of the offending task re-queues it with attempts + 1 and the "reverted by FIX-MAIN" reason, outcome `reverted`; one at `MAX_ATTEMPTS` - 1 is BLOCKED only on a real revert; an overlap only in shared paths (`docs/architecture.md`, `docs/decisions.md`, a file under `.sqlx/`) is `fixed_otherwise`; an empty-hand-in FIX-MAIN is `fixed_otherwise`; a FIX-MAIN with no recorded files keeps today's outcome; and unit cases for `fix_main_reverted` itself, including an offending merge with shared paths only. Every existing test stays unchanged and passing, `tests/test_failure_drills.py`'s review-red drill among them (its FIX-MAIN pull request records no files, so it keeps today's outcome). Update the `docs/architecture.md` line on clearing a red `main` (found by grep, never loaded whole) and add your entry to `docs/decisions.md`. Runner logic: an Opus worker, an Opus review, and two review rounds (the second on the head the first round's fixes produce).

Acceptance: `python3 -m pytest tests/test_runner_fix_main_clear.py` passes and the whole runner suite passes, every existing test unchanged; `fix_main_reverted` exists in `runner/cycle.py` under 50 lines; a cleared `main_red_history` record carries `outcome` and `fix_files`; `record_failure` runs on the offending task only for `reverted`; a FIX-MAIN that merged only `docs/decisions.md` leaves a DONE offending task DONE with unchanged attempts; no other runner file changes (D-3752).

## Output discipline

Every turn re-reads earlier tool output; large results cost tokens on every later turn (D-3305). Never omit failure lines to save tokens.

1. For a file over 200 lines (`wc -l`), never `cat` or `Read` it whole. Use `grep -n` with at most `-C` 3, then `sed -n 'A,Bp'` or Read with offset/limit: at most 120 lines, or 250 if one read replaces two. Don't re-read unchanged files or regions; use earlier output.
2. Log build, test and lint output; print only decisive lines. Example: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`. Grep each tool's failure markers: cargo/clippy `^error|FAILED|panicked`, pytest `FAILED|ERROR`, tsc `error TS`, npm `ERR!`, playwright `✘|failed`. If needed, read further log line ranges, including failures cut by `head`.
3. Prehand-in: `bash scripts/prehandin.sh >/tmp/p.log 2>&1; echo exit=$?; tail -n 40 /tmp/p.log` (smoke per Start step 2). Then, in its own Bash call with timeout 600000 ms, Ally: `bash scripts/prehandin.sh --ally >/tmp/a.log 2>&1; echo exit=$?; tail -n 30 /tmp/a.log`; no changed page path prints `not needed` immediately, otherwise only failed tests (D-3837).
4. Batch foreseeable reads, greps and `wc -l` into one turn, via parallel calls or one Bash call with `;` (D-3530).
5. Run `git diff --stat` before a full diff; diff only needed files.
6. Limit each output to 4,000 characters (D-3444). Read additional log ranges for failures. No running commentary; report once at end.
7. Exception: `git commit` must be plain, alone in its Bash call: never `-q`, redirect or pipe. Its Git `[<branch> <abbrev>]` transcript line is required by `--after` for every commit (D-3728, D-4796).
