## Output discipline

Every turn re-reads earlier tool output; large results cost tokens on every later turn (D-3305). Never omit failure lines to save tokens.

1. For a file over 200 lines (`wc -l`), never `cat` or `Read` it whole. Use `grep -n` with at most `-C` 3, then `sed -n 'A,Bp'` or Read with offset/limit: at most 120 lines, or 250 if one read replaces two. Don't re-read unchanged files or regions; use earlier output.
2. Log build, test and lint output; print only decisive lines. Example: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`. ### 2. Principles that bind this codebase (lines naming this task's requirements)
**R1. Parse at the edge into types that cannot hold bad values.** Phone numbers, codes, money, IDs and statuses become newtypes or enums the moment they cross a boundary (form, webhook, row, setting); inner code takes the type, never a `String`. Why: "Newtypes provide static distinctions" (C-NEWTYPE); "Arguments convey meaning through types, not `bool` or `Option`" (C-CUSTOM-TYPE); King: a parser returns a more precise type so the check is never repeated or forgotten. Serves SEC-010 (serde typed structs, `deny_unknown_fields`), SEC-033 (never trust browser values), Arch 4 rule 5.
**R6.
