# T245: payments: narrow the default privileges in schema payments to SELECT, INSERT and prove every money table's grants in a test

Task T245 (build, phase 1, stage 3). Slug: payments-default-privileges.
Branch: `claude/task/T245-payments-default-privileges`
Model: `claude-opus-5-5`, effort medium. Reviewer: `claude-opus-5-5` (areas: money, security).

## Goal

`migrations/0090_payments_ledger.sql` gives the app role SELECT, INSERT, UPDATE and DELETE on every future `payments` table by default, so a money table is append-only only when its own migration remembers to revoke (0090, 0093, 0095, 0096 and 0097 each do it by hand, D-1495). Add `migrations/0098_payments_default_privileges.sql` (first line `-- payments (T245): ...`) running `ALTER DEFAULT PRIVILEGES IN SCHEMA payments REVOKE UPDATE, DELETE ON TABLES FROM askhava_app;` and changing no existing table's grants (`fee_limit` keeps UPDATE and DELETE, `pick_intent`, `charge_attempt` and `pay_timer` keep UPDATE, `payment_method` keeps UPDATE of `removed_at`). Add `tests/integration/tests/payments_grants.rs` (a `sqlx::test` on the shared migrator) asserting, table by table against an explicit allow list, the app role's privileges on every `payments` table, the schema's default ACL from `pg_default_acl`, that no table grants TRUNCATE, REFERENCES or TRIGGER, that a table created after the migrations gets SELECT and INSERT only, and that a `payments` table outside the pinned list (one a later task adds, such as T066's, T067's or T210's) holds a subset of SELECT and INSERT plus what the explicit `GRANT ... TO askhava_app` statements in `migrations/` give it (the test parses those statements, including comma lists of tables, statements over several lines and column-level grants as 0093, 0095 and 0096 write them; it is never edited by a later build task, since only a harness task takes over another task's test), so a forgotten REVOKE or an unlisted extra privilege fails `Ci` (FEE-028, FEE-042; TD-SEC-33). Other schemas keep their defaults; that wider finding is recorded in D-1495, not fixed here.
