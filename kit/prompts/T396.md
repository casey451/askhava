## Goal

Register row IC-95, the hold (D-3081; BIZ-033, CALL-012; D-311, D-288, D-963, D-1695, D-3079). BIZ-033 and CALL-012 say a phone linked by a team member other than the owner works only after the owner approves it, but nothing holds it back: `team::link_phone` (`app/businesses/src/team.rs:439`) and `team::change_phone` (`:503`) put the number's digests in `messaging.sender_directory` at once, so `messaging::api::sender_business` (the inbound text route's lookup) and `calls::routing::party_of` treat the phone as the business; `businesses.staff_phone` (`migrations/0056_businesses_team_members.sql:32`) has no approval column; and two DONE tests, `td_biz_34_a_staff_phone_follows_into_the_directory` in `tests/integration/tests/sender_directory_sync.rs` and the member-link case in `tests/integration/tests/team_members.rs`, assert the opposite of BIZ-033. After T391 (the last earlier owner of `app/businesses/src/reply_link.rs`, which adds the blocked phone on the main phone's LINK reply) and T322 (of `team.rs`). (1) `migrations/0186_businesses_phone_approval.sql` (new): `businesses.staff_phone.approved_at timestamptz` and `number_end char(4)` (the number's last 4 digits, staff data the owner needs to know which phone to approve, as the LINK notice already names them, D-078; never the whole number); every row that exists when it runs gets `approved_at = linked_at` (those phones were linked under the earlier rule, and no row exists outside a test database before Gate C); and `messaging.sender_held` (line ID, index version, digest, business; unique on index version and digest; no number) with the app role's SELECT, INSERT and DELETE and nothing more. A phone's standing is `approved_at IS NOT NULL` alone. (2) `app/messaging/src/sender_held.rs` (new), through `messaging::api`: `sender_hold(db, line)` moves that line's directory digests into `sender_held` (a digest another waiting phone already holds is `SenderTaken`); `sender_release(db, line)` moves them back (a digest another phone now holds in the directory is `SenderTaken` and nothing moves); `sender_drop_held(db, line)`; and `sender_line(db, vault, phone)`, the directory's business and line for a number by the same `sender-dir` digests `sender_business` uses (for T398). Nothing logs a digest. (3) `app/businesses/src/team.rs`: every link and number change stores `number_end`. The owner's link (the main phone always) stores `approved_at = now` and works at once. A link by any other member (`team_member.is_owner` false, even one holding both roles) stores `approved_at` NULL and, after `SenderLink::link`, calls `sender_hold` in the same transaction (`SenderTaken` is `PhoneTaken`), so the phone is in no directory lookup until approved. `change_phone` first calls `sender_drop_held` (so no old number stays held), then relinks: by the owner it sets `approved_at = now` and the new number works; by any other member it sets `approved_at` NULL and holds the new number, whether the phone was waiting, approved or linked by the owner, so a member can never put a working number in place by changing one. `unlink_phone` and `remove_member` also call `sender_drop_held`. `app/businesses/src/reply_link.rs`: the phone the main phone's LINK reply adds stores `approved_at = now` (the main phone's reply is the owner's act, CALL-012) and its `number_end` if it inserts the row itself; TD-CALL-24 passes unchanged. (4) `app/businesses/src/phone_approval.rs` (new), through `businesses::api`: `approve_phone(conn, by, line, now)` and `reject_phone(conn, by, line, now)`, owner only (any other member, a "Confirm and billing" member holding both roles included, is `NotAllowed`), each only on a waiting phone of the owner's own business (another business's line, an unknown line and a declined one are `UnknownPhone`; an approved one is a new `TeamError::NotWaiting`), in one transaction with one audit row of IDs only (`businesses.phone_approved`, `businesses.phone_rejected`). Approve sets `approved_at` and calls `sender_release` (`SenderTaken` is `PhoneTaken`: nothing changes and the phone stays waiting); reject deletes the staff phone row and its held digests, so it can never work, and a later link of the same number is a new waiting phone. Also `phone_standing(conn, line) -> Option<bool>` (whether `approved_at` is set; `None` for no such phone) for T398, and `waiting_phones(conn, business)` (line, linking member, `number_end`, linked time) for T397's page. The SEC-038 step-up is the route's (T397, T399). (5) Tests in `tests/integration/tests/phone_approval.rs` (TD-BIZ-52) through `businesses::api` and `messaging::api::sender_business`, fake numbers only (555-01xx); the call and text routes are T398's. (6) The two DONE tests change only where BIZ-033 decides (TD-BIZ-34 as D-3081 rewords it): each phone a member links is first asserted absent from `sender_business`, then the owner approves it with `approve_phone`; in `td_biz_34_a_staff_phone_follows_into_the_directory` the member's `change_phone` leaves the new number absent too (and the old one absent) until the owner approves again, after which the existing assertions follow; every other input, expected value and assertion is unchanged. Update the `businesses` and `messaging` `CLAUDE.md` files, one line in `docs/architecture.md` section 10 found by grep (never the section whole), and `docs/decisions.md`.
