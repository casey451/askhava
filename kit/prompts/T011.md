## Goal

`core` gives every crate validated settings (the app refuses to start on a missing value, a live key in a test environment, a test key in live, or a vendor account identifier off that environment's allow-list), an injectable clock with Arizona time and the 8 a.m. to 8 p.m. business clock, and logging that carries request IDs and route templates only, with Sentry's default PII off and contact fields held as `Redacted<String>` (JOB-007, PRIV-016, PRIV-017, PRIV-028, SEC-001 to SEC-003, SEC-036). Each log event is one line of JSON with `message` and `level` at the top level (`flatten_event(true)`) (PRIV-016, D-492). `app/core/src/settings.rs` is a shared path: this task creates it, and each later task adds its own `ASKHAVA_*` keys (SEC-040's client-IP header, `ID_SECRET`, the masked pool, the vendor base URLs, the webhook secrets, the vault keys) to the typed settings, so the parser still refuses unknown keys (D-493).

### 2. Principles that bind this codebase (lines naming this task's requirements)
**R5. Log an error once, where it is handled.** "Errors should be logged when they are handled"; a function that propagates with `?` does not log (Palmieri). **R6. Personal data and secrets cannot print.** Contact values live in `core::Redacted<T>`, whose `Debug` and `Display` print a marker; secrets are `secrecy::SecretString`, which redacts `Debug`, zeroizes on drop and needs `ExposeSecret` to read (secrecy docs).
