## Goal

Plan change D-4180 (Casey, Nov 17: "We can run more lanes if you are able"; the lanes stay at 7 and the idle time is attacked instead; evidence in D-4180): stop throwing away a valid smoke verdict when `main` moves mid-smoke. Today `settle_background_smoke` and `_background_smoke` (`runner/github_env.py:1370`-`1393`) stop this job's background smoke of an older head A as soon as `main` is at a new head, and the start routine smokes the new head from scratch (13 to 22 minutes each), so frequent merges keep lanes in `smoke_pending`. New rule, with no proof rule changed: when this job's own smoke is for an ancestor A of the head and A would be a valid D-3058/D-3156 ancestry-reuse base for the head once green, the smoke is kept, its verdict is recorded as a real run on A, and the head then claims through the unchanged ancestry reuse. (1) Qualifying, pure, in `runner/state.py` beside `ancestry_smoke` and sharing its per-commit loop rather than copying it: `ancestry_pending(state, chain, sha, merged, limit, proven) -> bool` is True only when `main` is not red, `limit` >= 1, `sha` is `chain[d]` for some 1 <= d <= `limit` (`chain` is `main_first_parents(head, limit + 1)`, starting at the head), `sha` passes `_clean_commit` (no `main_red_history` entry, no `smoke_env_problems` strike, no red or timed-out run), and every commit `chain[0:d]`, the head included, has no real run of its own, passes `_clean_commit` and is a DONE task's squash merge (`done_merges`) or `proven` returns exactly True for it (`green_twin_tree`, asked only after the cheaper tests): exactly the tests `ancestry_smoke` applies, so it would take `sha` as its base the moment a fresh real green is recorded on it. The cycle adds `_head_doubted` on every commit `chain[0:d+1]`, as `_ancestry_reuse` does; any error is False. (2) Env, `runner/github_env.py`: a reader of this job's own smoke whatever its SHA (the `job` check of `_pre_result` kept; the SHA check dropped only in this reader) giving its SHA, whether its background process still runs and its finished result (pre-session or background) if any; and a wait on a kept smoke of A that is `_await_background(A, pid)` itself (it sets `smoke_pending` while A runs, uses a result as `_use_pre_smoke` does, and is `_background_lost(A)` when A ended with no result, `runner/github_env.py:1423`-`1428`). `settle_background_smoke` and `_background_smoke` stay byte-for-byte unchanged: the cycle keeps A by returning before it calls them, so a lost-race retry in the same call (`runner/cycle.py:1713`) judges A afresh and can never reach the stop at `github_env.py:1390` through a keep flag left over from the first pass; nothing else in `smoke_main` changes. (3) Cycle, `runner/cycle.py` `_start_smoke`, before `settle_background_smoke`: when this job's own smoke is for A other than the head, there is no own result for the head, the head has neither a same-head reuse nor an ancestry reuse standing now (if it has one the ancestor smoke is stopped as today, `tests/test_runner_smoke_reuse.py:594`) and A qualifies under (1): (a) still running: wait as in (2); still running then is `smoke_pending` with nothing recorded, nothing claimed and no second smoke started (one smoke per smoke tree and database, `github_env.py:1386`-`1388`); (b) finished green: append a real run on A to `smoke_runs` (`sha` A, `ok` true, `at` the result's own `at`, written when it finished, `github_env.py:1525`, when it parses, else now; `seconds` when known; `why` "start routine (<source>, ancestor of <head[:12]>)", no `reused`, no `base`; no new key, so `kit/state_schema.json` is unchanged; a result already recorded on A with that `at` is not recorded again, which keeps the 6-hour window honest and spares the 20-row `smoke_runs` cap, `runner/cycle.py:1158`), then the ancestry reuse for the head runs as today and, when it stands, is recorded and the claim proceeds in the same call; when it does not stand (something became doubted meanwhile) the head is smoked as today; (c) finished red: recorded on A (`ok` false, `at` as in (b), so A is doubted and no ancestry reuse passes through it), nothing claimed, and the head is smoked in the same call exactly as today (`_smoke`); a red head then sets `main` red or makes a D-498 strike through the unchanged `_next_step` code (`runner/cycle.py:1723`-`1732`). A red on A never sets `main` red by itself: later commits may have fixed it, and `offending_merge` would blame the latest DONE merge, so FIX-MAIN would revert or charge the wrong task; (d) finished with no result, or timed out: recorded as a timed-out run on A (D-1178; `at` as in (b)), `smoke_timeout`, no strike, nothing claimed; the next call smokes the head. A finished own pre-session result for a qualifying A (`main` moved during the job's warm-up) is collected the same way. When A does not qualify (an unreadable chain, A not on the first-parent chain or more than `smoke_ancestry_reuse` commits back, an in-between commit neither a DONE merge nor proven, anything doubted, `main` red, `smoke_ancestry_reuse` 0, an env without the new readers such as the drills' FakeEnv), behaviour is exactly today's: stop it and smoke the head. Invariants: nothing is claimed while a smoke of the head, or a kept ancestor smoke, still runs; nothing is claimed on a head no real green proves; a red result on a qualifying A is never dropped: it is recorded and the head is smoked before any claim (a result on an A that does not qualify is ignored as today, `github_env.py:448`); one smoke per smoke tree and database; `SMOKE_REUSE_MAX_AGE` (6 h), kit/runner.json `smoke_ancestry_reuse` (5) and every D-2560, D-3058 and D-3156 refusal are unchanged; `clear_main_red` still needs the runner's own fresh green on the head; FIX-MAIN claims still skip the smoke; `BUILD_BRIEF.md:240` is unchanged.
