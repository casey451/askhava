# T167: Stand-ins served over HTTP at the vendors' URL shapes, so the Rust adapters use one client for stand-in, sandbox and live

Task T167 (harness, phase 1, stage 1). Slug: stand-ins-http.

## Goal

One standard-library HTTP server exposes every stand-in at its vendor's paths (Twilio Messages and Verify, Stripe, Resend, Lob, the stand-in AI) with the same signatures, errors and idempotency behavior; the existing contract tests also run over HTTP (D-453). The Twilio stand-in records each message's derived key and offers a sent-log query and a voice-session stand-in, so OPS-017's 'nothing sent twice' check and the recovery drills can run against it (D-491). The stand-in AI is fixed to match AI-010: this task writes the committed schema `schemas/intake_reading.json` (at the repository root, outside any crate, since `app/ai/Cargo.toml` does not exist until T024, D-493) (the AI-010 fields with a 0-to-1 confidence for trade and for job type and nothing else), and `stand_ins/ai.py` drops its `rental` field, returns the two confidences and validates its output against that schema (AI-022, D-492). This task also writes the provider's Advanced Opt-Out settings as `stand_ins/provider_optout.json` (outside any crate, D-493): START and UNSTOP the only re-subscribe words (no YES), exactly CON-030's twelve opt-out words (stop, stopall, unsubscribe, cancel, end, revoke, optout, quit, parar, alto, cancelar and baja) and the CON-009 reply in English and Spanish; the fake Twilio reads that file for its keyword matching and its reply per keyword (D-492, D-493). It also accepts inbound picture texts (NumMedia and media URLs) and serves a Media DELETE endpoint that removes the stored media, so the picture-text cases can run (D-492). `stand_ins/ai.py` also gains fault modes selected by a request header (a 500, a 504, a 529, a 429 with and without `retry-after`, a `refusal` stop and a `max_tokens` stop) and planted outputs selected the same way (a carrier-restricted word, a URL, 600 characters), so TD-AI-14 and TD-AI-10 run against the stand-in (D-493).

Acceptance: Every contract test passes over HTTP (`python3 -m pytest tests/contract -q -p no:cacheprovider`), and `tests/contract/test_stand_in_server.py` has no skip path (no `pytest.skip`, `skipif`, `importorskip`, `xfail` or `SkipTest`): the runner records stage 1's exit proof only from a green nightly run in which that file ran with no way to skip (D-551).
