## Goal

Nov 11 code review batch 3, F6 (b) (D-2705; BIZ-050, LIC-043, D-393, D-2593, D-2596): `reapply_license` (`app/businesses/src/capability.rs:559`) has no production caller, so a class removed from a business's record keeps its job types and cards, and no `businesses.license_change` email is ever queued. Fix: (1) `app/licensing/src/class_changes.rs`: a read, through `licensing::api`, of each license number whose class set differs between a recorded ROC list and the one recorded before it, with the old and new classes; a number missing from the newer list is not a change (a truncated list must not strip and pause everyone; a lapsed license is CARD-015's and the lookup's, not this task's); (2) `app/businesses/src/license_reapply.rs`: a daily `businesses.license_reapply` task, registered in the shared worker and queued once a day after the list time (tomorrow queued first), that, applies each recorded list it has not yet applied, oldest first, each against the list before it (so a class removed on a day the task did not run is never lost), marking a list applied without a new table (a done task keyed per list date, or an audit row); for each list it maps each changed license number to its businesses and calls `reapply_license` with the old and new classes and the list date, in bounded batches; a re-run for the same list does nothing new (D-2596's key). It does not depend on who records the lists (T371). Tests in `tests/integration/tests/license_reapply_daily.rs` (TD-BIZ-48), lists recorded with `import_roc_list`: an R-37 business whose class goes loses its plumbing job types, is paused for `no_covered_job_type` when nothing is left, and one `businesses.license_change` task is queued; a class added is offered, never ticked, and a switched-off category is not offered (T368); a business on an unchanged record is untouched; a re-run queues nothing; two lists recorded on days the task did not run are applied in order, so a class removed on the first and not restored is removed; a license number missing from the newer list leaves its businesses untouched; a business paused for `no_covered_job_type` that saves a capability tick its license covers is resumed in that transaction, audited, and one with no covered tick stays paused. The email itself is T329's. Resume (D-2596 (1), decided here; D-2711 as narrowed by D-2730): (a) `businesses::api::save_job_types` (in `capability.rs`) stores a business's job-type ticks later, after sign-up: in one transaction it locks the business row, rebuilds the offer from T374's `businesses::api::holding` and the stored category switch (T368), and stores only ticks that offer allows (never the caller's offer); `save_capability` keeps its signature for the done tests, but its lift check also uses the rebuilt offer; (b) a `no_covered_job_type` pause lifts only when, in that same transaction, the rebuilt offer and the stored ticks share a licensed job type, and every other pause rule is re-run first: the complaint count (`app/businesses/src/complaints.rs`, the rule `record_complaint` applies over `PAUSE_WINDOW_DAYS`), a pest license reported wrong (LIC-047, `licensing.business_license.paused_at`) and any license or insurance standing rule the code has (CARD-015's latest check); if one holds, the business stays paused with that rule's reason (audited), never active; (c) when the license pause replaced the owner's own pause (`replace_self_pause`, D-969, D-970: its audit row is the `pause_reason` field change, not a status change), the lift returns the business to paused by itself, never active; (d) otherwise it becomes active, audited. A later list that covers a job type only offers it (BIZ-050), so the owner's tick is the resume; the license-change email says so. TD-BIZ-48 gains a case each: a covered tick lifts the pause; a business that crossed the complaint limit while paused stays paused for complaints; a pest business reported wrong stays paused; a business self-paused before the license pause returns to paused by itself; a tick posted outside the rebuilt offer is refused and lifts nothing. Update the `businesses` and `licensing` `CLAUDE.md` files and `docs/decisions.md`.
