## Goal

Plan change D-4748 (Fable's decision (5a); CARD-023, FEE-013, FEE-036, PRIV-011; D-3189, D-3719, D-1939). CARD-023 (`docs/spec/job-cards.md:27`) puts every intake answer on the business job page, but nothing outside `intake` can read them: `intake.intake_answer` is keyed by request (`migrations/0053_intake_tables.sql:64`) and `models::latest_answer` is crate-private (`app/intake/src/models.rs:530`), so the Quote link's page passes none (`app/server/src/action_links.rs:296`). And a job opened by an ALSO reply (INT-032, `begin_job`, `app/intake/src/conversation.rs:131`) lives only in a `job.%` link row that `close_request` drops (`models.rs:718`), so `intake::api::jobs_of_contact` (`app/intake/src/api.rs:182`, which reads only `intake.conversation.job_id`) misses it: a repeat customer picked on such a job is charged the full fee instead of $0 at Confirm (FEE-013, FEE-036; D-3719's known limit) and her portal delete misses its photos (PRIV-011). This task: (1) `migrations/0213_intake_request_job.sql` (after T653's 0212 and before T729's 0215 in the runner's serial order, which is why this task waits for T653; re-check the next free number at claim time) adds `intake.request_job (conversation_id, job_id, opened_at)`, one row per job a request opened, never dropped by a close, backfilled from `conversation.job_id` and the live `job.%` links; `begin_job` and `set_first_job` (`models.rs:800`) write it in their transaction; the retention purge must remove it with its request (check `app/privacy/src/purge.rs`'s intake tables; a row that would outlive its request is a plan gap to report). (2) `jobs_of_contact` reads it (still one homeowner's, `DISTINCT`), so FEE-013's same-customer check and PRIV-011's delete see ALSO-reply jobs and closed requests. (3) The new `app/intake/src/job_answers.rs`, re-exported through the shared `intake::api`: `job_answers(conn, job) -> Result<Vec<JobAnswer>, IntakeError>`, the latest answer to each question of the request that opened `job` (through `request_job`), as question ID and stored code or scrubbed value in question-bank order (`docs/catalog/question_bank.yaml`); the contact questions (her name, street address and any on-site contact, INT-041) are never returned (PRIV-001, PICK-022); a job with no request reads none. Tests in the new `tests/integration/tests/job_answers_reader.rs`, PostgreSQL, fake data only: the first job and an ALSO-reply job each read their own request's answers before and after the request closes; no contact answer appears; `jobs_of_contact` returns both jobs after the close; a repeat customer's ALSO-reply job is found by the Confirm route's same-customer check (`same_customer_jobs`, D-3719). Every existing intake, conversation and close test passes unchanged. Opus worker, Opus money and privacy review, two review rounds. Update the `intake` notes, `docs/architecture.md` and `docs/decisions.md`.

Acceptance: `tests/integration/tests/job_answers_reader.rs` passes against PostgreSQL; every existing intake test passes unchanged; an ALSO-reply job is in `jobs_of_contact` after its request closes; no contact answer is returned by `job_answers`.

2. Build, test and lint output goes to a log, and you print only what decides: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`.
