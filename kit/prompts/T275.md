# T275: adapters and stand-ins: local write-once storage that a racing writer cannot alter, object delete and list, and the Twilio message-body delete

## Goal

(1) B05 (second external audit, D-1841): `write_once` (`app/adapters/src/storage.rs:72`) writes every attempt to the same deterministic `<name>.<key>.part` with `std::fs::write`, which truncates and rewrites one shared file, then hard-links it into place, so a racing retry can empty or change an object already published. Each attempt now creates its own temporary file exclusively (`create_new`, a random suffix from the OS source), writes it fully, `sync_all`s and closes it, and publishes with `hard_link` (which never replaces an existing object); it compares bytes with an existing object only once that object's publication is complete, and removes only its own temporary file. Directory-fsync crash durability is decided and recorded in the decision entry. (2) D-1803's missing capabilities, additive so no existing fake changes (the `RefundStripe` pattern, D-1753): `StorageDelete: StorageAdapter` with `delete_object(name)` (an absent object is success) and `list_objects(prefix)`, implemented for `LocalStorage`; `SmsBodyDelete: SmsAdapter` with `delete_message_body(sid)` for Twilio's documented message delete (or body redaction, whichever the vendor documents for removing a body; the choice recorded), implemented for `TwilioSms` in `app/adapters/src/sms.rs`. The Twilio stand-in (`stand_ins/twilio.py`, its route in `stand_ins/server.py`) answers that call and afterwards returns no body for the message, and a repeat answers as Twilio does. The real B2 store (T134) and the Twilio sandbox (T129, T131) implement or check the same traits later. The `photos/` prefix uses its own key with read, list and delete; PRIV-029's write-only, prefix-scoped token, versioning and object lock stay in force for the audit-stream and export (backup) prefixes (D-1841). Tests: the competing-writer cases in `app/adapters/src/tests/storage.rs`; the stand-in in `tests/contract/test_twilio_body_delete.py`. Update the `adapters` `CLAUDE.md`, `docs/architecture.md` section 7 and `docs/decisions.md`.

Acceptance: TD-SEC-39 and TD-PRIV-19 pass; every existing storage, photo and Twilio stand-in contract case still passes, and no existing `StorageAdapter` or `SmsAdapter` fake changes.
