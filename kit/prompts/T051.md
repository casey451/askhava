# T051: portals: sessions, __Host- cookies, CSRF, security headers, no third-party hosts

Task T051 (build, phase 1, stage 2). Slug: portals-base-security.

## Goal

`portals` sets the shared web security: `__Host-` cookies that are Secure, HttpOnly and SameSite=Lax and rotate on login, CSRF tokens on every form (pre-session ones bound to their own cookie) plus `Sec-Fetch-Site` and `Origin` checks, Askama autoescaping always on, the SEC-012 headers and `no-store` on contact or photo pages, no third-party script or font host, realm proof types for vault reads, and security events logged with route and actor reference only (SEC-009, SEC-011 to SEC-013, SEC-034, SEC-042, SEC-046, SEC-048). It also creates the plain shared layout `app/site/templates/base.html` and `app/portals/askama.toml` (whose `dirs` point portal templates at that layout), so every portal page from here on extends it; T101 restyles it later (D-491). The realm capability types of SEC-046 are T022's; this task uses them once T022 has landed (D-491). TD-SEC-21's cross-site POST runs against a portals test route here; the quote page, web chat and action-link routes add their own cases (T052, T103, T148) (D-491).
