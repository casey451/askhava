## Goal

Plan change D-4720 (Nov 19, 2026; Fable's decision on Casey's token-efficiency ask). Part B of two, on T726's mechanics (`runner/wip.py`, `GitHubEnv.wip_check` with its scans of each commit, the head tree and the messages, `push_wip`, `wip_refs`, `delete_wip_ref`, `wip_continue`, `prepare_branch`'s `wip_continue`, `continued_from` and `wip_dropped`): the policy. From `claude/kit-state` history, about 120 failed attempts that pushed nothing cost about 520 to 580M worker tokens, and the attempt after such a failure used about 7 to 10M against about 1.1M after a pushed (check_failed) one; the expected saving is 350 to 550M. (1) A new session outcome `review_failed`: the attempt's reviewer, after step 4's findings round, still ends with `REVIEW-VERDICT: FINDINGS`; the session passes `--outcome review_failed --log <the findings>`. In `runner/cycle.py` it counts exactly as `tests_failed` (attempts, BLOCKED at the cap, `last_failure`, strikes), the only difference being (2). (2) WIP push: when an attempt ends `review_failed` with reviewer evidence, or `plan_gap`, with commits ahead of `main`, origin has no task branch (the hand-off's prepared `remote_sha` empty), `env.wip_continue()` is true, the attempt did not itself continue a WIP and the task's entry has no `wip_used`, and the log names neither test weakening nor protected-path tampering (a fixed, tested case-insensitive pattern list, e.g. `weaken`, `assertion removed`, `test removed`, `protected path`, `tamper`), the runner asks `env.wip_check(head)`; on '' it records `wip: {ref, sha, attempt, kind ("review" or "plan_gap"), at}` on the task through `update_state` FIRST and only then calls `env.push_wip(ref, sha)` (record before push, as D-515 orders the review record before the branch push), ref `claude/wip/<id>-a<attempt>`; a refusal or a failed push records `wip_skipped: <why>` in the attempt's history row and changes nothing else. Every other ending (timeout or a lease that ran out, `tests_failed`, prehandin or smoke red, review missing, path-check failure, usage limit, api error) pushes nothing, as today. An Env without these methods does nothing new. (3) Continue: at claim, before `_prepare_branch`, the task dict gets `wip_continue: {ref, sha}` only when the entry's `wip` exists, `wip_used` is unset, the flag is on and, for `kind` `plan_gap`, the entry's latest `requeues` item has `plan_fix` and an `at` later than the record's `at` (a requeue after `--plan-fix`, D-677); the claim then sets `wip_used: true`. The attempt's history row gets `continued_from` (from `prepared`) or `wip_dropped`; either way `wip` is dropped from the entry once the attempt is prepared, so a continued attempt that fails again starts the next one fresh. The reviewer is not told the branch continues earlier work or that a head was rejected, and reviews the whole diff against `main` as usual. (4) Cleanup: `wip` is dropped when the task is DONE or SKIPPED; each cycle, beside the stale-train pass (`cycle.py:635` to `:654`), a sweep lists `env.wip_refs()` FIRST, then re-reads the state (`env.read_state()`, fresh, after the listing) and deletes only refs that are not exactly some task's recorded `wip` (ref and sha) in that fresh state; because a lane records `wip` before it pushes, a ref pushed by any of the seven lanes after the listing is never deleted, and one pushed before it is already recorded, so DONE, SKIPPED, fresh-started, removed tasks and stray names are all cleared; a failed delete is retried on the next pass; it runs whether or not the flag is on. A WIP ref never gets a pull request, auto-merge or `_adopt_orphan_pr` (`cycle.py:1814`): those read only `claude/task/**` branches and recorded PRs. (5) Tokens: the history row's existing `usage` with `continued_from` lets the overseer compare continued and fresh retries; after 10 continued retries the overseer records the comparison in `docs/decisions.md` and sets `wip_continue` false if continuing is not clearly cheaper (D-4720). (6) Ownership check first: in `backup-runner.yml`'s session prompt (step 3, where the worker is briefed), tell the worker that its first step, before any edit, is to list every file it expects to create or change, compare the list with the prompt's owned and shared paths, and if any falls outside, stop and report `PLAN GAP: outside ownership: <path>, <path>` naming the exact paths; `runner/cycle.py` records those paths as `paths` in the task's `plan_gap` record. Step 4 adds `review_failed` as above and says never to pass the branch note or the last failure to a reviewer; step 3b passes a `continued_from` branch note word for word to the worker. (7) `kit/state_schema.json` describes the optional per-task `wip`, `wip_used` and `plan_gap.paths`, and history's `continued_from`, `wip_dropped`, `wip_skipped`; absent keys mean no WIP, and unknown keys are kept (D-121), so a state written by either runner reads under the other and no merge hold is needed; `python3 scripts/check_state.py` passes on states with and without them. (8) `tests/test_runner_wip.py`: protected-path refusal, scan hit and scanner error each push nothing and record `wip_skipped`; the record is written before the push; a timeout, a `tests_failed`, a smoke-red and a path-check ending push nothing; a sha mismatch or missing ref starts fresh and drops `wip`; once only (a continued attempt that fails again pushes nothing and the next starts fresh); a `plan_gap` WIP continues only on a requeue after `--plan-fix`, not after a plain `--requeue`; a log naming test weakening pushes nothing; no pull request, auto-merge or `_adopt_orphan_pr` adoption from a WIP ref; the sweep deletes the ref after DONE, after SKIPPED and for a stray name, and keeps a recorded one, including one recorded by another lane between the listing and the state read (the race case); `review_failed` counts like `tests_failed`; flag off: no push, no `wip_continue`, the sweep still runs; PLAN GAP paths land in `plan_gap.paths`.

## Output discipline

Every turn re-reads earlier tool output; large results cost tokens on every later turn (D-3305). Never omit failure lines to save tokens.

1. For a file over 200 lines (`wc -l`), never `cat` or `Read` it whole. Use `grep -n` with at most `-C` 3, then `sed -n 'A,Bp'` or Read with offset/limit: at most 120 lines, or 250 if one read replaces two. Don't re-read unchanged files or regions; use earlier output.
2. Log build, test and lint output; print only decisive lines. Example: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`. Grep each tool's failure markers: cargo/clippy `^error|FAILED|panicked`, pytest `FAILED|ERROR`, tsc `error TS`, npm `ERR!`, playwright `✘|failed`. If needed, read further log line ranges, including failures cut by `head`.
3. Prehand-in: `bash scripts/prehandin.sh >/tmp/p.log 2>&1; echo exit=$?; tail -n 40 /tmp/p.log` (smoke per Start step 2). Then, in its own Bash call with timeout 600000 ms, Ally: `bash scripts/prehandin.sh --ally >/tmp/a.log 2>&1; echo exit=$?; tail -n 30 /tmp/a.log`; no changed page path prints `not needed` immediately, otherwise only failed tests (D-3837).
4. Batch foreseeable reads, greps and `wc -l` into one turn, via parallel calls or one Bash call with `;` (D-3530).
5. Run `git diff --stat` before a full diff; diff only needed files.
6. Limit each output to 4,000 characters (D-3444). Read additional log ranges for failures. No running commentary; report once at end.
7. Exception: `git commit` must be plain, alone in its Bash call: never `-q`, redirect or pipe. Its Git `[<branch> <abbrev>]` transcript line is required by `--after` for every commit (D-3728, D-4796).
