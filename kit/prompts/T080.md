# T080: calls: relay-friendly bridging, identity call, code call

Task T080 (build, phase 1, stage 4). Slug: calls-voice.
Branch: `claude/task/T080-calls-voice`

## Goal

The masked line works with 711 relay (spoken prompts, long PIN waits); the homeowner's code call happens only on her tap, opens "This is Ask Hava LLC" with the main number as callback, speaks slowly and repeats the code; no business can text a homeowner on Ask Hava's number; no announcement plays on a bridged call; and the safety voice call stays off unless every CALL-022 condition is met (`intake` and `messaging` cannot call `calls`, so intake enqueues a `core.task` safety-call event (this task adds the enqueue to `app/intake/src/emergency.rs`, T039's, D-492) that a `calls` handler in `voice.rs` places, D-491) (CALL-013 to CALL-016, CALL-019, CALL-022, CALL-023); a safety voice call answered by a person acknowledges its critical alert through `ops::api` and lists it in the digest, and `calls::api` offers the bridge that rings Casey's phone and connects him to the homeowner with the Ask Hava number shown (OPS-028); the owner-portal button that starts it is T108's (D-491). The PIN prompt's 10-second wait with one repeat (CALL-013) and the calling-side-only PIN prompt and read-back (CALL-023) are changed in `app/calls/src/routing.rs` (T077's, extended here) (D-493).
