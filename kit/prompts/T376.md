# T376: ai and stand-in (harness): the intake schema sent to Claude uses only keywords the API supports, and the stand-in refuses the others

## Goal

Nov 11 vendor-double review batch 4, F1 (D-2760; AI-010, AI-021, AI-022, AI-023). The committed intake schema `schemas/intake_reading.json` is sent whole as `output_config.format` (`app/ai/src/service.rs:206`, through `intake_schema`, `app/ai/src/schemas.rs:26`) and gives `trade_confidence` and `job_type_confidence` `minimum` 0 and `maximum` 1 (`schemas/intake_reading.json:21`, `:23`). Claude's structured-outputs page lists `minimum` and `maximum` among the constraints the API does not support (https://platform.claude.com/docs/en/build-with-claude/structured-outputs), and `docs/brains/ai-intake.md:26` records a 400, which `:64` turns into no retry, an alert and the AI-off path: every real reading would fail. The stand-in never looks at the request's schema (`messages`, `stand_ins/ai.py:147`), so no test can see it. Fix: (1) `schemas/intake_reading.json`: drop `minimum` and `maximum` from the two confidences (each gets a `description` saying 0 to 1); the 0-to-1 check stays in code (`parse_reading`'s `in_range`, `app/ai/src/schemas.rs:168`). (2) `intake_schema` sends the file without its top-level `$schema` and `$id` (metadata the request does not need; harmless whichever way the API treats them); `app/ai/src/tests/schemas.rs` keeps its equality test against the file minus those two keys and adds: a reading with a confidence of 1.5 or -0.1 is discarded. (3) `stand_ins/ai.py`: a request whose `output_config.format.schema` uses, anywhere, a keyword `docs/brains/ai-intake.md:26` lists as unsupported (`minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `minLength`, `maxLength`, `maxItems`, or `minItems` other than 0 or 1), or an object without `additionalProperties: false`, gets the API's 400 `invalid_request_error`; the stand-in's own output check keeps the 0-to-1 range for the two confidences in code, since the schema no longer holds it. (4) `tests/contract/test_stand_in_ai_contract.py`: a request with a `minimum` in its schema is refused (fails before the stand-in change); a request with the committed schema, as `intake_schema` sends it, is accepted (fails before the schema change); and a scan of `schemas/intake_reading.json` finds none of those keywords. The real API's answer is checked in T137 (D-2760). Update `docs/decisions.md`.
