Meaning rule, closed: a rewritten sentence that changes who acts, what is allowed, required or promised (may / must / will / never / only), an amount, a time, a condition or an exception is a finding; word choice alone is a note. A reworded clause that passes them all and the meaning rule, where a reviewer would have chosen other words, is a note under 'Scan list notes (not findings)', not a finding; forbidden framing actually present in a rewritten file (a List B hit of any scan above) still blocks, as does a rewrite that moves a number, a required phrase or the D-3879 retention bracket. Passing the closed scans is the wording bar; an off-list phrasing that no file in scope contains is a note under 'Scan list notes (not findings)', not a finding (D-4038).

## Output discipline

Every turn re-reads earlier tool output; large results cost tokens on every later turn (D-3305). Never omit failure lines to save tokens.

1. For a file over 200 lines (`wc -l`), never `cat` or `Read` it whole. Use `grep -n` with at most `-C` 3, then `sed -n 'A,Bp'` or Read with offset/limit: at most 120 lines, or 250 if one read replaces two. Don't re-read unchanged files or regions; use earlier output.
2. Log build, test and lint output; print only decisive lines. Example: `cargo test -p <crate> >/tmp/t.log 2>&1; echo exit=$?; grep -nE 'FAILED|panicked|^error|test result' /tmp/t.log | head -n 60; tail -n 15 /tmp/t.log`. Grep each tool's failure markers: cargo/clippy `^error|FAILED|panicked`, pytest `FAILED|ERROR`, tsc `error TS`, npm `ERR!`, playwright `✘|failed`. 3. Prehand-in: `bash scripts/prehandin.sh >/tmp/p.log 2>&1; echo exit=$?; tail -n 40 /tmp/p.log` (smoke per Start step 2).
