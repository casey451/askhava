## Goal

A local drill restores the nightly encrypted export into a fresh database, replays, and shows no duplicate text, email or charge and a ledger that reconciles (OPS-013, OPS-018, OPS-019). Plan change D-3889 (Fable's pre-claim check, Nov 16, 2026): (1) T206 adds no table and no migration: T110's replay flags unmatched charges and the nightly reconcile refunds them (FEE-032); `service.rs` runs the restore, then the replay, retries the replay while Stripe is unreachable (OPS-018, never guessing), lists each unrebuildable job in T110's `recovery.replay_item` with one `ops::api::raise_alert`, and records the drill in T110's `recovery.restore_drill` (OPS-019). (2) `server replay`, a subcommand in the shared `app/server/src/main.rs` beside `migrate` and `bootstrap-owner` (the `migrate` and `bootstrap-owner` branches), calls `recovery::api`'s drill entry; T117's runbook and T139's Railway drill name it. (3) Coverage does not count `askhava-recovery-tests` (the `--exclude askhava-recovery-tests` line in `.github/workflows/ci.yml`, `EXCLUDED` in `scripts/coverage_floor.py`), so the wait-and-retry and OPS-019 branches have unit tests in `app/recovery/src/tests/service.rs`. (4) The test decrypts the export with a fake `age` identity (`age` is allowed, `kit/allowed_crates.txt:41`; a dev-dependency in the shared `tests/recovery/Cargo.toml`), and `pg_dump` and `pg_restore` come from T109's in-crate path helper, reused, not copied. Budget 600 lines (TD-OPS-04 has eight cases). Never write a script with `std::fs::write` and exec it from the same test process: a concurrent fork can hold the write descriptor and the exec fails with "Text file busy" (D-4864). Create any fake binary through a waited-on child process (`/bin/sh` with the arguments `-c`, `printf %s "$2" > "$1" && chmod 755 "$1"`, `sh`, the path, the text), as `write_script` in `app/recovery/src/backup.rs` `mod tests` does; that helper is private to its file, so write your own few-line copy in your own test file. Plan change D-4932 (Fable's pre-claim checks, Nov 20, 2026): the app host cannot read an export back (PRIV-029's write-only key) and holds no private key (PRIV-024, D-4835), so the drill never reads storage and never takes an `age` identity. `recovery::api`'s drill entry and `server replay` take the path of an already-decrypted `pg_dump -Fc` file that the operator supplies and the URL of the fresh database; fetching the object and `age -d` are the operator's steps, with the key kept off the host, and T117's runbook names them. `service.rs` gains no decrypt code. In `local_drill.rs` the test takes the encrypted bytes T109's export wrote to the storage stand-in, decrypts them with its fake identity (the `age` dev-dependency), and hands the plain file to the drill, which shows that the export restores (TD-OPS-04). `tests/recovery/Cargo.toml` gets its first `[dependencies]` from T648 (D-4835); this task adds only `age` and repeats none of T648's.
