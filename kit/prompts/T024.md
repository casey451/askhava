# T024: ai: strict schemas, no tools, instruction versions, stand-in by configuration

Task T024 (build, phase 1, stage 2). Slug: ai-adapter.
Branch: `claude/task/T024-ai-adapter`
Model: `claude-opus-5-5`, effort medium. Reviewer: `claude-opus-5-5` (areas: privacy, security).

## Goal

`ai` sends only `ScrubbedText` through the adapter with versioned instructions and no tools, accepts only schema-validated fixed fields (discarding anything else), and screens every AI-written text for restricted content, URLs and length before use, falling back to the fixed template (AI-005, AI-006, AI-010, AI-015, AI-021). The adapter calls only `/v1/messages` and `/v1/messages/count_tokens` (AI-001); the Rust types and the request's `output_config` come from `schemas/intake_reading.json` (T167's, D-493) and a test fails on any difference (AI-022); each call has a 20-second timeout and retries only on the AI-023 codes, any other failure returning the AI-off result and the key and spend errors raising an owner alert (AI-023); the model ID is a setting stored with each call record beside the instruction version and request ID (AI-024); the scrubbed text goes inside one fixed XML tag with the tag name escaped inside it (AI-025); enums are trimmed, lowercased and checked against the catalog (AI-005) (D-492). The carrier-restricted word list of CARD-010 lives in `catalog` (`app/catalog/src/restricted_words.rs`, this task's, exported through `catalog::api`, a shared path), so `ai` screens with it here and `quotes` (T185) reads the same list; `ai/src/lib.rs` is a shared path this task creates (D-492).
