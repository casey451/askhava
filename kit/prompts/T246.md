## Goal

No homeowner can pick on the quote page today: `portals::pick_flow::final_pick` re-renders the review step with `not_open` and stores nothing, the code step sends no code (D-1248, D-1264, D-1280), and `server` builds `pick_flow_routes(pool, clock)` with no Verify client, vault or secret. Build the page pick end to end (D-1516). (1) One pick rule: add `JobStatus::takes_pick` (Quotes ready, Awaiting confirm) to the shared `app/jobs/src/status.rs`, its doc naming PICK-012, PICK-032 and PICK-045; the quote page's Pick buttons (`app/portals/src/quote_page.rs`, today `takes_quote_edits`), `pick_flow::takes_pick` (today `takes_quotes`) and the final Pick all call it, and a unit test pins `picks`' text stage (Ready or Waiting) equal to it for all twelve statuses; `takes_quote_edits` stays for business quote edits. Open and No quotes yet drop out because T247's first-quote move puts a quoted job in Quotes ready. (2) The pick core in `picks` (`app/picks/src/service.rs`): pull the end-move-insert part of the private `pick_quote` into one function both channels use, and add `picks::api::page_pick(tx, job, quote, actor, at)` answering picked, same (the waiting pick is that quote) or taken (the job no longer `takes_pick`, a homeowner pause (CON-029), or an unavailable quote); a re-pick while one waits ends it as `replaced` with its withdrawal event (PICK-032) and does not restart the Confirm window; `insert_pick` with no inbox already writes channel `page`, so `app/picks/src/models.rs` (T063's and T069's) is not changed. Nothing irreversible happens before Confirm: no fee, free win or release. (3) The code without `portals` seeing the number: add `Purpose::PickCode` and the grant `(Reader::Picks, Purpose::PickCode, [Phone], "vault_read.picks.pick_code")` to `GRANTS` in `app/privacy/src/models.rs` and `privacy::api::read_for_pick_code` (audited and counted like every read; refusing a connection inside a transaction, as `read_for_release` does), as `docs/architecture.md` section 8 now records; `picks` adds `send_page_code` and `check_page_code`, which take the homeowner's contact ID, read the phone with it and call the existing `send_code` and `check_code` (caps, cooldown, PICK-055); the phone is never returned, logged or put in an error. Add `("read_for_pick_code", &["picks"])` to `READERS` in `tests/security/tests/vault_readers.rs` (T022's test, taken over here). `intake::api` gains the job's newest request's conversation, contact and language, built on `job_texts::homeowner_of` (`app/intake/src/job_texts.rs`).
