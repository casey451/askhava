## Goal

Casey, November 8, 2026 (D-2038): "the longest we should have for a reply is 3 to 5 seconds, and that should be as limited as possible." AI-023 changes: every AI call a homeowner's reply waits on has one budget, 3 seconds by default, the setting `ASKHAVA_AI_TIMEOUT_SECONDS` allowed from 1 to 5 and never more, with its retries and backoff inside it, so a retry happens only while time is left; when the budget runs out the call ends, is recorded with its outcome (`timed_out`), and the caller gets the AI-off result at once, so intake asks the fixed question-bank question (INT-021, INT-039). In `app/ai/src/models.rs` the default becomes 3 and the range 1 to 5 (an out-of-range value is an error naming the key); `send` (`app/ai/src/service.rs:183`) already wraps the retries in the timeout, so it needs no change. The only AI call in the code today is the intake reading, which a homeowner's reply waits on; a business quote read (PICK-006) may later get its own longer setting from the task that builds it, not here. TD-AI-14's expected values change with the default (D-2038), so this task updates T024's `app/ai/src/tests/adapter_calls.rs` to the new row, keeping every case it tests, and adds TD-AI-22 in `app/ai/src/tests/reply_budget.rs`. Update `app/ai/CLAUDE.md` (shared) where it names the setting.

Acceptance: TD-AI-14 (with its new values) and TD-AI-22 pass; `AiConfig::from_pairs([])` gives a 3-second timeout; `ASKHAVA_AI_TIMEOUT_SECONDS=6` is refused; every other existing `ai` test passes unchanged.

- **AI-023** Each AI call has one time budget, and its retries and backoff run inside it: a call a homeowner's reply waits on (every intake step's call, on web chat or in reply to an inbound text: the reading, a reword, the follow-up, the card, the project file, a photo screen and a concept prompt) has 3 seconds by default, a setting allowed from 1 to 5 seconds and never more; a call no homeowner reply waits on (reading a business's quote, PICK-006) may use its own setting, 20 seconds by default, 1 to 120.
