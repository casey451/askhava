# T286: server: every request has a whole-request time limit, answered 503 with the security headers

Task T286 (build, phase 1, stage 4). Slug: request-timeout.
Branch: `claude/task/T286-request-timeout`
Model: `claude-opus-5-5`, effort medium. Reviewer: `claude-opus-5-5` (areas: security, money).

## Goal

`tower-http`'s `timeout` feature is enabled (`Cargo.toml:38`) but `build_router` (`app/server/src/lib.rs:75`) applies no time limit, so a request whose body trickles in, or a handler that hangs, holds its connection and task without end (third external audit, D-1870; threat model D13). (1) `app/server/src/request_timeout.rs`: the limit is a setting, `ASKHAVA_REQUEST_TIMEOUT_SECS`, added to the typed settings in the shared `app/core/src/settings.rs` (D-493) and read from them at start-up (default 60 seconds, allowed 10 to 300; any other value, or one that is not a whole number, stops start-up with a message naming the key, never the value). 60 seconds is longer than the longest chain of bounded vendor calls one handler makes today (a Confirm press makes at most three Stripe calls at the adapters' 15-second limit, `app/adapters/src/base.rs:211`), so the limit stops only a stalled request, never a slow vendor call the adapters already bound. (2) `build_router` takes the limit and applies it to every route, inside the `security_headers` layer, so a timed-out request is answered `503 Service Unavailable` with `Retry-After: 5`, the SEC-012 headers and `Cache-Control: no-store`, and its handler future is dropped (every write a handler makes is in a transaction or keyed, so a dropped request commits nothing half-done; a webhook sender retries a 503, SEC-017). A Confirm press dropped in the middle of a Stripe call leaves its attempt `sent`; it is never retried until Stripe, asked directly, says it failed (FEE-037's sent-then-fetch path in `confirm_and_pay` and `repeat_press`), so the limit can never cause a second charge. The worker has no HTTP routes and is unchanged. (3) `app/server/tests/request_timeout.rs`, with `tokio::time::pause`: a route that never answers is cut at the limit with 503, `Retry-After`, the security headers and the request ID; a route that answers just inside it is untouched; a body that stops arriving is cut the same way; each bad setting value stops start-up. Update the `server` `CLAUDE.md`, `docs/architecture.md` section 2 (the layer order) and `docs/decisions.md`.

Acceptance: TD-SEC-42 passes; every existing `app/server/tests/` case passes unchanged.
