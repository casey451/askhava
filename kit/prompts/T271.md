# T271: server and calls: the dialed leg's status callbacks are served, so each call's start and finish are logged once

Task T271 (build, phase 1, stage 4). Slug: call-status-route.

## Goal

No route serves the dialed leg's status callbacks, so nothing in production calls `calls::api::log_finished_call` or T282's `call_start_confirmed`, and no call log exists for the refund rules, the TXT-026 reminders, the no-show, or the business portal's call log (D-1814's caller "not wired yet"; second external audit B06, D-1836). `app/server/src/call_status.rs`: the status-callback route that T282's `dial_twiml` names, checked with `X-Twilio-Signature` (SEC-016) and merged in the shared `app/server/src/lib.rs`: an `initiated` event records the dialed leg against the start T262's webhook stored, by `ParentCallSid`, through `call_start_confirmed` (creating the start at the callback's time when the webhook's write was lost); a final event logs the call through `finished_call` and `log_finished_call`, its start joined by the dialed SID, the party taken from the line as T262's voice route resolves it; each is applied once per CallSid and event (SEC-017), a repeated or out-of-order callback changing nothing; after a business call is logged the route enqueues T281's `picks.unreachable_step` check for the line's pick (deduped per call). A forged signature gets 403 and changes nothing; no phone number is stored or logged (PRIV-016), and the request log shows the route template only. Tests in `app/server/tests/call_status.rs` through the real route with signed fake Twilio requests. Update `docs/architecture.md` section 10, the `server` and `calls` `CLAUDE.md` files and `docs/decisions.md`.

Acceptance: TD-CALL-16 passes against PostgreSQL through the served route; every TD-CALL-04 and TD-CALL-14 case still passes.
