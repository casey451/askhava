## Goal

Plan change D-4052 (Casey's outside code audit, batch B, Nov 17, 2026; each item re-checked on `main` 67f601a before planning): (B14) `confirm_quote_at` (`app/quotes/src/intake.rs:694` to `:711`) checks only `takes_quotes`, while `submit_quote` refuses a quote after its card's 24 hours (`window_open`, `:46`, used at `:646`). Decision (D-4052): PICK-001's window closes the read-back confirm too, because the every-window-ended check (TXT-042, JOB-025) may already have told her "all quotes are in" or closed the job; so `confirm_quote_at` reads the card's `sent_at` (`models::card_sent_at`) and returns `Guarded::MovedOn` when the window has closed, storing nothing; a business with no card on the job stays `Guarded::MovedOn`, never an error (`tests/integration/tests/quote_window.rs:165` to `:169` expects `Ok(Guarded::MovedOn)`; D-4173); no production route calls it yet (the read-back screen is later), so no page copy changes. (TXT-017, found while checking B21) The quote-count update text is built (`quotes::api::notice`, `notice_for`, `update_text`, `app/quotes/src/notify.rs:99`, `:123`, `:166`) but nothing sends it: no production caller of `update_text` or `notice_for` exists, and D-1198/D-1199 left the sender unowned. This task adds the trigger and the read; T583 adds the sender. In the new `app/quotes/src/count_update.rs`: `COUNT_UPDATE_KIND` (`quotes.count_update`) and a queue call, run in the same transaction as a quote that becomes shown (in `submit_quote` when not AI-read, and in `confirm_quote_at` when applied) on a job that was already Quotes ready (the first quote's text stays `jobs::api::first_quote`'s), one `core.task` per newly shown quote (dedupe key: job and business), payload the job ID only. Newly shown means its business was not in `shown_quotes` (`intake.rs:732`) before this write, so a re-confirm or a form edit of an already shown quote queues nothing, and the job's status read under its row lock is Quotes ready (`AwaitingConfirm` also takes quotes, `app/jobs/src/status.rs:185` to `:189`, and gets no update: TXT-042, no update follows a pick). `quotes.count_update` has no handler until T583, so D-4064 lists it in `tests/task_kinds_deferred.json` with owner T583, as D-3880 did for `calls.owner_alert_call`. In the new `app/messaging/src/quote_text_sent.rs`, through the shared `messaging::api`: the last `first_quote` or `quote_update` outbox row to a recipient about a job (`subject_ids` holds the job) and when it was delivered (its Twilio `delivered` event's time, else its `sent_at`, and for a row still queued or sending its queue time, so an unsent text is never invisible), as D-1190 says the sender reads it. A `blocked`, `failed` or `expired` row (`migrations/0182_messaging_outbox_not_before.sql:23`) never reached her and is never sent, so the read skips it and returns the last row before it (TXT-017 measures the 3 hours from a delivery); an `unknown` row (the carrier may have taken it, never resent) counts as sent at its `sent_at`, as T580 maps it to Sent. (D-4064, the Opus pre-claim check) TD-PICK-02's confirm at `tests/integration/tests/quote_window.rs:157` calls `confirm_quote`, which uses the wall clock (`intake.rs:683`), on a card sent at `2026-11-03T08:00-07:00` (`:145` to `:146`), so after this change it would return `MovedOn`; that one call becomes `confirm_quote_at(&mut db, (id, a), at("03T09:30:00"))`, inside the card's window, and its `Applied` assertion is kept: a fixed clock in place of the wall clock, forced by PICK-001's window (D-4052), not a weakening; taking over T046's test makes this a harness task with an Opus review (`scripts/validate_tasks.py:596` to `:613`, `BUILD_BRIEF.md:70`). The other confirms (`quote_window.rs:167`, `:293`, `tests/integration/tests/pick_bound_business.rs:161`, `:184`, `tests/integration/tests/first_quote_move.rs:308`, `:315`) are inside their windows or moved on already and are not changed. Tests in the new `tests/integration/tests/quote_count_event.rs`, fake data only: a confirm after the 24 hours is `MovedOn` and shows nothing, one inside them is applied; a second shown quote queues one count event, the first queues none, and a re-confirm or form edit of a shown quote queues none; the read gives the delivery time, the send time without one, the queue time for an unsent row, skips a failed row for the one before it, and gives none for another job. Existing quote tests pass unchanged, except the one `quote_window.rs` call above.

Acceptance: `tests/integration/tests/quote_count_event.rs` passes against PostgreSQL with every listed case, the late-confirm case failing on `main` before the change; the quotes crate tests and `tests/integration/tests/quote_texts.rs` pass unchanged, and `quote_window.rs` passes with only line 157's call moved to `confirm_quote_at` inside the window and its import (`quote_window.rs:16`) adjusted; `tests/integration/tests/task_registry.rs` (TD-OPS-36) passes with `quotes.count_update` deferred to T583.
