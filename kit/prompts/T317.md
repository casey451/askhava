## Goal

Fourth external audit F12 and F17 (D-2206; SEC-014, TXT-031; D-1951, D-2041 (2), D-1310): the inbound text route opens requests with no SEC-014 limit (D-1951 named the next owner of `app/server/src/inbound_text.rs` to call `intake::api::admit_new_request`; D-2041 (2) left it because `admit_new_request` counts on its own pool outside the delivery's transaction, so a 500 and resend counts twice, and the route has no open-request read), and the LIST reply names no business (`Webhooks::names` is built empty, `app/server/src/lib.rs:277`). This is a harness task only because it adopts six done tests that build `Webhooks` by name (D-2206, D-3083). After T279: (1) `app/intake/src/limits.rs`: `admit_new_request` takes `impl Acquire<'_, Database = Postgres>` and counts on the connection it acquires (the delivery's transaction, so a rolled-back delivery counts nothing), through a connection-taking variant of `core`'s counter added in `app/core/src/rate_limit.rs` and exported through `core::api` (`hit`, `:201`, takes only `&PgPool`; it and its callers stay as they are); `&PgPool` still meets the bound, so T089's `tests/security/tests/rate_limits.rs` (`:67`, `:77`, `:87`, `:107` and the concurrent pool clones at `:182`) compiles and passes unchanged (D-3083); the count stays in the delivery's transaction, never a separate statement, because a separate count survives a rolled-back delivery and Twilio's resend counts again (D-2041 (2), D-2206), but `intake.requests_all` is one row per hour shared by every new request, so its lock must not serialize inbound texts: the count runs only for a homeowner with no open request, as the delivery's last step before `receive_reply`, with the global bucket last (`admit`'s narrowest-first order), and nothing between the count and the commit waits on the network (carrier, AI or any HTTP call), so the row is held only for the delivery's remaining database statements (D-3083); keyed by the sender's vault contact (blind index; no IP, the request comes from Twilio); `intake::api` gains the read of whether the sender has an open request. Every caller may then pass its own connection: the web-chat path calls it too (with her contact and the client IP, in the transaction that opens the request), which T103 builds and T299 wires, both after this task (D-2206). (2) `inbound_text.rs` calls it before `receive_reply` only for a homeowner sender with no open request; a refused text keeps its inbox row (so Twilio's resend is a repeat), opens nothing, is answered by nothing and raises at most one Low alert per sender per window, with no body or phone; HELP, STOP and START are handled before the limit as today. (3) `Webhooks::names` is removed: the LIST reply reads the quoted businesses' names at the time of the text through T316's `businesses::api::public_names` (D-1310's no-name fallback stays).
