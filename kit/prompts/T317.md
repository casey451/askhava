## Goal

Fourth external audit F12 and F17 (D-2206; SEC-014, TXT-031; D-1951, D-2041 (2), D-1310): the inbound text route opens requests with no SEC-014 limit (D-1951 named the next owner of `app/server/src/inbound_text.rs` to call `intake::api::admit_new_request`; D-2041 (2) left it because `admit_new_request` counts on its own pool outside the delivery's transaction, so a 500 and resend counts twice, and the route has no open-request read), and the LIST reply names no business (`Webhooks::names` is built empty, `app/server/src/lib.rs:277`). This is a harness task only because it adopts four done tests that build `Webhooks` by name (D-2206). After T279: (1) `app/intake/src/limits.rs`: `admit_new_request` counts on the connection it is given (the delivery's transaction, so a rolled-back delivery counts nothing), keyed by the sender's vault contact (blind index; no IP, the request comes from Twilio); `intake::api` gains the read of whether the sender has an open request. The signature changes from the pool to a connection for every caller: the web-chat path calls it too (with her contact and the client IP, in the transaction that opens the request), which T103 builds and T299 wires, both after this task (D-2206). (2) `inbound_text.rs` calls it before `receive_reply` only for a homeowner sender with no open request; a refused text keeps its inbox row (so Twilio's resend is a repeat), opens nothing, is answered by nothing and raises at most one Low alert per sender per window, with no body or phone; HELP, STOP and START are handled before the limit as today. (3) `Webhooks::names` is removed: the LIST reply reads the quoted businesses' names at the time of the text through T316's `businesses::api::public_names` (D-1310's no-name fallback stays). (4) `Webhooks` gains the route's `Environment`, set from the settings in `main.rs`, which T299 passes to the AI gate (D-2065). (5) The four done tests that build `Webhooks` (`tests/integration/tests/inbound_text_route.rs`, `inbound_first_contact.rs`, `inbound_scrub_context.rs` and `app/server/tests/inbound_voice.rs`) change only in that construction (no `names`, the test environment set) and, where a test passed names for LIST, in seeding those businesses' records instead; every input, expected value and assertion stays byte-identical. Tests in `tests/integration/tests/inbound_text_guards.rs` through the served route (TD-SEC-52); every TD-TXT-12, TD-TXT-16, TD-TXT-32, TD-TXT-33, TD-CALL-14 and TD-AI-19 case passes.
