## Goal

Plan change D-4419 (5): `td_lic_30_reads_write_nothing_and_log_no_value` (`tests/integration/tests/signup_own_record.rs:602`) failed once in `Ci` at its `assert!(!logged.is_empty(), "the unreadable read is logged")` (`:634`) with no code change, then passed. Each test file that checks log lines keeps its own `Subscriber` (`Lines`, `:628` to `:674`) and installs it for its own thread only with `tracing::subscriber::set_default` (`:613`). `tracing` caches each callsite's interest the first time any thread reaches it; when another test in the same binary reaches a callsite while no subscriber is in place, or while the interest is being rebuilt as a capture is installed, the callsite can keep a cached `Interest::never`, and the event never reaches the capture: a test that asserts a line is logged fails, and one that asserts no line holds a value passes without having seen the line. Build one capture for the `askhava-integration` test crate in the new `tests/integration/src/log_capture.rs` (`pub mod log_capture;` in `tests/integration/src/lib.rs`; `tracing` moves from `[dev-dependencies]` to `[dependencies]` in the shared `tests/integration/Cargo.toml`, no new crate, `Cargo.lock` unchanged): a process-global subscriber installed once per test binary (`std::sync::OnceLock`, `tracing::subscriber::set_global_default`, then `tracing::callsite::rebuild_interest_cache()`), whose `register_callsite` answers `Interest::always()` and `enabled` true, so no callsite is ever cached as never while it is in place, and which appends each event's and each new span's fields (as the files' `Line` visitors do: ` name=value` with the value's `Debug`) to the buffer of the capture started on the current thread, if any; `log_capture::start()` gives a guard holding that buffer (a `Vec<String>` behind `Arc<Mutex<_>>`) whose drop ends the capture, and a capture never sees another thread's events, as today. A unit test in `log_capture.rs` reaches a callsite first on another thread before any capture exists, then captures it on the test's thread. Move to it the three files whose tests assert that a log line is present, deleting their own `Subscriber`: `signup_own_record.rs` (TD-LIC-30, both captures, `:211` and `:613`), `tests/integration/tests/emergency_request_limits.rs` (`:275` to `:286`, "logged once", `error=\"Counter\"`) and `tests/integration/tests/safety_key_retry.rs` (`:228` to `:229`, "step failed"). Every assertion in the three files stays as it is, word for word: no assertion is removed, loosened or moved after a retry; only the capture's type and its start change. The other per-thread captures are not changed here: eight more `tests/integration/tests/` files assert only that no line holds a value, and those in other test crates (`app/server/tests/`, `tests/security/tests/`, `app/jobs/src/tests/transitions.rs`) cannot use this crate's helper. First check that the "unreadable read" line (`app/licensing/src/own_record.rs`) is logged on the test's own thread; if it is logged on another, that is the cause, and the worker reports a plan gap instead of widening the capture. Update `docs/decisions.md`.

Acceptance: `cargo test -p askhava-integration --lib log_capture` passes, its other-thread-first case included; `signup_own_record.rs`, `emergency_request_limits.rs` and `safety_key_retry.rs` pass against PostgreSQL with every assertion unchanged (a `git diff` of the three files shows only the capture's type and start changing), and the three files pass 20 runs in a row (`for i in $(seq 20); do cargo test -p askhava-integration --test signup_own_record || exit 1; done`), the result in the PR; no other test file changes.
