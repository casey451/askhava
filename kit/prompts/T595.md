## Goal

The bug fails closed: the empty string never equals the 64-hex token, so no forged or missing token was ever accepted, and after the fix a missing, empty, wrong or other-cookie token is still refused. (2) CON-025 (`docs/spec/consent.md:29`: "the start screen says the user must be 18 or older"; TD-CON-10, `docs/test-design.md:349`): `app/site/templates/request.html` shows the line `You must be 18 or older to use {{ brand }}.` (the `brand` already bound at `:10`) in its own `<p>` right after the English consent text (`:17`) and above the chat box, on every step, outside `lang="es"`; it is plain copy (no `data-fixed`: CON-025 fixes the fact, not the wording), so `scripts/check_copy.py` measures it and reports 0 problems; no Spanish copy is added (WEB-006 covers only the consent draft). (3) Why T489's tests missed it: `app/site/src/chat.rs`'s unit tests call `chat_routes` directly, without `server`'s guard (`chat.rs:524`); `app/server/tests/door_matrix.rs` only proves refusals (`probe_csrf`, `:1263`, a cross-site and a wrong-token `POST`) and accepts any answer below 500 for a Public `POST` with the actor's own token (`judge`, `:448`), so a 403 passed; `app/server/tests/route_wiring.rs` probes with a bodiless `PROBE` request.
