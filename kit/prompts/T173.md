## Goal

Ally runs the Playwright accessibility suite at 320, 768 and 1280 px; Ci gains a job that builds the server and worker, starts stand_ins/server.py (T167) and a Postgres service, and runs `npx playwright test tests/e2e`, so the four journeys are a required check (BUILD_BRIEF.md section 11); the Dockerfile's build stage runs `npm ci` and `tsc` so compiled browser scripts ship in the image (D-453, D-479). Acceptance: a journey spec with one failing assertion turns Ci red, and one axe violation turns Ally red (both shown in the task report) The e2e job builds server and worker with the test-control feature, starts Postgres, stand_ins/server.py and stripe-mock (pinned by digest) as services, runs `server migrate`, uses T227's Playwright config and webServer, runs `npm run build` first so the compiled .js exists, uses actions/setup-node with Node 22, and caches the Playwright browsers (D-481). This task also writes the reduced J1 as `tests/e2e/j1_reduced.spec.ts` against the stand-ins, the stage-2 exit evidence: J1 steps 1 to 6 (text in and consent, ZIP and trade, the urgency and question set, the card shown and sent, quotes on the quote page, the pick by code and the contact choice) with these omissions: no photo (step 3 sends none and step 4's card has no photo), no review links (step 5), no share box (step 6), and the two diagnostic-visit quotes seeded through the test-control router instead of a business quoting; no payment or call (D-491).

Acceptance: A journey spec with one failing assertion turns `Ci` red and one axe violation turns `Ally` red, both shown in the task report.
