## Goal

Plan change D-3144 (OPS-001, OPS-024, FEE-017, FEE-021, PICK-022, SEC-030; D-133, D-491): safe mode pauses releases as well as charges, but every release goes through `server`'s `PickReleaser` (`app/server/src/release_sink.rs:78`), which no switch reaches, and T105, which builds safe mode, owns none of the release files. (1) While `ops::api::safe_mode_on` (T487) is true, `PickReleaser` settles and releases nothing for a cleared pick: it queues one held-release task (its payload the pick ID and its due time, since a claimed task carries no run time, `app/core/src/tasks.rs:100`; deduplicated per pick) and answers success, so the Stripe route answers 200 and Stripe sends nothing again. An error reading safe mode settles, releases and queues nothing and returns `ReleaseError::Database`, so the Stripe route answers 500 and Stripe sends the event again (fails closed); TD-OPS-40 makes that read fail with `ALTER TABLE ops.safe_mode RENAME TO safe_mode_unreadable` in the test's own database (the test pool connects as the database's owner, so a `REVOKE` from the app role would change nothing; the database is the test's alone, so nothing is restored). The gate queues nothing for a pick whose `picks.release` row already exists (released before safe mode began, or a duplicate event after its release) and answers as the sink answers an already released pick; it reads that through `picks::api::is_released(conn, pick)`, which this task makes by renaming the private `claimed` (`app/picks/src/release.rs:385`) and making it `pub`, with one `pub use` in the shared `app/picks/src/api.rs` (nothing else in `release.rs` changes).
