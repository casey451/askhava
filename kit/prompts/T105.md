## Goal

Casey is alerted on the delivery-rate, safety, dispute and coverage conditions, one delivery alert at a time with automatic acknowledgement at 97%; owner pause switches are checked by every action; and safe mode pauses only charges and releases when a pushed High alert is unacknowledged for 24 hours, each paused item going ahead after the FEE-017 check when it ends (OPS-001 to OPS-006, OPS-023 to OPS-025). `ops` reads nothing above it: `messaging` reports delivery counts by calling `ops::api::record_delivery_counts` and `businesses` its active-business counts by `ops::api::record_business_counts`, both added here to `ops`' `api.rs` and called here from `messaging`'s delivery handler (`handlers.rs`) and `businesses`' status changes (`service.rs`); the pause-check property test lives in the integration crate, which sees every action, in `tests/integration/tests/safe_mode.rs` (D-491, D-493); `jobs` reports each trade's requests per calendar month by calling `ops::api::record_request_counts` from `app/jobs/src/request_counts.rs`, owned here, so OPS-006 sees which trades had a request (D-493); the email-limit push itself is T204's (TD-OPS-13, D-491). Plan change D-3144 (OPS-001, OPS-003, OPS-024, PICK-048, FEE-038; D-1427): the two `safe_mode_check.rs` files once planned in `payments` and `picks` are dropped (nothing would call them). Safe mode's state is `ops`' (this task's migration and `safe_mode.rs`, read through a new `ops::api::safe_mode_on`), and `payments::handlers::charges_paused` (`app/payments/src/handlers.rs:90`, owned here after T359; D-1427 left this check to the task that builds safe mode) checks it beside the `charging` and `all` switches, which is all the charge side needs: a "Confirm and pay" press is refused with "try again later" before any Stripe call (`before_attempt`, `app/payments/src/charge.rs:367`, `ChargeOutcome::Paused`, OPS-024), a PICK-048 auto-confirm falls back to the Confirm step (`app/payments/src/off_session.rs:220`, `FellBack`), and the card-fix and Stripe-release timers stop and resume, because `sync_pause` (`handlers.rs:569`) reads `charges_paused` (FEE-038). The release half (a release waits while safe mode is on and goes ahead after the FEE-017 check when it ends) is new T408's, which runs after this task: TD-OPS-01's and TD-OPS-06's release clauses are proven there (TD-OPS-40), and this task's `safe_mode.rs` tests the charge side, the alerts and the switches. The town and trade switches are read where cards go out (T251's card pool, through `ops::api::is_paused`); TD-OPS-01's "every action checks the pause switches" property covers the actions on `main` when this task runs. `NewAlert` gains no field (34 files build it by literal); an acknowledgement or push fact this task adds lives in its own column or table.
