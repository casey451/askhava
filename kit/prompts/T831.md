## Goal

Plan change D-5502 (T118's attempt-4 plan gap, reproduced by its reviewer at cb4a620, checked on `main` 23fcbe8; A11Y-005, `docs/spec/accessibility.md:9`). At 1280 by 900 the chat start screen's `textarea#chat-words` (`app/site/templates/request.html:48`) spans y=784 to 914, partly below the viewport; Chrome does not scroll a partly visible control into view when Tab reaches it, so its focused box lies partly outside the viewport and A11Y-005 fails (T118's `tests/a11y/j3_keyboard.spec.ts` checks it at step 5). Scrolling the page in the test would hide the defect a keyboard user meets, so the page changes. Lay out the start screen so, at 900 px tall and at each width the keyboard journeys and Ally use (320, 768, 1024 and 1280), every control on it (the words box, its "Send" button) is either wholly inside the first screen or wholly below it, measured as the keyboard tests measure (a box outside by more than half a pixel counts, `tests/a11y/j2_keyboard.spec.ts:39`); at 1024 and 1280 the words box sits wholly inside it ("Send" may sit below: Chrome centres a wholly below-fold button when Tab reaches it). A Chrome mock with the real CSS and fonts puts the box at y=784 to 886 at 1280 by 900 with `rows="3"` alone, so a small change suffices. Use spacing, padding and the textarea's height or `rows`, in markup in `request.html` or CSS in `site.css` scoped to a class this task adds in `request.html`; `.form-card` also styles `app/site/templates/help.html:29`, so no rule changes `main`, `h1`, `h2`, `p`, `textarea`, `.card` or `.form-card`, and `/help` renders unchanged; never by changing a word, the order of the consent text, the Spanish draft, the 18-or-older line, the AI line and the form (`tests/e2e/web_chat.spec.ts:116` to `:122`), the focus ring, a font size under 16 px or the 44 px targets; no script. Every DONE test of the page passes unchanged (`tests/e2e/web_chat.spec.ts`, `site_pages.spec.ts`, `site_no_js.spec.ts`, `tests/a11y/page_structure.spec.ts`, `reflow_spacing.spec.ts`, `design_tokens.spec.ts`, the `/request` states in `page_states.ts:457`, `:755`, cites refreshed by D-5526), and the screenshot review (`tests/a11y/polish_screens.spec.ts`) records the new first screen. The new `tests/a11y/request_first_screen.spec.ts` opens `/request` at each of those widths by 900 and asserts the rule above for each control, and, as J3 checks it, Tabs to `#chat-words` at 1280 by 900 with the AI-026 line shown and asserts its box is inside the viewport, also with the WEB-007 banner shown (about 45 px more) and with the safety-call consent shown (about 112 px more). Update `docs/decisions.md`.

Acceptance: `tests/a11y/request_first_screen.spec.ts` passes at 320, 768, 1024 and 1280 by 900, and Tab reaches `#chat-words` at 1280 by 900 with its box inside the viewport with the AI-026 line shown, with the WEB-007 banner and with the safety-call consent; `/help` renders unchanged; Ally (axe, design tokens, reduced motion) and every existing test of `/request` pass unchanged; no word or order changes.
