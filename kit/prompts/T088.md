## Goal

A security test generated from the route table checks every route against anonymous, two homeowners, two businesses and the owner, proving each gets exactly its expected allow or deny, one homeowner's token never reads another's job, and every denial is logged as a security event (SEC-004 to SEC-006, SEC-008, SEC-019, SEC-048); and, since the push web app is not built in the pilot build (BIZ-041), the route table holds no push-subscription route and no portal page registers a service worker or serves a web app manifest (TD-BIZ-31, D-491).

### 2. Principles that bind this codebase (lines naming this task's requirements)
**R4. Handlers are infallible; every error becomes a response.** axum requires services with `Infallible` error type, so failures are values converted through `IntoResponse` (axum error_handling docs). Serves SEC-019, WCAG error pages (`docs/spec/accessibility.md`) [inferred link].
**R5. Log an error once, where it is handled.** "Errors should be logged when they are handled"; a function that propagates with `?` does not log (Palmieri). In Ask Hava the handling point is `AppError::into_response` for web and the claim loop for tasks. Serves PRIV-016 (fewer log lines, fewer leaks), SEC-048.
