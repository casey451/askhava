## Goal

D-1772 made `tests/a11y/fixtures.ts` a shared path so a page-adding task can add its `PAGE_STATES` entry, but the same file holds the Ally check machinery (`WCAG_TAGS` at `tests/a11y/fixtures.ts:25`, `REVIEWED_INCOMPLETE` at `:28`, `NOT_PAGES`, `readRouteTable` at `:73`, `axeScan` at `:180`), so a shared-path edit could weaken the checks, and only a reviewer notices (D-1788). Split it. (1) New `tests/a11y/page_states.ts` holds only data: the `PageState` type, `PAGE_STATES`, and per-route seed helpers, so each route's states carry their own seeding (today `PAGE_STATES` is one `.map()` over `QUOTE_ROUTE`, `fixtures.ts:129`–`:137`, and `seed()` assumes a quote token, `:144`–`:153`): each entry names its route, its states and a seed function returning the path to open, with the quote-page states moved unchanged. (2) `tests/a11y/fixtures.ts` imports them and keeps `ROUTES`, `STATES_TO_CHECK` (the filter against the route table is check logic, so the shared file can never narrow what is checked), `NOT_PAGES`, `WCAG_TAGS`, `REVIEWED_INCOMPLETE`, `readRouteTable`, `axeScan` and the test fixture, and re-exports `PAGE_STATES`, so no importing spec changes. (3) `tests/a11y/page_states.ts` is already a shared path (`shared_paths`, `ALLOWED_SHARED` and the template's sentence, D-1788), so every later page-adding task adds its entry there; `fixtures.ts` stays shared until the plan change after this task drops it from both lists (register row IC-36). Every page-state entry on `main` when this task starts (T084's sign-in page included) moves across unchanged.

Acceptance: TD-A11Y-03 passes; `Ally` is green on the task's head with the same (route, state) pairs as `main`; `WCAG_TAGS`, `REVIEWED_INCOMPLETE`, `NOT_PAGES`, `readRouteTable` and `axeScan` are byte-identical to `main`.
