## Goal

The app answers `/healthz` for the uptime monitor, the owner portal shows the OPS-008 health figures, and it offers the monthly spot-check of 10 random job cards (OPS-007 to OPS-009). The `/healthz` probe is `app/server/src/healthz.rs` (the server binary checks the process, the database and the worker check, read from `core.task`, so no new table is needed (plan change D-3144: the worker counts as down only when a task has been due, its `run_at` passed with no `done_at`, no `dead_at` and no live lease, for longer than a setting, 10 minutes by default; an idle worker and a database no worker has served yet answer 200, because `app/server/tests/door_matrix.rs` probes `/healthz` as a public `GET` that must answer 200, `:390`, with no worker running; the body names the database and worker state and the age of the newest lease or finish, TD-OPS-02); `ops` holds no route, D-491); the health page with its figures is a portals page reading each module's `api` (the last-backup figure reads `ops::api`, where `recovery` records each backup and restore result; T109 adds that record and replaces this task's 'not yet recorded' placeholder, D-493). `web` and `worker` exit non-zero when their own liveness check has failed for 3 minutes (a setting) so the host's On Failure policy restarts them (OPS-049), and the health page shows each required secret as present, parsed and environment-matched, never its value, length or hash (OPS-008) (D-492). T304 serves the health page (D-2128): the page function and route constant only, no `.route` for it in `server` (`/healthz` stays this task's). Its routes pass T348's doors unchanged: `tests/security/tests/auth_matrix.rs` classifies each and `app/server/tests/door_matrix.rs` probes each `yes` row of `docs/architecture.md` section 13 over HTTP (D-2440); this task edits neither, and a route whose path parameter the probe cannot fill is reported, not worked around.
