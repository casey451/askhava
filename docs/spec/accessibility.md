# Spec: Accessibility (WCAG 2.2 AA)

Prefix: `A11Y` · Modules: `site`, `portals`, `messaging`, `calls` · Format and checks: [index.md](index.md)

- **A11Y-001** Every page and state of the site and the three portals, at 320, 768 and 1280 px, has no axe-core violation of the WCAG 2.0, 2.1 and 2.2 Level A and AA rules (tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`), and every WCAG 2.2 Level AA success criterion axe-core cannot test is covered by a row of the accessibility checks in docs/test-design.md section 6 or by the Gate B screen-reader check (A11Y-022) (D-485). Source: `BUILD_BRIEF.md:384`, `sources/01_spec/Changes_Since_v9.3_AUTHORITATIVE.md:151`.
- **A11Y-002** axe-core runs on every page and state at 320, 768 and 1280px, and any violation fails the `Ally` check. Source: `BUILD_BRIEF.md:424`.
- **A11Y-003** Every page has one `h1`, landmarks and a skip link, using semantic HTML first and ARIA only where HTML can't do it. Source: `BUILD_BRIEF.md:387`.
- **A11Y-004** Every page has `lang="en"` or `lang="es"`, and any inline passage in the other language has its own `lang`. Source: `BUILD_BRIEF.md:388`.
- **A11Y-005** On every page, every link, button and control can be reached and used with Tab, Shift+Tab, Enter and Space alone, in the order it appears in the page source; the focused element always shows the design spec's focus ring (3 px, the `focus` token) and its box lies inside the viewport and not under any sticky header; and focus can always leave every component with Tab, Shift+Tab or Escape, so there is no keyboard trap (D-485). Source: `BUILD_BRIEF.md:389`.
- **A11Y-006** Targets are at least 24×24 CSS px, and nothing needs dragging or complex gestures. Source: `BUILD_BRIEF.md:390`.
- **A11Y-007** Text contrast is at least 4.5:1, and large text and UI parts at least 3:1. Source: `BUILD_BRIEF.md:391`.
- **A11Y-008** Pages work at 320px wide and at 400% zoom without sideways scrolling, except data tables, which scroll inside a focusable region with `tabindex="0"`, `role="region"` and an `aria-label`. Source: `BUILD_BRIEF.md:392`, `sources/01_spec/Changes_Since_v9.3_AUTHORITATIVE.md:148`.
- **A11Y-009** With the WCAG 1.4.12 text-spacing overrides applied (line height 1.5, paragraph spacing 2 times the font size, letter spacing 0.12 and word spacing 0.16 times the font size), no text is clipped, overlapped or cut off and no control is hidden; and with `prefers-reduced-motion: reduce` no CSS animation, transition or smooth scrolling runs (every computed animation and transition duration is 0) (D-485). Source: `BUILD_BRIEF.md:393`.
- **A11Y-010** Form fields have visible labels with instructions before the inputs. Source: `BUILD_BRIEF.md:395`, `BUILD_BRIEF.md:396`.
- **A11Y-011** Form errors are named in text, linked from an error summary and announced. Source: `BUILD_BRIEF.md:397`.
- **A11Y-012** No form asks again for something the user already entered. Source: `BUILD_BRIEF.md:398`.
- **A11Y-013** Sign-in needs no memory or puzzle test, and pasting and autofill work. Source: `BUILD_BRIEF.md:399`.
- **A11Y-014** New quotes arriving are announced politely with `aria-live`, and focus moves to the result heading after a pick. Source: `BUILD_BRIEF.md:400`.
- **A11Y-015** Time limits exist only for pick codes, sign-in links, the sign-in, Confirm and identity codes (SEC-004, BIZ-002), the 5-minute fresh-code windows (SEC-038, SEC-043), owner sessions and the owner's 30-minute idle timeout (SEC-043); each warns before expiring, offers a one-step way to get a new code or extend, and keeps what was entered (D-491). Source: `BUILD_BRIEF.md:402`, `BUILD_BRIEF.md:403`, `BUILD_BRIEF.md:404`.
- **A11Y-016** Quote windows are shown as plain text, never as countdown timers. Source: `BUILD_BRIEF.md:405`.
- **A11Y-017** Help is in the same place on every page. Source: `BUILD_BRIEF.md:411`.
- **A11Y-018** The site-wide status banner and every status message that needs no immediate action (saved, sent, a new quote) use `role="status"`, and a message that needs immediate attention (an error that stops the action, a code or session about to expire) uses `role="alert"` (D-485). Source: `BUILD_BRIEF.md:412`.
- **A11Y-019** Emails are real text rather than images, include a plain-text version, and use meaningful link text. Source: `BUILD_BRIEF.md:419`.
- **A11Y-020** An accessibility statement page gives the conformance target, known limits and a contact by text, email or the help page's form, saying "If you use a relay service, you can reach us by text or email." and that the Ask Hava owner usually replies within 2 days, the same as the HELP reply (CON-018), and never offers a phone line while the Ask Hava number is text-only (CALL-020) (D-379). - **A11Y-025** Every axe-core "incomplete" (needs review) result on any page and state is listed in the Ally job's report, and a page with an incomplete result not reviewed within one release fails Ally (D-490). Source: `docs/brains/accessibility-forms.md:146`, `BUILD_BRIEF.md:293`.
- **A11Y-026** Every page with a sticky header, footer or the WEB-007 banner sets scroll-padding-top and scroll-padding-bottom to the bar's height, and a Playwright test tabs through each page and fails if any focused element is fully covered (D-490). Source: `docs/brains/accessibility-forms.md:147`, `BUILD_BRIEF.md:293`.
- **A11Y-027** Every photo upload is a native file input with a visible label; any drag-and-drop area is an addition to it, never a replacement (D-490). Source: `docs/brains/accessibility-forms.md:148`, `BUILD_BRIEF.md:293`.
- **A11Y-028** Every text input, select and textarea on the paper surface has a border of at least 3:1 against the paper behind it, and the WEB-027 colour-pair test includes input borders and the focus ring against every surface they can sit on (D-490). Source: `docs/brains/accessibility-forms.md:149`, `BUILD_BRIEF.md:293`.
- **A11Y-029** Every form field is named by a visible <label for>; aria-label is used only where no visible text exists, and placeholder never carries a label or a hint (D-490). Source: `docs/brains/accessibility-forms.md:150`, `BUILD_BRIEF.md:293`.
- **A11Y-030** Every form posts to the server with novalidate and no required attribute; after a failed submit the page title begins "Error: ", the error summary is the first element in <main> and receives focus without JavaScript, each message links to its field, and every entered value is kept (D-490). Source: `docs/brains/accessibility-forms.md:151`, `BUILD_BRIEF.md:293`.
- **A11Y-031** No form's submit button is ever disabled; double submits are refused or ignored by the server through the request's idempotency key (D-490). Source: `docs/brains/accessibility-forms.md:152`, `BUILD_BRIEF.md:293`.
- **A11Y-032** Every one-time code field (pick, sign-in, Confirm, identity) is a single input with autocomplete="one-time-code" and inputmode="numeric" that accepts pasting (D-490). Source: `docs/brains/accessibility-forms.md:153`, `BUILD_BRIEF.md:293`.
- **A11Y-033** The quote page's role="status" element is present and empty in the first server render, and each update writes one short summary line, never one line per quote (D-490). Source: `docs/brains/accessibility-forms.md:154`, `BUILD_BRIEF.md:293`.
- **A11Y-034** Every HTML email sets lang on its root element to the recipient's language (D-490). Source: `docs/brains/accessibility-forms.md:155`, `BUILD_BRIEF.md:293`.
- **A11Y-035** The web chat works without JavaScript as one question per server-rendered page with the conversation so far shown above the current question; JavaScript may enhance it but never adds a question or a step (D-490). Source: `docs/brains/accessibility-forms.md:156`, `BUILD_BRIEF.md:293`.
