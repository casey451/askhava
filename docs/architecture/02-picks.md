# Architecture section 2 notes: `picks`

Moved here verbatim from `docs/architecture.md` (D-6022), whose index lists every part. Until T885 makes `docs/architecture/` a shared path, a task adds new notes to the index, at the end of the section this part came from, and the next plan change moves them here.

The section 2 notes ("Processes and code layout") whose first named crate is `picks`, in their original order.

- Open-cards email (T684, D-4361, D-5017, D-4992 to D-4994; CARD-022, BIZ-037, BIZ-038, OPS-038): the hourly `picks.open_cards_email` (`picks::open_cards_run`, registered by `server::register_open_cards` from `register_unreachable`, first queued by the worker's `schedule_checks` under one dedupe key per clock hour, each run queuing the next hour) works only in the hour of 8 a.m., noon or 5 p.m. Arizona time. It takes the businesses `quotes::api::card_businesses` names plus those with a waiting pick, reads each one's unquoted open cards through `quotes::api::open_cards` (new `quotes::open_cards`; no homeowner detail), asks `messaging::api::digest_goes` per team member who gets job cards, and stores one `Notice::OpenCards` email per person and slot with `messaging::api::queue_email` as `EmailClass::Bulk` to the member's mailbox; `messaging.email_due` sends it. The Quote and Confirm links come from `picks::api::OpenCardsLinks`, which `server`'s `PortalDigestLinks` implements with `portals::api::mint_action_link`.
- Aftermath notices wired (T681, D-4361, D-4997, D-4998; PICK-026, PICK-038, D-1575): `picks::settle` calls `aftermath::lost_notices` in the transaction that records the pick `paid` or `free` (on the pick's `tier_index`, default `LossSettings`); `jobs` may not call `picks`, so every applied move into a final status (`service::apply`, so timer moves too) queues one core task `jobs.final_status` `{job, status, at}` (`at` since T744; `jobs::api::FINAL_STATUS_KIND`, `jobs::final_event`, keyed per job) in the move's transaction, whose handler `picks::api::run_final_status` (registered in `server`'s `register_pick_notices`) calls `no_longer_active`; `picks::confirm::refused_at_confirm` (account or license refusal) and `connect::end_pending` with `Ineligible` call `refused_after_confirm` in their transaction. New cross-module edge: a `jobs` task kind handled by `picks`.
