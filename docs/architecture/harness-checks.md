# Architecture: CI, the smoke and the plan checks

Moved here verbatim from `docs/architecture.md` (D-6022), whose index lists every part. Until T885 makes `docs/architecture/` a shared path, a task adds new notes to the index, at the end of the section this part came from, and the next plan change moves them here.

Section 12's bullets about CI, the smoke test, the plan checks and the other workflows, in their original order.

- Smoke test (D-476): `scripts/smoke.sh` is the smoke test every task runs first and before hand-in: the sources fingerprint, Ci's gitleaks scan over the files Ci sees when `gitleaks` is on the path (the backup runner installs the pinned release; elsewhere it says it skipped, D-582), every plan and wording check, the Python tests and, once the workspace exists, `cargo fmt`, clippy and `cargo test` against a local PostgreSQL 16 it starts with a fresh local-only password (`--full` adds cargo-audit and cargo-deny). `.gitignore` keeps `/target/` and `node_modules/` out of commits and out of the scanners. The pre-hand-in gate (D-1300): `scripts/prehandin.sh` runs on a task branch the `Ci` "Checks" steps smoke does not (the sources file count, every plan, wording and source-rule check, the skip guard, `check_plan_lock.py` and `check_pr_change.py --base origin/main --branch <branch>`), and without `--quick` eslint and `python3 scripts/npm_audit.py` (D-4223) when the npm tree changed and cargo-audit and cargo-deny when Rust changed and both are on the path, by `Ci`'s own path rules; also without `--quick`, when the diff touches a crate with a floor in `tests/coverage_floor.json`, `cargo llvm-cov` on `Ci`'s pinned nightly over that crate and every workspace crate depending on it, judged on those floors by `scripts/coverage_floor.py`, the comparison `Ci`'s Coverage job now calls too (`select` and `compare`; a floor whose path has no file is never selected; a missing measurement is red: an empty report, a floor on disk the report does not measure or measures with zero lines, an absent `--only` prefix, and a floor not on disk unless the floor file's `future` list gives a reason, D-2096; skipped without the tools or `DATABASE_URL`, and past 360 s; `backup-runner.yml` keeps the instrumented build on `/mnt` or `/tmp`, so it is cold every job, D-1440, and installs cargo-llvm-cov and the nightly best effort, so a failed download there leaves the gate saying it skipped, while its gitleaks and `Ci`'s own downloads stay required and every release download in both workflows retries 5 times; gitleaks in both falls back to building the same pinned version from proxy.golang.org, checked by sum.golang.org and the pinned module hash `GITLEAKS_MOD_H1`, and must report that version, and `Ci`'s cargo-audit, cargo-deny and Coverage cargo-llvm-cov fall back to `cargo install --locked` of the same pinned versions from crates.io and must report them, D-1986); it does not run pytest, cargo or tsc (smoke does) or `Ci`'s workspace-total coverage. The worker runs smoke (polled every 4 minutes at most, D-1317), commits, then the gate. At `python3 -m runner --after`, `GitHubEnv.collect_result` runs main's copy of the gate with `--quick` (`prehandin`, `PREHANDIN_ROOT` pointing at a detached worktree of the submitted head, `PREHANDIN_TIMEOUT` 240 s) after the decision entries are put in order and before any review record or push; exit 1 turns the hand-in into `tests_failed` with the gate's last 30 lines, redacted and capped at 3,000 characters (`PREHANDIN_RED`), and any other exit (3 is the gate's own "cannot check": no base or no merge base), a timeout, a missing gate on main or a worktree git cannot make is logged and lets the hand-in through; a check script the head lacks is skipped, and the output is also redacted with `scripts/pii_scan.py`'s key, phone and email patterns (`GATE_REDACT`). `runner/__main__.py` `hold_red_gate` then holds a red hand-in for up to 2 fix rounds per hand-off (`PREHANDIN_HOLDS`, counted in `.git/runner_handoff.json` with the last gate output): `cycle.after_handoff` writes nothing, the lease stays held and the task IN_PROGRESS, `--after` prints `runner: prehandin_red` and the output, and `backup-runner.yml` step 5b gives it to a new worker on the same branch; the third red fails the attempt with that output as `last_failure`, and a session that ends without handing in leaves the kept output in the safety step's failure. The hand-off carries `hand_in_by` (the lease's expiry less 30 minutes, `runner/__main__.py` `hand_in_by`), which `backup-runner.yml` step 3 passes to the worker as its deadline (D-1440). With `--ally`, its own call after the gate (D-3837), it runs the required `Ally` suite as `a11y.yml` does (the test-control build that `tests/e2e/webserver.ts` starts, then `npx playwright test --config tests/a11y/playwright.config.ts`) when `scripts/prehandin_ally.py select` names a changed path that can change what `Ally` renders (page templates at any depth and `static/` files, `docs/legal/`, `docs/copy/`, `docs/catalog/`, `app/<crate>/data/`, a crate's `Cargo.toml` and `Cargo.lock`, every source of a crate with an `.html` template and a route, any source holding a `.route(` call on the head or the base, `app/server/src/lib.rs` and `main.rs`, `migrations/`, `tests/a11y/`, `tests/e2e/webserver.ts` and `keyed.ts`, `stand_ins/`, the npm tree, `a11y.yml`), else it prints `not needed`; it makes a fresh `askhava_ally` database on the local PostgreSQL when `DATABASE_URL` is unset, tries `npx playwright install chromium` once, says it skipped when a tool, the database or a port is missing, when no test ran (the suite's globalSetup threw: its `SETUP ERROR` lines and the log's tail are printed and the log kept) or after 540 s for the whole call (`PREHANDIN_ALLY_TIMEOUT`, the build under the same `timeout`), ending `prehandin --ally: skipped (Ci runs Ally)`, prints only failed tests and counts (`prehandin_ally.py summary`), and removes the `.js` files `npm run build` wrote; `--quick` never runs it. D-4281: in the backup job the state read (`Read the recorded smoke runs`) comes before the warm-up, and `--warm-smoke` builds nothing when `_reusable_line` (the pre-session step's own rule, the same `smoke_ancestry_reuse`) says the recorded smoke will be reused.
- Compiled-in files (D-1867, D-2248): `Ci` builds Rust only when the diff matches its path rules (the Checks and Coverage rules in `.github/workflows/ci.yml`, `RUST_PATHS` in `scripts/prehandin.sh`, and the E2e rule), so the files the Rust code pulls in by path are named there: `docs/legal/`, `docs/catalog/`, `schemas/`, `docs/architecture.md`, `docs/copy/mail-app-steps.md` and `scripts/pii_scan.py` (read by `tests/fixtures`), never all of `docs/`. `scripts/check_include_paths.py` runs in Checks on every push and in `prehandin.sh --quick`: every `include_str!`, `include_bytes!`, `include!` and `concat!(env!("CARGO_MANIFEST_DIR"), ...)` path in `app/` and the Rust test crates must resolve to an existing file inside the repository that all three rules match; a non-literal argument fails, and a path naming the repository root (a run-time base) is printed as a note. A new compiled-in folder therefore joins the rules in the same pull request.
- Proven-parent pass (D-4281, D-4321): in the four `changes` steps of `.github/workflows/ci.yml` (Checks `rust` and `npm`, Lint and slow tests `rust`, Coverage `rust`, E2e `run`), a flag D-489's rule set true on a branch run goes back to false only when `scripts/ci_proven.py` prints an exact `proven=<sha>` line: HEAD is a two-parent merge whose second parent is on origin/main's first-parent line (the runner's update merge), every push run of this repository's `ci.yml` on HEAD^1 has that job green in every attempt, and `git diff -z --no-renames HEAD^1 HEAD` touches neither the step's own rule (read from the step script, `$0`) nor the script's `EXTRA` paths (coverage floor and `scripts/coverage_floor.py`, `.cargo/`, workflows, the script, `scripts/npm_audit.py`, `scripts/brand.py`, every path in a subdirectory of `tests/` (only the top-level `tests/*.py` stay outside), every `Cargo.toml`, `Cargo.lock`, `rust-toolchain(.toml)`, `clippy.toml` and `deny.toml` at any depth, every `.js/.mjs/.cjs/.ts/.mts/.cts/.jsx/.tsx` path, rustfmt's config and the files Rust tests read at run time: `kit/tasks.json`, `Dockerfile`, `tests/task_kinds_deferred.json`, `scripts/check_rust_rules.py`; D-4321 gives each job's inputs). Any doubt prints `unproven: <why>` and compiles. `ci.yml` asks for `actions: read`; nightly-main's `ci` call grants it. Every other step, and the schedule, dispatch and `main` early exit, are unchanged.
- Merge train refs (D-4281, D-4355): on a `claude/task/T###-` branch `scripts/ci_proven.py` also judges, after HEAD^1, each tip of a `claude/train/T###-<12 hex>` ref of the same task (listed with `git ls-remote`, fetched with `--depth=1`, the job token in `http.extraheader` through git's environment) by the same rules (2) and (3), with no parent relation; on a `claude/train/` ref it proves nothing. `ci.yml` Checks fetches main in its own unconditional step, its delete guard fails when origin/main cannot be read, and only the plan lock and change rules step is skipped on `claude/train/` refs; `twin.yml` and `a11y.yml` ignore those refs and `governance.yml` skips their heads.
- Governance (D-479): the layer table of section 4 is also `kit/layers.json` (protected), which T175's architecture test reads; the approved crates of section 11 are also `kit/allowed_crates.txt` (protected), which `scripts/check_crates.py` enforces in `Ci`; sections 3 to 6 of this file are fingerprinted in `kit/plan.lock` and change only in a harness task or a plan change with a decision entry (`docs/governance.md`). When a crate joins section 11 under the new-library rule, the same decision adds it to the allow-list.
- Context budgets (D-1036, D-1075): `scripts/gen_prompts.py` measures each prompt's `budget.context_pct` from the bytes of the prompt, its owned files and its reads (this file, read by almost every task, is the largest term; `docs/decisions.md` counts only through the entries a prompt pastes). A stored value is kept while it is within 3 points of the measurement and both are within the task's limit, so this file's growth does not rewrite every prompt; `--check --strict` fails a measurement over the limit or a stored value further off. `scripts/pii_scan.py` warns when `docs/decisions.md` passes 75% of its `MAX_BYTES`. A read of this file counts as its section 2, every section the prompt itself cites ("architecture section 8"), plus the lines that name the task's module (`<module>` in backticks or `app/<module>/`), since workers read only section 2 and line ranges; a task that owns it would count it whole (D-1350).
- Plan health (D-1350): `scripts/plan_health.py` checks a task's plan before it is claimed: (a) its measured context against its limit (`gen_prompts.context_bytes`, `validate_tasks.context_limit`); (b) every repository path its requirement sentences, test-design rows and `reads` name is owned by it, an ancestor or the shared list (`check_pr_change.task_paths_check`) or already exists, and every path a live decision it pastes names is owned by some task or exists (a superseded decision never holds); (c) each dependency is DONE or SKIPPED and each DONE dependency's owned files are on `main`, except a file the plan deleted: a DONE task that owns it lists it under the optional `kit/tasks.json` field `deletes` (checked by `validate_tasks.py` to be its own owned file) and no DONE owner that depends on that task brings it back (D-2922; the runner's owned-file check at a close, `cycle._owns`, leaves a task's own `deletes` out too). `runner/cycle.py` `plan_health_pass` runs it on every eligible candidate before the pacer picks one (dependency status left to `eligible`, which already allows a proof-waiting cleanup dependency): a task with problems stays QUEUED with `attempts` untouched, gets a `plan_gap` mark (`{at, problems}`, at most 10 problems kept, allowed by `kit/state_schema.json`) listed under "Needs attention" in STATUS.md, and the next sound task is claimed; a sound task loses a stale mark, so a plan fixed on `main` frees it with no state edit; a changed problem list keeps the first `at`; a task that stops being a candidate keeps its last mark until its next turn; a check that raises holds nothing and leaves the mark as it is, and a checker that cannot be built (`runner/__main__.py` `plan_health_checker`) leaves the runner without the check. `refill_lanes` gives no lane to a candidate that already carries a `plan_gap` mark (a claim refused it) while the check still refuses it: judged read-only (`cycle._plan_keep`, writing no mark, each id asked once) on the ids left after the crate rule as in the claim (`lanes.claimable_together` with `keep`), failing open on a check that raises; an unmarked task is never refused there, since the run's checkout may be a task branch cut before later merges (D-723 hand-in runs). So a QUEUED task the plan no longer holds (T365, removed by D-3106) cannot start one idle run after another (D-3812). `python3 scripts/plan_health.py --all` surveys every task not DONE, plus every DONE task's owned files. Check (d), pinned lists (D-2550), is report-only: `scripts/plan_pins.py` finds tests that pin a data file by exact count or id list, and route tests whose classifier panics on a path it does not name, and warns about a task whose goal adds rows to such a file or serves such a route when it may not edit the test (unless a dependency not yet DONE owns the test by name, or a pasted decision lets it edit it); `plan_health.py --all` or `--pinned` prints the warnings as `WARN` lines, `check_task` never returns them, so nothing is held and the exit code ignores them; D-2551 (reserved) makes them holding problems. Check (e), unowned users (D-3496), is report-only the same way: `scripts/plan_symbols.py` warns when a file the task may not edit (the hand-in rule) names a public Rust item of the task's owned files that a change sentence of its goal or acceptance names (read from the clause's own words and a span's leading path; a method as `Type::name`, a free function as a call or path, a type as a word, a new enum variant only where a match has no `_ =>` arm; in another crate only where the file names the defining crate), when a test it may not edit holds verbatim a pinned value a change sentence quotes (an `@` tag, a kebab-case code, a `{placeholder}`), and lists the tests the goal names that it may not edit, those it says pass unchanged apart; a file a dependency not yet DONE owns is excused; `plan_health.py --all` or `--symbols` prints the `WARN` lines, guarded and never held, as for (d). Check (f), pages without states (D-3837), is report-only the same way: `scripts/plan_pages.py` warns when a task serves a GET route (its section 13 row's `Wired` cell names it, or its goal quotes `GET <path>` for a path section 13 does not list, stand-in, Stripe and Twilio sentences and query-string and `/v1/` paths left out) that no `PAGE_STATES` path or `NOT_PAGES` line in `tests/a11y` covers, unless its own goal names the registry in a sentence that does not hand the entry away, or a task it depends on names the registry and the path; `plan_health.py --all` or `--pages` prints the `WARN` lines, guarded and never held, as for (d).
- Build caches (D-2782, D-3143): GitHub keeps 10 GB of Actions cache per repository. `Ci`, `Twin` and `Ally` restore on every run and save only on `main` (the nightly): `Swatinem/rust-cache` with `save-if`, sqlx-cli and the Playwright browsers through `actions/cache/restore` and a `main`-only `actions/cache/save`. The backup job keeps one entry per family, each saved only from `main`'s ref: the smoke's (`rust-smoke-<os>-…`, D-1911) and the worker's (`rust-<os>-<lock>-<sha>`), which holds the registry alone because `python3 -m runner.cache clear` empties `target/debug` before the save; before the session, `python3 -m runner.cache seed` gives the worker's empty `target/debug` the smoke build's dependency artifacts (a fresh checkout rebuilds every member anyway). Just before each save `python3 -m runner.cache drop` deletes the family's entries created before the job started, and skips the save when another job saved a newer one (`runner/cache.py`) D-4071: the job first frees its root disk (`Free the runner disk (D-4071)`: Android, .NET, GHC, CodeQL and Swift removed before any restore), and `python3 -m runner.cache bound` deletes the smoke tree's profile-level `incremental` folders and saves the smoke entry only when it is at most `SMOKE_CAP` (24 GiB on disk, about 5.1 GB compressed); an entry over the cap is still dropped, so the next job builds the smoke cold and saves a small one. D-4281: a warm-up skipped on a reuse leaves no `target/smoke-ran`, so the smoke entry is saved only by a job that compiled, and the worker's `target/debug` is then seeded from the restored, unwarmed smoke build.

- Integration-closure gate (T265, D-1760, D-2101, SEC-022): `scripts/stage_exit.py` has a fifth condition read from `docs/integration-closure.md`'s table. A `security`, `money` or `privacy` row that is not `closed` is judged at stage N only when every owner it names has a numeric `stage` at or below N in `kit/tasks.json` (otherwise it prints a `note:` line, so a later owner's merge never closes an earlier stage the runner re-checks on each claim); a judged row fails when every owner is DONE or SKIPPED; a row with no owner or an unknown task id fails at every stage; a `closed` row of those areas needs a commit SHA or `#PR` and a test name (`test_…` or a `TD-` id) in Evidence; other areas only print; a missing register fails. `evaluate`/`passed_stages` take the register path as an optional last argument and judge it only when given; the command line always passes `<root>/docs/integration-closure.md`. The runner's gate (`runner/__main__.py` `build.gate`) does not pass it yet (D-2101). Tests: `tests/test_stage_exit.py` (TD-OPS-31).
- Advisory watch (T618, D-4269, SEC-021): `.github/workflows/advisory-watch.yml` runs on `schedule` (`23 */4 * * *`) and `workflow_dispatch` only; its read-only `scan` job runs `Ci`'s cargo-audit 0.22.2, cargo-deny 0.20.2 and `npm audit` (judged by `scripts/npm_audit.py`, so its exceptions apply) on main's locks, and `scripts/advisory_watch.py` turns what would fail a hand-in into `found.json`. It only reports: its `report` job writes `outbox/advisory-<ID>.md` on `claude/kit-state` (the outbox id is the dedupe record), stamps `dispatched: <date>` on new and stale unsent outbox files and dispatches `notify.yml` (a `GITHUB_TOKEN` push starts no workflow); a found advisory never fails it. Only `report` joins `kit-state-writer`, and only when there is something new or pending, because a newly queued run in a concurrency group cancels the pending one (a nightly `record` or a `notify`). It stays outside the nightly: never a required check, never writes `kit/nightly.json`, so an advisory never blocks claims through it.
- Flake run (T879, D-5996, D-6004): `.github/workflows/flake-run.yml` runs on `workflow_dispatch` only, read-only (`contents: read`, no push, no state, no secret, caches restored and never saved). Its `Inputs` job checks each input by pattern (crate, test binary, filter, spec under `tests/`, repeat 1 to 30, default 10) before any build; then `Rust flake run` (Checks' setup and cache key) runs `cargo test -p <crate> --locked --test <bin> -- <filter>` N times, or `Playwright flake run` (E2e's setup) runs `npx playwright test <spec> --repeat-each N --retries 0`; neither stops at the first failure, and the job summary gets runs passed and failed and the failing run numbers. A Rust run passes only on exit 0 with at least one test passed; a Playwright run k passes only if every test's k-th result is `expected` (skipped fails it), and the step fails on Playwright's non-zero exit or any report-level `errors` (`tests/test_flake_run_workflow.py`).
