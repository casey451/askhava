# Architecture section 2 notes: `jobs`

Moved here verbatim from `docs/architecture.md` (D-6022), whose index lists every part. Until T885 makes `docs/architecture/` a shared path, a task adds new notes to the index, at the end of the section this part came from, and the next plan change moves them here.

The section 2 notes ("Processes and code layout") whose first named crate is `jobs`, in their original order.

- Owner flag day-3 input (T523, D-3881, D-4037, D-4053, D-4032; OPS-031): `jobs::api::record_check_in_answer` writes one `jobs.check_in_answer` audit row (field `<day3|day14>_<answer>`) with each applied `answer_check_in` move, and `intake::check_in_replies` calls it in the delivery's transaction when an email-contact day-3 NO newly queues its `day3_no` step; `jobs::api::connected_answers` takes job IDs and a month and returns the jobs that moved into Connected in it and those whose connection drew a `day3_no` or `day3_other` row before the job's next move into Connected (IDs only).
- Masked lines close on job end (T662, D-4338, D-4398; CALL-009, CALL-010, JOB-005, JOB-015): `jobs` and `intake` may not call `calls`, so an applied cancel (`intake`'s text and page cancel and the INT-038 cancel) and an applied check-in PROBLEM or NO (`jobs::followups::answer_check_in`) queue one core task `calls.close_line` (`jobs::api::queue_line_close`, `jobs::line_close`) in the move's transaction, payload `{job, number, reason}` (`cancelled`, `complaint`, `no_show`), keyed per move by the job's version after it; `server` registers `calls::api::run_close_line` for it, which calls `close_line` (a cancel tells the business, no strike; a job with no open line closes nothing). The daily `calls.close_expired` sweep (`calls::close_tasks`, seeded by `worker`'s `schedule_start`, each run queuing the next a day later first) closes lines 30 days old. `picks`' `picks.line_retry` opens no line for a job in a final status (`jobs::api::current`).
- Final status ends waiting picks (T744, D-4748, D-5664, D-5883 to D-5885; FEE-021, PICK-038, QH-007, PICK-048): the `jobs.final_status` payload gains `at`, the move's own time as RFC 3339 text (`jobs::final_event`); `picks::api::run_final_status` now, in one transaction, calls `messaging::api::expire_job_rows(job, at)` (skipped for a payload with no readable `at`), then `picks::final_status_end::end_for_final`, which sends every `awaiting_confirm`, not-ended pick of the final job through `connect::end_pending` with the new `PendingEnd::JobFinal` (end reason `job_final`, migration 0214 replaces `pick_end_reason_check`), so its PaymentIntent ends through `payments::api::end_pick_intent` and a later success is refunded once; then `no_longer_active`. New cross-module call: `picks` to `messaging::api::expire_job_rows`.
