# Architecture section 2 notes: `site`

Moved here verbatim from `docs/architecture.md` (D-6022), whose index lists every part. Until T885 makes `docs/architecture/` a shared path, a task adds new notes to the index, at the end of the section this part came from, and the next plan change moves them here.

The section 2 notes ("Processes and code layout") whose first named crate is `site`, in their original order.

- Web chat after the code (T649, D-4294, D-5658 to D-5660; INT-027, PRIV-005, PRIV-008, AI-003, AI-020): with the chat's code keys, `site::chat` holds the typed words as a `SecretString` and hands them to `site::api::ChatKeys::read` and `ChatKeys::turn`, which `server::chat_codes::ChatParts` implements: `read` scrubs after the code with `privacy::api::read_inbound_for` for the session's contact (`intake::api::chat_contact`; D-2088's vault-error rules, a fallback turn running only `intake::api::chat_opt_out`), and an answer to her open name-and-address question that `reads_as_address` is only `[removed]` (`inbound_text::answer_words`); `turn` calls `intake::api::chat_raw_message` with the raw words, the vault and the LIST's public names, which sends the turn to `receive_raw_reply` while `name_address_open` holds. Without keys the chat keeps the no-contact `chat_codes::scrubbed` and `chat_message`.
- Styled 404 fallback (T615, D-4252, D-5166; WEB-027, WEB-007, SEC-012): `site::not_found` is `server::build_router`'s one `.fallback(not_found)`, merged after every route and inside every layer, so an unknown path's `GET`/`HEAD` gets `templates/not_found.html` with status 404, `Cache-Control: no-store` and the SEC-012 headers; any other method a bare 404 with no read. Its WEB-007 banner read goes through its own in-process cache (`BANNER_WINDOW`, 60 seconds): at most one database read a minute. The site's head now carries the SVG icon, the 180 px touch icon, `theme-color`, the meta description and the `og:` tags, and `assets` serves `brand/touch-icon.png` and `brand/share.png`.
