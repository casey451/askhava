# Architecture section 12: keeping this file true (the rules)

Moved here verbatim from `docs/architecture.md` (D-6022), whose index lists every part. Until T885 makes `docs/architecture/` a shared path, a task adds new notes to the index, at the end of the section this part came from, and the next plan change moves them here.

## 12. Keeping this file true

- A new module, table, cross-module call, status, timeout, adapter or pinned version changes this file in the same PR, with a `docs/decisions.md` entry when it is a choice (`BUILD_BRIEF.md:489`).
- **Build order and file ownership** live in `kit/tasks.json` (K6): each build task names the module and the files it owns (`app/<module>/src/…`, its own `migrations/0NNN_<slug>.sql`, its own test files), and `python3 scripts/validate_tasks.py` fails if two tasks that can run in either order own the same file, or if a non-`harness` task owns a protected path (D-111, D-118). The shared files are this file, `docs/decisions.md`, `docs/for-casey-review.md`, `app/server/src/main.rs`, the workspace `Cargo.toml`, `Cargo.lock`, `.sqlx/`, `package.json`, `package-lock.json` and every crate's `Cargo.toml` (D-453): a crate can only list a path dependency once that crate exists, so the task that first needs `picks` to call `payments`, or the server or a test crate to use a new module, adds that line. A new outside crate still needs its decision entry and must be in the workspace table. The first task of each module creates its crate's `Cargo.toml` and `src/lib.rs`. Stage 2 builds layers 0 to 7 far enough for job cards, the quote page and the pick (including the license imports and business records that matching reads); later stages add to each module's own files in dependency order (D-112).
- A new library needs a decisions entry with purpose, license and a cargo-audit (or npm audit) result, and must pass cargo-deny (`BUILD_BRIEF.md:122`).
- The threat model (`docs/threat-model.md`) changes with any new trust boundary or asset.
- The not-a-contractor phrase list (WORD-022) lives in one place, `NOT_A_CONTRACTOR` in `scripts/trace_spec.py`; the spec check, the catalog check (`scripts/check_catalog.py`) and the app's wording scan (T104) all read it (D-360). It also holds the WORD-023 banned descriptions ("connect you with", "referral network/service", D-377). Each alternative that names the brand names both "Laftly" and the old "Ask Hava" (and both possessives), so a leftover is still caught, and the message is "implies the brand is a contractor (WORD-022)"; the spec check alone excuses a match followed by `.com`, `.net` or `.org`, so "through laftly.com/help" names a page, not the brand, while a banned word in the path still fails (D-3402).
- The legal document drafts live in `docs/legal/` (TERMS-028, D-389). `scripts/check_legal_docs.py` keeps them true to the spec: each key phrase it lists must appear word for word in its spec requirement and in its draft, and it reuses the banned-phrase list from `scripts/trace_spec.py`; `tests/test_check_legal_docs.py` runs it in `Ci`. When the site pages are built (T111, T112), the published terms and policy come from these drafts.
- Legal holds live in the catalog and its check: pest control, when on, is for Department of Agriculture licensees only and never advertised (LIC-012, D-402); sale, purchase and refinance inspections are fee-free job types (FEE-045, D-403); and no category is a warranty or protection plan (`scripts/check_catalog.py`, LIC-015, LIC-042, D-376).

- Build notes (D-3620): this file holds the design, not the history of who built it. What a task built goes as one line per fact at the end of its crate's `app/<crate>/NOTES.md` (`- [REQ-IDS or -] (task NNN) text`, union-merged, `docs/code-docs.md` section 2), never as a "What T### built" paragraph here; this file changes only for a design fact (the first bullet of this list). `python3 scripts/split_arch_notes.py --check` lists any such paragraph (`tests/test_split_arch_notes.py` runs it in `Ci` and the smoke test, report-only during the transition, though a second copy of a note already moved, from a resync that kept an old section, fails it and the move refuses it: a task claimed before D-3620 may still bring one in on its update merge, and the operator sweeps those with a plan pull request that runs the script; a later plan change makes the test run `--check --strict` once every task whose attempt started before D-3620 merged is DONE or SKIPPED). - Performance measurement (D-3292, T416 to T418): the targets of Casey's performance review (`docs/audit/performance-review-2026-11-12.md`) are non-blocking goals, not spec requirements. `core` counts sqlx's own statement and pool-acquire events in a metrics-only tracing layer (`app/core/src/db_metrics.rs`; no SQL text, bind value or URL is kept or logged; the pool's size and five-second acquire timeout are unchanged) and the test-control router serves the counters at `GET /__test/perf/db` (T416, D-3298: statements, acquire count, wait sum, maximum and log-scale buckets from 0.1 ms to 5 s, pool size, idle and maximum; a reader subtracts two snapshots; the JSON log's own filter drops every `sqlx::query` event and passes only sqlx's slow-acquire WARN, over 250 ms, which holds numbers only). `tests/integration/tests/perf_zip_scale.rs` (ignored in `Ci`) times the ZIP-to-town lookup over a synthetic 41,000-ZIP markets file; the YAML reader's default 250,000-node budget refuses a markets file of about 30,000 towns, a ceiling the track must lift before a national file (D-3299). `perf/` (Python, standard library) seeds fake Phoenix-metro-size data, measures per-route p50/p95/p99, queries per request, acquire wait, payload bytes and error rate at 1, 10 and 50 users, and keeps its baseline in `docs/audit/perf-baseline.json`; `Ci`'s E2e job runs a quick pass plus lab Core Web Vitals and only warns (`continue-on-error`; T418, D-3342): `tests/perf/web_vitals.spec.ts` (its own `tests/perf/playwright.config.ts`, the journeys' globalSetup) writes lab LCP, CLS and an INP stand-in at 390x844 with 4x CPU and a slow mobile network, and `perf/compare.py` writes the step summary against `docs/audit/perf-baseline-ci.json` and warns on a p95 more than 25% over its baseline or a missed goal, always exiting 0. Its aspirational column holds DESIGN_SPEC section 7's lab aims, LCP 1.5 s and CLS 0.05, marking a home or quote page figure above its aim "missed" without a warning (T612, D-5839). The war games read the same snapshot. A fix to a measured route lands only with before and after numbers, and none trades privacy, authorization, idempotency or payment correctness for speed or adds infrastructure without measurement.
