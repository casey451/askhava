## 2. Slicing rule and four examples

1. Always include shared blocks. Select the union of the task's module, every crate in owns/reads/cites (`app/<crate>/...` including crate directories), migration ownership from the actual leading comment, and explicitly referenced cross-crate functions or flows in the goal, acceptance, requirements, source citations and test scope. Shared editable paths are not blanket ownership of every crate: server composition changes select the affected registration plus relevant module blocks; explicitly owned server paths still select the server tag. `core` and `server` appearances in a bullet count conservatively for direct selections. Do not recursively traverse every allowed dependency: section 3's Calls column says what *may* be called, not what this task actually calls. Cross-module blocks are included in full if any selected tag matches. A direct dependency used in the task must be selected even if a block does not name the caller.
2. Inspect named requirements, tests, decision choices and cross-boundary evidence; add explicit block IDs for implicit flows. A cite to a section-2 line selects the complete containing block, even when tags do not match; a substantive instruction to read all of section 2 overrides slicing. A cite to a different section preserves the existing whole-section charge. For other sections, preserve at least the original module-line selection and explicitly cited sections; do not narrow them in this change. Keep sections 3–6 governance untouched. `architecture.md` ownership overrides everything: load and count the whole file exactly once.
3. Fail closed: null module without a reviewed scope, generic tree sweeps, unrecognized crate paths, unmatched semantic references, unfamiliar section structure, unreviewed new blocks or uncertain cross-cutting integration require full section 2 (or stop generation with a clear error for malformed source/manifest). Do not use a regex match or absence of a crate name as proof that a block is irrelevant. Any task needing an extra block must add it via the same accounted loader, not quietly read the entire file. No permission to edit files is gained through reading a block.
4. For estimates only, the supplied metadata is expanded by these conservative spec-domain hints (not a substitute for the actual requirements/cites): 
`intake.md` → intake, `messaging.md` → messaging, `consent.md` → intake messaging privacy, `fees.md` → payments picks, `privacy.md` → privacy, `quotes-pick.md` → quotes picks, `businesses.md` → businesses, `ops-recovery.md` → ops recovery, `quiet-hours.md` → messaging, `ai.md` → ai, `job-cards.md` → quotes catalog, `lifecycle.md` → jobs, `website.md` → site, `licensing.md` → licensing, `calls.md` → calls, `recurring.md` → jobs intake. ### Optimization priority after the safety pass

The broad multi-tag rule is not a meaningful fix for the example tasks: T856 selects the entire section, and the other three save less than 2.5 KB each. The primary cause is high fan-in: generic references to `server`, `core`, `messaging`, and `privacy` occur throughout operational paragraphs. A second, independent review should distinguish **described crate** (the block defines its behavior or public contract) from **incidental reference** (for example, a handler name mentioned solely because the composition root registers it). Keep all blocks describing the owned/read/cited crate, but require the incidental edges only when the task touches that exact interface or flow. Split a long bullet further only at independently reviewable sentence boundaries with explicit atomic groups for invariants, conditions and exceptions; do not truncate sentences. For a server composition task that changes `build_router` broadly, retain all route-related contracts; a narrowly scoped `action_links.rs` task can use reviewed action-link contracts rather than every unrelated handler registration. This more selective scheme is the promising optimization, but its savings are not certified here; it needs a separate tagged-manifest review with the full task records and source code. Do not ship the broad baseline just to claim a context-budget win.
