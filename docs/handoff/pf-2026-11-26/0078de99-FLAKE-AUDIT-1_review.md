## Remediation and acceptance

1. Fix DB metric synchronization and isolate clock-mutating E2E specs first. Test J1 immediately followed by keyed sign-in at representative Arizona daytime, quiet hours, and just before UTC/AZ midnight. Exercise the same tests after an artificial forward clock advance; no global retries.
2. Fix quote notification terminal-state waiting and legacy positive log capture. Add a deliberately delayed worker fixture and a test that reaches the tracing callsite before capture, plus a concurrent case. Ensure both expected warning and no sensitive values are tested.
3. Verify the ID-format and cache-clock assumptions in findings 5–8 before changing assertions. Add deterministic test inputs that contain the forbidden digit sequence inside a legitimate ID, and a negative control that injects the actual forbidden value into a field where it is not allowed. Both conditions must be tested: legitimate data passes and actual leak fails.
4. Replace random small-domain fixture identities with per-case allocations after obtaining complete call sites. Verify isolated and whole-suite execution; retain any genuine returning-user test as explicit seeded state.
5. Separate real product failures from fixture flakes in the runner ledger. Record actual failed assertion, clock, randomized fixture IDs (fake only), and test order; never log live secrets. A repeated green run alone does not establish that a flake is fixed. Do not change the CI retry policy.
