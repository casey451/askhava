## R2a — Evidence-based CI supersession

**Disposition: GO after the bounded-ambiguity and merged-proof guards below are accepted.** Harness, Opus worker and reviewer, after phase 1. No dependency on R2b. No change to required-check definitions, review proof, smoke reuse or attempt limits.

**Goal (paste-ready):** Distinguish a cancellation of an obsolete CI run from a failure of the task's current required checks, using fresh read-only GitHub evidence. In `pr_for` retain the existing check projection and add transient metadata for the observed PR number, repository, branch, head, required check IDs, app, suite, status, conclusions and ordering, and page completeness. A fresh same-PR read and complete check-run read must positively establish that the old head is no longer current or that the same trusted logical required check on the same SHA has a newer run. A hard `failure` among current required checks is not excused by a cancelled sibling. A current timeout or cancellation with no replacement remains chargeable. A timeout can be treated as superseded only with positive replacement evidence, not because it timed out. Optional checks never establish the exception. Read failures and ambiguous identities are unknown, not success or replacement. Do not use numeric ID alone as proof of chronological order; require consistent run identity and ordering; if suite identity changes require evidence that both runs belong to the same logical check/workflow rather than allowing arbitrary same-name matching.

For an open PR, inspect stale cancellation evidence before charging or acting on stale review/auto-merge information, re-read the current head before making any write, and re-enter ordinary reviewed-head handling on the fresh snapshot. A proven obsolete observation holds MERGE_PENDING; the successor's actual verdict is judged normally. The current `_open_pr_step` checks review before CI (cycle.py:1161–1166); a guard placed only below that check can still close or charge the wrong head. Preserve `_unreviewed_step` on the *current* head, including closing auto-merge before requeue. For a merged PR, defer cancellation-only check judgment only if a successor is pending or a fresh read is needed, and only if no independent review/tree/proof defect is already known. No stale cancellation can suppress an unreviewed merge or tree mismatch (`cycle.py:998–1008,1322–1346`). Never turn a replacement into DONE directly. If a fresh ordinary check projection still contains historical cancellation alongside a success, do not loop forever and do not filter it to manufacture green; route to explicit unresolved-evidence escalation.

For an empty cleanup hand-in anchored to H0, examine the exact attested commit's checks or its uniquely associated merged PR head, not arbitrary current main. Same-head replacement pending: hold for ordinary H0 proof. H0 obsolete because a fresh descendant H1 positively superseded the cancelled work: close existing history with `result=ci_superseded`, do not charge or strike, clear obsolete empty/review/merge-turn markers, and return QUEUED for a fresh cleanup on H1. Never certify H1 using H0's work. The existing ordinary unknown-empty four-hour timeout stays unchanged. Existing `main_checks_green` selects the first merged PR (`github_env.py:1772–1775`); the evidence helper must independently verify unique association, correct tree/ancestry, repo and completeness. No ancestry-only shortcut. Preserve the stage-proof gate (`cycle.py:1341–1346`).

Bound the diagnostic wait: use a separate optional task-level `ci_supersession_wait` object carrying `head` and `since` (UTC timestamp); start it on the first unresolved supersession observation, not every read, and clear it on resolved verdict, fresh claim and terminal resolution. Recommended four hours, matching the existing empty-check operational ceiling (`cycle.py:1382`), then escalate unresolved diagnostic evidence as an operational BLOCKED condition without incrementing attempts, with an actionable reason. For open PRs, use existing auto-merge close/hold safety before releasing a blocked lane; never release a branch with uncontrolled auto-merge. For a merged PR with independent proof failure use ordinary main-red protection immediately; for unresolved merged evidence escalate explicitly, not DONE and not a fabricated test failure. Exclude genuinely running successors from the ambiguity deadline if the ordinary pipeline already governs their progress; nevertheless report aged running checks in status/operations and do not reset the ambiguity clock on repeated identical evidence. For empty checks that were already unknown without cancellation, keep the existing charged timeout. This is a proposed operational decision, not a verified policy from the package; approve before implementation. Test both `resolve_merged` and normal cycle (`cycle.py:1028–1070`), and both initial and deferred empty hand-in (`2859–2864,1349–1360`).

**Acceptance:** Focused failing-before/passing-after payload-driven regressions prove no charge on positively superseded CI, ordinary charge on current required failure/cancellation/timeout, no success or free retry on ambiguous/error reads, no merge/review/tree bypass, no stale empty certification, bounded diagnostic hold with an actionable outcome, and no lane-strike or lease/accounting regression.
