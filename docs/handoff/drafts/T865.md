## 3. Page variants (the open part: design, not a diff)

Acceptance: "a web request's reply from each is returned for the page". T857's page function is expected to look like `page_reply(db, (conversation, session), (template, body)) -> Result<PageReply, IntakeError>` and queue nothing. **Bind to T857's real API.** Constraints:

- Keep every existing public function and result type (`ZipStep` :75, `Reply` :80, `Option<Queued>` from `apply` and `tell_coverage`, `Closing` + `Option<Queued>` from `answer_close`, `AskedAgain` :39). Never fake an outbox ID. Never send a text and then delete it.
- One shape that fits the 400-line budget: in each owned file, move the "render the reply" step into a small private function that returns `(template, body, subject)`. The old wrapper then calls `queue_body`, and a new `pub async fn …_for_page(…, session)` runs **the same state transition in the same transaction** and returns T857's `PageReply` through the page function. Do not run a transition twice.
  - **ZIP:** `ask` :243-266 renders with `zip_body` :268 and writes the `ZIP_ASKS` marker. The page variant writes the marker and returns the body. Out of area goes through routing's page variant.
  - **Routing:** `apply` :302-343, `tell_coverage` :378-397 and `not_covered` :402-443 keep their close, demand and audit effects. Only the sink differs. The body comes from `reply_body` (:602).
  - **Closing:** `say` :206-252. The page variant returns the body; `close_from_page` (:275) is the quote-page close button, not this.
  - **Help (`replies.rs` `auto_answer` :492-529):** the page variant keeps the audit once, and no raw words.
  - **Address re-ask:** `ask_again` is a worker step with no browser session. Leave it on the guarded text path, and say so in `docs/decisions.md`.
- Expose each `…_for_page` in `app/intake/src/api.rs` (shared path, one `pub use` per item) and test it directly. Do not wire `web_chat.rs` or `order_dispatch.rs`. If review insists on wiring, that is `PLAN GAP: app/intake/src/web_chat.rs:450-460 T856/T801 …`.
- Keep each function under 50 lines, give it a `///` with its requirement IDs (CON-005, TXT-034, D-5848), and leave nothing unused: every new item is either called by its wrapper or exported.

use askhava_intake::api::{OUT_OF_AREA_TEMPLATE, ZIP_AGAIN_TEMPLATE, ZipStep, answer_zip};

/// D-5848, CON-007: the chat exemption keeps the INT-022 out-of-area text of a `web_chat`-only
/// request in the outbox through the guarded routing sink, and the request closes.

    let mut db = pool.acquire().await.expect("db");

    let msg = TextIn { inbox_id: Uuid::from_u128(0x86501), ..text_in(contact, "86401") };
    let before = all_rows(&mut db).await;
    let step = answer_zip(&mut db, &secret(), (&msg, request), Settings::default()).await.expect("area");
    let ZipStep::OutOfArea(Some(queued)) = step else { panic!("out of area") };
    assert_eq!(queued.template, OUT_OF_AREA_TEMPLATE);
    assert_eq!(rows(&mut db, request, OUT_OF_AREA_TEMPLATE).await, 1);
    assert_eq!(all_rows(&mut db).await, before + 1);
