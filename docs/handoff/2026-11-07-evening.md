## Lessons this stretch
- **External audits come from lower-tier models; verify every finding against the repo before acting** (Casey: the overseer has final say). Today's bundle mis-read D-033 as a bug; its CI-path, done-check, timeout, confirm-amount and reconcile findings were real.
- **`docs/decisions.md` is append-only to `check_pr_change`:** when merging main into a plan branch, main's entries stay where they are; move only the branch's own entries.
- **A plan PR goes `dirty` every time a task merges first;** expect to merge main in more than once before it lands.
- **A plan PR with auto-merge on goes `dirty` when a task merges into `main` first.** Merge `main` into the plan branch (plain merge), reorder `docs/decisions.md`, regenerate, re-check, push; auto-merge stays on.
- **Never change a task that is IN_PROGRESS or MERGE_PENDING.** A plan change does not reach an attempt already running; move the duty to a new or queued task (as done for T230 in `plan-audit2`).
- **Plan-fix requeue** (`python3 -m runner --requeue T### --plan-fix D-#### --reason "..."`, D-677) is refused unless the fixing decision is listed in that task's `decisions` in `kit/tasks.json` on `main`. Put it there in the same plan PR.
- **Protected paths** (and taking over a DONE task's test file) need a `harness` task with an Opus review (e.g. T250, T252, T282).
- **V9 migration order:** `validate_tasks.py` V9 checks that migrations run in serial order. Adding a dep from an older queued task onto a new task can force renumbering its migration (T103 0169 → 0172 in `plan-audit2`); leaving numbers unused is fine.
- **superseded_map wording:** `scripts/gen_prompts.py` SUPERSEDED_PATTERNS reads phrases like "supersedes D-###" as the whole decision superseded. When only part goes, write "sets aside only ..." and run `superseded_map` over new entries.
- **After the scheduled prompt's shallow clone, run `git fetch --unshallow origin`** before fetching state or merging `main` into a plan branch.
- **Fetch kit-state and lease WITHOUT `--depth`.** A `--depth 1` fetch re-shallowed the repo and caused false ahead/behind counts and "unverified commits" stop-hook noise. GitHub squash commits on `main` are verified; never rewrite `main`.
