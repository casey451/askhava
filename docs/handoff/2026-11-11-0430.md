## Lessons (new)
- **`docs/decisions.md` is append-only.** After merging main into a plan branch, main's new entries can land after the branch's own.
  - Fix: in a separate commit, move the branch's own D-entries back to the end of the file, after main's new ones. Each entry is one line starting `- **D-<n>**`.
  - For example (pass the branch's own ids):
    ```python
    import re, sys
    ids = set(sys.argv[1:])  # e.g. D-2832
    path = "docs/decisions.md"
    lines = open(path, encoding="utf-8").read().splitlines(keepends=True)
    own = lambda l: (m := re.match(r"- \*\*(D-\d+)\*\*", l)) and m.group(1) in ids
    keep = [l for l in lines if not own(l)]
    moved = [l for l in lines if own(l)]
    open(path, "w", encoding="utf-8").write("".join(keep + moved))
    ```
  - Check that the file ends with a newline before and after.
- **Open the PR right after numbering.** Runner reservations and other open PRs move the next free number within the hour.
- **A plan PR can lose the race to a lane claim (T337, #453).**
  - Check kit-state claims right before opening the PR and again right before merging it.
  - Never merge a plan change for a task that went IN_PROGRESS in the meantime.
- **Shared runner paragraph in `docs/architecture.md`.** When two harness PRs both edit it, a word-level merge resolves the conflict cleanly: tokenise on spaces and three-way merge the words.
- **Plan PRs that change queued tasks:**
  - Open them without auto-merge.
  - When CI is green, re-check kit-state that none of the edited tasks was claimed.
  - Then merge with `merge_pull_request` (squash, with `expectedHeadSha`).
- **Code review of merged code finds real defects.** Six reviewers found about 6 high findings in about 1.5M tokens, roughly one build task's cost. Plan each batch as fix tasks through two review rounds; the plan review caught real money and privacy holes every time.
- **Environment leaks into tests.** Any new env var the workflow exports can change runner tests inside the smoke. Add it to the `tests/conftest.py` fixture in the same PR.
