### Additional blockers and decisions

1. **A consent record is not a sender authorization by itself.** `contact_consented` currently scans all requests for a contact (`models.rs:348–359`). Keep per-contact genuine SMS evidence for eligibility; additionally detect first SMS for the current web-origin conversation, including a returning SMS-consented contact, before normal reply. Never send asynchronous notices merely because a prior request had SMS evidence if this request is web-only; define the request's delivery eligibility explicitly. Existing web sessions joining an existing SMS request at `web_chat.rs:756–760` must still render their own turn on screen. Keep suppression and mode at actual send time. Do not replay previously queued web-origin notices after enabling SMS. CON-005/021/025 (`docs/spec/consent.md:9,25,29`).
2. **First consent and safety exception need explicit reconciliation.** The brief says full consent first on every SMS path, but current service deliberately orders emergency 911 before consent (`service.rs:137–140,290–296`), and `intake_order_area_trade.rs:299–303` pins it. Business-intent reply is a deliberate no-request/no-consent path (`service.rs:251–266`); HELP/STOP/START have distinct handling. Do not change safety/mandatory keyword ordering in this task. Plan owner must confirm that “first” means first ordinary intake/campaign text with existing safety/keyword exceptions; if literal first even for safety, resolve conflicting spec and guard explicitly before implementation. Verify CON-031 ordering and exact template unchanged. No legal interpretation inferred beyond package.
3. **No use of an SMS outbox as chat transcript.** `Queued` is a real outbox ID (`service.rs:66–81`); `site/chat.rs:440–445` currently discards results and says TEXTED. A separate `ShownReply`/screen delivery result with template/body (and only approved links) must flow through all turn branches, including raw reply, age, HELP/LIST, choice, address, summary and photos. Shared intake state remains the only state machine. Don't introduce optional transport switches based on a client form. Never log or persist rendered contact-bearing body outside authorized retention paths.
4. **D-5716 is broader than two reads.** Actual snapshot `tests/e2e/j1_homeowner.spec.ts:81–99,178–180,236–238,246–267` uses body throughout J1, including quote token lookup. Prompt's line 172 is now a comment boundary. `web_chat.spec.ts:157–161` should assert zero campaign rows, not use carrier fallback. J1 genuine SMS must still validate bodies, and avoid a second race if body is cleared before fake carrier read: bounded polling for matching sent entry, recipient + unique send identity where available; do not match merely template or newest recipient. Check fake carrier's actual fields before choosing exact correlation. Maintain dedupe checks (J1:349–354).
5. **Timestamp semantics:** `intake.conversation.consent_sent_at` is NOT NULL (`migrations/0053_intake_tables.sql:41–43`); `models.rs:255–256` supplies it at opening and `web_chat.rs:775` audits `intake.consent_sent` even for web. Do not falsely label a shown disclosure as an SMS send. Decide whether to rename/generalize these metadata or add nullable distinct SMS queue timestamp with forward migration; actual authoritative users absent. Web record time and version must remain accurate and audit action should distinguish web disclosure from SMS.
6. **Existing sender check isn't a universal authorization guard.** Inspect all downstream producers before enabling mode. `app/messaging/src/service.rs:137–145` documents past-customer restriction, not a proof of consent at all producers. Separate enqueue defense (avoid cross-crate dependency cycle) from send-mode/suppression gates. Validate existing stale pre-fix queued messages before any live switch; package has no deployment inventory.
