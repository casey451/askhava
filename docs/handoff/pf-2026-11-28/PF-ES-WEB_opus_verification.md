## The "never share" question (BLOCKER)

- TXT-018 (`docs/spec/messaging.md:22`) has the ask text: *"What email should we use? We never share it with businesses."* The same requirement later says an update address is *"never given to a business unless the homeowner chooses email contact at the pick (PICK-018)"*.
- PICK-018 (`docs/spec/quotes-pick.md:22`): *"a call through the masked number or an email address they choose to share"*.
- How the code releases an email: the pick form starts with an empty email field (`app/portals/src/pick_flow.rs:1189`). An address she types there is sealed into `privacy.contact.email` by `store_shared_email` (`pick_flow.rs:39-40`, `app/privacy/src/vault.rs:449-458`, audit action `SHARED_AT_PICK`). The release opens that field only when she chose email (`app/picks/src/release.rs:7-8`, `app/picks/src/contact_choice.rs:7-8`).
- The update address is kept in a different table, `privacy.update_email`. Its code comment says it is "never her contact's conversation email" (`app/portals/src/update_channel.rs:10-11`).
- The web-chat conversation address is kept in a third table, `privacy.conversation_email` (T862 goal, `kit/tasks.json:56134`).
- So no business is ever sent the address she types at the update ask. A business gets only an address she types herself at the pick. "We never share it" is true for the code as planned. The only problem is that the TXT-018 clause reads as if this same address could be released.
- The review's replacement also breaks WORD-024's 15-word limit (`docs/spec/wording.md:28`). "We only share it with the business you pick if you choose email contact with them." is 16 words.
