## 2. Blocking findings and minimum design

1. **Web/worker split**: `app/server/src/main.rs:63-75` constructs control then discards its clock; worker uses it (`app/server/src/bin/worker.rs:49-67`). `app/server/src/lib.rs:627,792,917` pick/quote/inbound and `:546,553` action/feedback use SystemClock. `app/server/src/checkin.rs:19` hides another SystemClock behind `checkin::routes`, merged at `lib.rs:554`. Make control.clock() the domain root even without webhook keys.
2. **Signature regression risk**: `app/server/src/inbound_text.rs:311-312` feeds the shared clock directly into `verify_webhook`; `:349-351` is actual event/dispatch time. Split them BEFORE injecting simulated clock. Stripe's `app/payments/src/routes.rs:182` is another shared timestamp, but the excerpt does not show whether it verifies signatures; inspect full body and all webhook helpers first. J2 sends signatures using real `Date.now()` (`tests/e2e/j2.ts:187`). Do not generate fake future signatures to compensate.
3. **Stripe/Confirm missed by round 1**: `main.rs:68-69` calls `release_sink::stripe_webhook`, whose local clock is SystemClock (`app/server/src/release_sink.rs:492`). `lib.rs:478-483` passes the resulting hooks to Confirm; `app/portals/src/confirm_pay.rs:1151,1465,1546` reads that clock. `release_sink.rs:121,139` supplies release time. Worker also constructs independent Stripe hooks (`lib.rs:1376-1379,1903-1913`), so worker's held release can still use wall time. The complete release sink and payment route are missing: cannot certify signature/settlement separation or exact call signature. Keep the CLI replay/drill callers real-time (`lib.rs:1832,1864-1879`).
4. **Independent business routes and session mismatch**: `lib.rs:485-524` merges business portal, job page, sign-in/up, cant-take, step-up and homeowner state whose constructors are independently SystemClock (ledger). `action_links.rs:691,1246,1340` consumes business principals at link time. Moving only action links/Confirm would potentially expire a session issued at wall time when the late journey advances by days. Conversely moving session creation but leaving real sweeps/readers produces inconsistent ages. Trace real contract before choosing a common session clock; if owner sessions must be real, keep owner reads/issuance/sweep in that domain. `tests/e2e/owner_session.ts:129-135` deliberately uses real TOTP.
5. **Rate-limit regression risk**: `app/portals/src/pick_flow.rs:853,863` per-IP admission shares flow.clock with domain expiry at :947 and `send_window` at :818; separate before injection. `lib.rs:2898` already feeds the worker's shifted clock into rate-limit pruning; change prune to the same real clock as bucket writes, not merely the web reader. Inspect domain per-contact pick-code TTL/cooldown versus external Verify and security daily caps. `app/picks/src/email_code.rs:86-120` already accepts `at`; never weaken cap checks or change consent. WebSecurity at `app/portals/src/security.rs:266` and refusal log at `lib.rs:631` must remain real-clock security logging; this corrects round 1's recommendation to inject into RefusalLog.
6. **Business time still leaks below composition**: `app/picks/src/settle.rs:114-115,164` creates transition and accepted-quote task times with Timestamp::now. `app/intake/src/accepted_quote.rs:97` queues mail with real time; registry `lib.rs:2772-2792` registers the wall-time handler directly. `app/quotes/src/intake.rs:692` has an existing `confirm_quote_at` but the actual caller is omitted. `app/messaging/src/models.rs:249,289` records claim/send timestamps from DB; if downstream pick deadline uses sent_at (four business hours from actual send, architecture.md:358), the worker can see it as days old. Trace the reader and distinguish real delivery timestamp from simulated business event time. Do not fake provider timestamps.
7. **SQL exceptions are intentional**: `app/messaging/src/consent_purge.rs:7,45,101,120,139` explicitly enforces 1827-day database time, `app/intake/src/conversation.rs:531,539` uses the later of caller time and DB time to prevent a purge race; `app/ops/src/safe_mode.rs:15,67` intentionally uses DB time to avoid fail-open. Do not remove these safeguards or advance PostgreSQL globally. Flag SQL business-time columns individually; preserve real retention and audit floors. If a journey is blocked by a protected floor, report that gap, not a bypass.
8. **Test fixtures**: `tests/e2e/keyed.ts:85,108-110,123-128,143-152,225`, `tests/e2e/j2.ts:33-36,136` seed wall timestamps/current_date. Clock-aware domain seed options are necessary after clock advance; use Arizona day rather than DB session date for list fixture. Existing ROC helper only inserts if no ROC list exists, so verify freshness of existing fixture rather than silently skipping. Keep real Stripe signature and TOTP code; never seed lifecycle transitions to claim a real journey. `tests/e2e/webserver.ts:111-129` already provides shared clock file.
9. **Offset clock boundary**: `app/core/src/test_control.rs:350-404` keeps known offset on read error, and saturating_add uses unwrap_or(real). Do not add a constructor-error fallback or silently alter this behavior in composition. The existing saturation fallback is a separate robustness issue: test extremes and reject unrepresentable advances rather than reverting to wall time. No evidence from bundle that normal J1/J2 offsets reach it.
