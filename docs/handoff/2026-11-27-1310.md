## Lessons

- **Plan-PR merge-ins chase main.** Each of the three #1480 merge-ins and the two #1500 merge-ins cost a full CI cycle, because tasks went MERGE_PENDING back to back. Main's base CI takes about 30 minutes; a plan-only branch takes about 7. Merge main in only once nothing is MERGE_PENDING, then merge as soon as CI is green.
- **Re-check MERGE_PENDING immediately before the merge call, not 3 to 5 minutes earlier.** T734 entered MERGE_PENDING during the wait for Governance.
- **Governance can be missing on a merge-in head.** On #1500's last two heads, the `governance` workflow_run never posted, and GitHub allowed the merge. Governance had passed on the branch's own head.
- **`expectedHeadSha` must be the full 40-character SHA.** Take it from `git ls-remote`; a guessed expansion gets a 409.
- **A QUEUED task has no CLI channel for a note.** `--requeue` works only on BLOCKED tasks. For T657, Fable's precise fix (an `x-real-ip` header so `portal_form_errors.spec.ts` spends no owner try from 127.0.0.1) could not be attached. The worker's own note pointed the same way, and attempt 3's E2e passed.
- **Check over-limit attempts (180 turns or 30M tokens) on every status pass.** status.py should print the last attempt's usage, so an over-limit retry is caught before the runner re-claims it.
