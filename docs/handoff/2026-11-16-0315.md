## Lessons (read before acting)
1. **Parallel Fable checkers over a shared brief file are cheap and fast.** Nine Fable agents read 57 tasks in about 15 minutes, each with a one-line prompt pointing at `/tmp/claude-0/fable_brief.md`. Recreate that brief from this file's checklist if needed.
2. **Have each checker write its report to a file**, so builders read it there and the overseer doesn't re-type findings.
3. **Parallel builders need disjoint task lists and ID ranges.** Then one builder merges the branches into a single PR (one CI cycle). Only T126's deps overlapped.
4. **Recurring plan-gap patterns** (for new tasks):
   - `app/server/CLAUDE.md` is at its 8,192-byte cap, so notes go to `NOTES.md`.
   - A crate may query only its own schema, so name every reader.
   - `api.rs` takes no new definitions.
   - A non-harness task may not change an earlier task's test.
   - A new homeowner template in `en.json` needs `app/quotes/src/update_texts.rs`.
   - Door matrices fill only `{pick}`, `{complaint}`, `{kind}`, `{object}`, `{token}`.
   - CSRF comes before auth; owner routes use fixed paths.
   - New `ASKHAVA_*` keys join `KEYS`.
   - New worker kinds are registered and seeded; `schedule_start` is near the 50-line limit.
   - Struct literals in unowned tests block new fields.
   - `PLAN GAP` in a goal stops the task.
5. **The review caught real defects the checkers and builders missed:**
   - safe mode failing open (T487);
   - an owner button that could create a release past the safety gates (T540);
   - a vault field shared with the released view (T534);
   - money moving outside `payments` (T110);
   - a business-texting switch with no eligibility gate (T526/T527);
   - phone numbers leaving `messaging` (T481).
   Keep two Opus rounds for money, privacy, consent and security.
6. **A plan fix to a claimable task races the keeper** (T516 was claimed mid-fix). Check status right before pushing a fix that touches a claimable task.
