## Lessons
1. A `models` change is a plan change to every in-flight retry (D-4933). Treat it like amending a claimed task.
2. Harness tasks do not hold a QUEUED retry from being claimed; only a dependency does (a plan merge). A plan PR that must hold a task has to merge before the next keeper wake (T663 attempt 3 was claimed while D-4864 waited; its hold was dropped from the PR).
3. `gen_prompts.py` rewrites every prompt and every drifted `context_pct` on main (main's stored values drift); keep only the touched tasks' prompts and values.
4. Pre-claim scouts kept finding real gaps (4 blockers in 26 tasks), mostly DONE tests the task cannot own and context ceilings; Fable's adjudications changed the scout's fix in about a third of the cases.
5. Auto-merge on a plan PR is safe only when the branch is final; disable it before pushing an unreviewed commit to that branch.
6. Six plan merges between 2:10 and 3:05 am MST kept T669 at the head of the merge train for over an hour (each merge re-ran its update CI). Batch harder: hold plan fixes for tasks not yet claimable and merge them together right after a squash.
