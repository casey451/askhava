## How runner changes are made (worked well on October 30)
1. A builder agent in a worktree writes the change on a new `claude/runner-*` branch with a decision entry (number = max(live `next_decision` + 20, main's highest + 1)), a Plan-Change trailer, and the full suite plus every check.
2. An independent Opus reviewer that did not write the change reviews it (verdict first). Blocking findings go back to the builder.
3. Open the PR through REST and turn on auto-merge with `gh api -X PUT repos/casey451/askhava/pulls/N/ccr/auto_merge -f merge_method=squash`.
4. Before opening it, merge main in and keep main's decisions entries first with the new one last (`check_pr_change` reads the committed HEAD).
