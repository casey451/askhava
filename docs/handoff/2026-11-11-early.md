## Lessons (new)
- **Code review of merged code finds real defects.** Six reviewers found ~6 high findings in about 1.5M tokens.
  - Each review costs roughly the same as one build task.
  - Plan each batch as fix tasks through two review rounds. The plan review caught real money/privacy holes in the first drafts every time.
- **Plan PRs that change queued tasks:** open without auto-merge. When CI is green, re-check kit-state that none of the edited tasks was claimed, then merge (`merge_pull_request` squash with `expectedHeadSha`). Merges through the GitHub MCP tool work.
- **Several open plan PRs all append to `docs/decisions.md`.** Each merge makes the others dirty: merge main, run `scratchpad/reorder.py <D-id>`, commit, push.
- **Environment leaks into tests:** any new env var the workflow exports can change runner tests inside the smoke. Add it to the conftest fixture in the same PR.
- **Runner reservations jump:** claims reserve above main's highest decision and above open PRs, so `next_decision` can jump by 50+ in an hour. Pick plan numbers right before opening the PR.
