## Lessons
1. **Plan and hand-off commits restart the merge line.** Every main move makes the turn holder re-run CI (~19 min). Batch them into one commit per quiet window (right after a task merge, before the next update push, or when nothing is MERGE_PENDING), and bring the branch up to date first so `green_twin_tree` proves it. Two decisions can share one PR (`check_pr_change` accepts several new decisions); prove the union task by task.
2. **`gen_prompts.py` without `--check` rewrites stored budgets in `kit/tasks.json` and about 150 other prompts.** Save `tasks.json`, run it, restore your copy, `git checkout --` every prompt you did not mean to change, and keep each changed task's stored `context_pct` within 3 of the measurement.
3. **A merged task can hide a real bug that only its dependent's e2e finds** (T489 → T594). T489's tests called routes without the CSRF guard and the door matrix accepts any <500 for a Public POST. A fail-closed bug still costs a dependent's attempt.
4. **Text scans in tests are substring matches.** When a plan moves a reader across a scan's boundary, warn every downstream task that will name the thing (D-4202 round 2 found T158).
5. **Short-digit negative checks on bodies that hold random hex tokens are flaky** (~1.5% for a 3-digit pattern over 64 hex chars).
6. **Fable as decider** worked when given the evidence files and the option list: it also found the cold-cache fault no Opus investigator had.
